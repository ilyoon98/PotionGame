# 특별 발견·배합·최대 효과 통합 개발 결과

2026년 10월 13일 · **코드 연결·격리 모델/UI 검사·파일 미리보기 완료 / 실제 Windows 화면과 조작 미검증**

확정 범위인 특별4종의 원정 발견 → 한 번 구매 → 자동 제조·판매, 미발견 마스킹, 실제1병 배합, 최대 강화의 현재 효과를 구현했다. 공유 기획 명세와 기획서의 상태는 기획 담당이 관리하며 이 문서는 개발 근거만 기록한다. 수치와 제조 그룹 교대는 개발용 초기값이며 최종 경제 승인과 구분한다.

## 통계·닫기 아이콘과 구매 버튼

통계에는16px 그래프, 닫기에는16px X SVG를 붙였다.80×34px 버튼을 유지하고 아이콘과 글자 사이6px, 좌우 최소12px 여백으로 함께 가운데 정렬한다. [통계·헤더 검사](../../.verification/statistics-icons-integrated-20261013.log)의475개 검사가 통과했다. 통계 열기/숨기기·같은 창 재열기와9개 누적 값·스크롤·저장 모델이 보존된다.

파일 검수에서 레시피 구매 버튼의 코인이 왼쪽 끝에 떨어지고 숫자만 가운데인 기존 문제도 확인했다. 관리의 단일 줄 구매 버튼에는 부모 Container의 실제 할당 폭을 기준으로 같은 정렬 helper를 적용했다. 코인·가격·구매 문구가6px 간격의 한 묶음으로 가운데에 놓인다. 줄바꿈하는 원정 조건 버튼은 기존 배치를 유지한다. 파일 exporter도 StyleBox의 기본 여백을 포함한 실제 `get_margin`으로 보정했다. ## 구현 상태

- 특별4종은 일반32종과 별도 등록했고 승인된 포션/병/레시피 PNG12개를 연결했다. 원본·승인 지도·팔레트는 수정하지 않았다. [핵심 모델·초기 수치 상세](특별-발견-런타임-검증결과.md).
- 미발견은 모든 원정·레시피·포션·추천·숨긴 상세·툴팁에서 공통 지도와 미발견 문구로 표시한다. 실제 이름·전용 아트·배합은 발견 완료 후부터 보인다. 별도 구매 전에는 제작할 수 없다. 같은 관리 창을 초기 모델로 돌려도 이전 공개 정보가 남지 않는다.
- 해당4개 원정 행만188px 이상의 여유를 주고 나머지는148px를 유지했다. 발견 이름은 레시피 탭의 해당 행으로 연결되며 별도 수령이나 팝업은 추가하지 않았다.
- 출발 때 특별 결과와 회차 종류를 확정해 저장하고 완료 때만 공개한다. 기존 진행 중 회차에는 추첨을 소급하지 않는다. 조사 완료 후 재료가 충분하면 비용·시간이 같은 특별 탐색만 진행하고 재료를 추가 지급하지 않는다. 미입고 재료·예비금30·미완료 일반 조사 비용을 보호하며 발견 후 특별 탐색은 멈춘다.
- 포션과 레시피의36개 실제 배합에32px 재료 아이콘과16px `× 필요 수량`을 표시했다. 체력·마나도 각각의 레시피 행을 갖는다. 이름/보유/부족은 툴팁·접힌 상세로 확인하고, 현재 예약된 배치와 다음 병 부족을 구분한다. 좁은 영역에서는 아이콘을 축소하지 않고 줄바꿈한다.
- 일반 하위 품목의 대체 상태는 `상위 물약 우선 · 부족 시 자동 대체`, 기본·기존 품목의 전역 대체 상태는 `신규 일반품 부족 시 자동 대체`로 안내한다. UI는 순수 생산 후보 조회만 사용한다. 품목별 강제 최소 비축 정책은 추가하지 않았다.
- 포션 보유는 품목 개수로 표시하고 공용 한도는 포션 탭 상단에 둔다. 약초 한도는 각 품종에 적용한다.
- 최대16개 설비·계열·훈련은 이전 단계의 효과 키를 포함한 현재 최종 값을 표시한다. 단계별 값을 합산하지 않는다. 솥의 실제 기본 제조 시간/품질과 실제 거래 간격이 남는다. 길 정비16%, 길잡이14%는 `원정 시간 N% 단축`으로 읽히며 합산 적용은30% 상한이다. 지역 상세의 기본·다음 출발·이미 출발한 시간은 구분한다.

양쪽에서 네 일반 계열 최상위도 실제 제조·판매됐고 재료가 부족하면 여러 하위 품목으로 대체됐다. 특별4종은 모두 실제 병으로 제조돼 판매됐으며 일반 제조를 완전히 밀어내지 않았다. 여러 최상위가 별씨를 공유하므로 소모가 공급을 따라잡아 끝 재고는0이고 대부분의 관찰 시간에 완제품 재고도0개였다. 영원·현자·세계수·그림자의 물약은 미보유 사례에서 각각16·24·18·12병, 특별 보유 사례에서12·23·21·10병 제조/판매됐다.

`생성·입고`는 끝 재료 − 시작 재료 + 시작 배치에서 예약한 소모로 계산한 실제 입고량이며 재배와 원정 입고를 합친다. 미입고량은 JSON의 각 재료 `pending`에 별도 남긴다. 현재 배치의 한 번 예약·완료/실패/진행 중 카운터와 물약 재고 보존을 별도로 검증했다.

이 관찰은 시작 때42개 등의 재료 버퍼와 최대 설비, 특정 난수의 짧은 두 사례다. 장기 정상 공급·발견 수집 시간·초반 진행·최종 경제가 충분하다는 결론은 내리지 않는다. 별씨 공급이나 재고 기반 우선권 조정은 다음 밸런스 검토 후보로만 남긴다. 모든32종을 강제 비축하는 정책을 이번 기능으로 추가하지 않았다.
