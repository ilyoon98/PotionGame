# 작업실 가로 확장 검수 결과

2026년 10월 10일 · **디자인 검수 통과 / 540×288 런타임 연결·격리 검사 통과 / 실제 화면 조작 미실시**

작업실 가로 확장 디자인 v1 수정본을 파일·좌표·낮밤/대기 이미지로 검수했다. 본 작업실은 **540×288**, 그림 영역 248px와 하단 40px로 결정한다. 520·560은 비교 자료이며 런타임의 추가 화면 선택으로 구현하지 않는다. 디자인 승인 뒤 실제 게임 연결과 격리 검사를 별도로 확인했으며, 실제 화면 입력·GPU 조명 검사는 수행하지 않았다.

## 사용자 제보 이후 런타임 검수

개발의 변경 목록·최종 검사 로그·범위는 [작업실 확장과 단일 실행 적용 결과](작업실-확장과-단일실행-적용결과.md)에 기록했다. 이 후속 절은 해당 결과와 현재 코드·파일 렌더를 확인한 기획의 검수 기록이다.

사용자가 보낸 기존 408px 화면은 디자인의 실제 게임 연결이 누락된 상태였다. 개발 수정 뒤 `workshop_layout.gd`와 실제 노드·날씨 clip·병 슬롯·손님 동선·게이지·18×18 상세 버튼·입력 bridge·하단 좌표를 승인 manifest와 비교했다. 새 소품 네 PNG는 승인본과 SHA256이 같다. 기존 실내·최소·정보 모드는 기존 크기를 유지한다.

실제 게임 상태를 읽어 만든 [낮 배치](../.verification/wide-runtime/day-crafting-2x.png), [밤 비 배치](../.verification/wide-runtime/night-rain-2x.png), [일곱 상태 비교](../.verification/wide-runtime/states-board.png)를 기획에서 시각 검수했다. 파일 렌더이므로 실제 데스크톱 캡처나 GPU 조명의 검증 결과로 사용하지 않는다. 병 전달 중 화면 모드를 바꾸는 회귀도 보완했다.

수동 실행에는 중복 보호가 없던 문제를 게임 시작 단계의 공통 실행 권한으로 수정했다. [최종 동시 실행 검사](../../.verification/single-instance-native-final.log)는 최초 실행 여섯 개 중 소유자 하나·중복 다섯 개, 정상·비정상 종료 후 재획득을 통과했다. 중복 초기 종료, 보호 기능 손실, 일반 headless·autostart 실행, 구매·강화·설정의 저장/로그인/진행 차단도 격리 검사에서 통과했다. 실제 플레이어 저장·기존 게임 창·로그인 등록은 조작하지 않았다.

현재 열려 있는 구버전 창에는 파일 수정이 자동 반영되지 않는다. 사용자가 기존 창을 닫고 `play.cmd`로 다시 실행하면 새 본 작업실과 공통 중복 보호가 적용된다. 실제 클릭·드래그·창 전환·GPU 조명 검수는 Computer Use 금지 조건에 따라 미실시로 유지한다.

## 개발 적용과 확인

540 레이아웃의 manifest를 단일 기준으로 본 작업실 크기·소품·날씨 clip·조명 기준점·실제 병 진열·손님 이동·게이지·상세 버튼·입력 bridge·하단·전환 기준점을 함께 연결한다. 연결 대상은 [제작과 검수 명세](작업실-가로-확장-디자인과-검수-명세.md)의 개발 연결 목록을 따른다.

최소 256×160·정보 320×112·실내 440×704는 확장하지 않는다. 상태/프레임/입력 rect는 새 좌표와 같아야 한다. 실제 제조·공급·원정·보관 대기/자동 재개·개수와 FIFO 진열은 기존 모델을 읽는다. 화면 갱신·전환·재실행으로 재료 소비/결제/보상/RNG가 추가 실행되지 않아야 한다. 로그인 자동 재개·관리 확대·기존 하단 조작과 오른쪽 하단 기준점을 보존한다.

개발은 격리된 headless 검사와 파일 기반 렌더로 새 본 화면의 상태·비겹침·입퇴장·병 이동·모드 전환·저장 복원을 확인한다. 실제 동시 손님·병의 이동 곡선과 가림, Godot 조명·네이티브 입력 연결은 미리보기와 별도 검증 대상이다. 현재 Computer Use·화면 입력·포커스 변경·보이는 게임/에디터 실행 금지는 유지하고 실제 클릭/드래그 검사는 미실시로 기록한다. 실제 플레이어 저장은 테스트에 사용하지 않는다.
