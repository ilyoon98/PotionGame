## 고정 대표·실제 제작 대기·솥 색상 연결 완료 · 2026-10-08

**구현 완료 / 격리된 headless 검사 통과 / 실제 화면 조작 미실시.** 이 기록이 아래 약초 3개·원정 2개·표시 전용 `+N`과 보관 가득을 성숙 그림으로 표시하던 이력보다 우선한다. [최신 명세와 완료 근거](작업실-대표-게이지와-제작-대기-명세.md).

- 본 작업실 약초는 기본 `herb`, 원정은 첫 `forest_edge` 각각 하나로 고정한다. 실제 기본 약초 성장 프레임·주기와 해당 지역의 저장된 단일 회차 진행을 표시한다. `N종 재배 중`/`N곳 탐사 중`은 대표를 포함한 실제 활동 수이며 0개는 대기다. 구매 버섯·미해금 재배·보유만 있는 재료·원정 대기는 제외하고 복귀 중은 포함한다. 대표만 보관/자금 때문에 멈춰도 다른 작업의 활동 수는 남는다.
- 솥은 실제 시작한 물약 ID를 읽는다. 아이콘·제조 게이지·본/최소 모드 액체와 증기 색이 함께 바뀌며 마지막 ID를 대기와 저장 복원에서 유지한다. 32종 기존 병의 색에 대응하고 액체 151픽셀만 변경한다. 원본 그림·솥 외곽·불·알파·날씨 조명은 보존한다.
- 보관 가득과 재료 부족을 구분하며 실제 진행만 유지한다. 정지 표시를 위해 100%나 성숙 그림으로 채우지 않는다. 실제 판매 후 같은 제조 배치의 예약 재료와 경과를 이어가는 기존 모델을 사용한다. 최소/정보 모드에 채집 막대를 제조 막대처럼 대신 표시하던 경로도 제거했다.
- 돋보기 18px 세 개로 기존 포션/약초/원정 관리 탭을 연다. 그림 영역에서 이 세 실제 버튼만 입력 예외로 연결하고 나머지 그림 클릭 통과와 하단 이동·관리·모드·종료를 유지한다. 배치가 같으면 브리지를 재시작하지 않는다. 네이티브 보조 파일은 컴파일하고 내장본과 파일 일치를 검사했으며 실행하지 않았다.
- Pretendard·관리 48px 아이콘/520px 폭/98px 고정 행, 작업실 408×288·최소 256×160·정보 320×112와 현재 하단 간격을 유지한다. 경제·제작 선택·저장 형식·RNG는 변경하지 않았다. 책상·포스터·가로 확장 후보, 특별 레시피 실제 획득과 오프라인 보상은 여전히 대기다.

워크스페이스 로그 `fixed-representatives.log`, `potion-liquid.log`, `desktop-regions.log`, `fixed-proof.log`, `fixed-verify_*.log`와 `state-audit-test_*.log`에서 실제 상태·예약·재개·저장 복원·색·클릭 영역 논리·모드·관리 가독성/조건/성장/드래그·하단 간격·공급/진행/다중 원정 검사 통과를 확인했다. 실제 병 8칸의 제조/판매 이동 경로와 세 버튼의 좌표 겹침도 검사했다. [파일 기반 배치 이미지](../.verification/workshop-gauge-placement-proof.png)는 실제 ID의 솥 색과 기존 아트를 조합한 정적 검토 자료다. 실제 화면·셰이더·OS 클릭 검증은 미실시이며 Computer Use·입력·포커스 변경·플레이어 저장 접근은 하지 않았다.

## Pretendard·아이콘 확대 적용 완료 · 2026-10-08

**사용자 제공 Pretendard 1.3.9 적용 완료 / 관리 가독성 개선 완료 / 격리된 headless 검사 통과 / 실제 화면 조작 미실시.** 아래 84px 행 높이는 이전 이력이며 현재 약초·포션 행은 98px다.

- 제공 ZIP의 Regular·SemiBold OTF와 원본 SIL OFL 라이선스를 `assets/fonts/pretendard`에 포함했다. 게임 전체 본문·숫자·상태·작업실 획득 문구는 Regular, 제목·버튼은 SemiBold다. PC의 설치 폰트나 맑은 고딕/바탕체에 의존하지 않는다.
- 관리 여섯 탭의 목록 대표 아이콘을 **모두 48×48px**로 통일했다. 이전 운영·약초·포션은 24px, 구매 목록은 32px였다. 아이콘을 왼쪽 독립 영역으로 옮겨 본문·버튼·막대의 자리를 확보했다. 관리 표시용 AtlasTexture로 투명 여백만 제외하고 원본 아트와 작업실 소품은 수정하지 않았다. 최근접 필터와 종횡비를 유지한다.
- 설비 강화 단계에 따라 아이콘이 갱신될 때도 같은 표시용 여백 정리를 적용했다. 판매대·건조대가 갱신 직후 작은 원본 캔버스 표시로 돌아가던 누락을 수정했다. Regular/SemiBold 파일은 사용자 ZIP의 원본과 SHA256이 일치한다.
- 원정 예상 결과와 영업 결과 재료 아이콘은 24→**32px**, 텍스트는 11→**14px**다. 아이템별 최소/최대·보장/추첨·레시피 상태를 유지하며 좁으면 항목을 다음 줄로 배치한다.
- 관리 제목은 22px, 항목 제목·보유 골드·명성은 16px, 본문·조건·상세·탭·구매 버튼은 14px, 막대 보조 숫자는 12px다. 관리 창은 **520×800px**를 기준으로 하되 실제 사용 가능한 화면 높이에 따라 600~800px 범위로 맞추고 목록을 스크롤한다. 관리 창의 확대는 별도 작업실 배치 후보 채택과 무관하다. 본/최소/정보 작업실의 크기는 유지한다.
- 약초·포션 접힌 행은 **98px**로 고정되어 큰 아이콘·대표 조건·작업/재고 막대가 상태 변경 때 움직이지 않는다. 800px 관리 화면에서는 기존 운영 첫 화면의 세 구역·실제 막대 6개를 유지한다. 상세 펼치기·완료 정렬·추천의 직접 구매·조건·코인·저장·경제는 유지한다.

`verify_readable_management.gd`에서 폰트 리소스·한글/숫자/기호 글리프·폰트 역할·라이선스, 여섯 탭과 결과 페이지, 새 상태/해금 상태/환경 강조에서 전체 제목과 본문 높이, 48px 대표/32px 보상 아이콘, 짧은 창의 스크롤 경계를 검사했다. 조건·원정 예상 결과·막대·고정 행·추천 구매·결과 진입·작업실 게이지·하단 간격·코인·3단 모드·좁은 보상 목록 검사도 통과했다. 로그는 워크스페이스 `.verification/readability-*.log`다. 설비 아이콘 갱신 정정 후 가독성·추천 구매·게이지·경제/RNG 검사는 `.verification/font-final-readable.log`와 `.verification/font-final-growth.log`에서 재확인해 통과했다. 화면을 띄우거나 Computer Use·실제 입력·플레이어 저장 접근은 하지 않았다.

## 작업실 게이지·결과 진입·목록 압축 완료 · 2026-10-08

**구현 완료 / 격리된 headless 검사 통과 / 실제 화면 실행·조작 미실시.** 아래 102px 조건 행과 하단 결과 버튼 이력보다 이 상태가 우선한다. 본 작업실 가로 확장·책상 제거·원정 포스터는 별도 배치 후보이며 이번 구현에서 채택하지 않았다.

- 본 작업실에 현재 물약 제조 1개, 실제 해금 공급원 순서의 약초 3개, 열린 순서의 원정 2개를 표시했다. 품목별 실제 경과를 읽으며 수확·완료·대기 때문에 대표 순서를 돌리지 않는다. 재고로만 보유한 미해금 재배나 버섯 자동 구매를 화분으로 표시하지 않는다. 대기해도 슬롯은 유지된다. 408×288과 기존 하단 기준점·256×160 최소 작업실·320×112 정보 화면을 유지했다.
- 막대·그림은 입력을 받지 않아 클릭 통과 구조를 유지한다. 하단에는 추가 버튼의 여유가 없으므로 `+N`은 **표시 전용**이다. 전체 목록은 기존 관리 버튼의 약초/원정 탭에서 확인한다. 신규 배치 후보가 채택되기 전까지 현재 소품과 승인 아트를 유지한다.
- 관리 헤더에 책 아이콘과 `결과`를 추가했다. 기존 결과 페이지로 기간·순영업수입·주요 입고/수확 재료 3종·새 일반 레시피 해금을 표시하고 상세 장부는 접어 둔다. 원정 재료 누적과 기본 약초 수확·버섯 구매를 실제 기록으로 계산한다. 열기·상세 펼치기로 보상을 지급하거나 집계를 초기화하지 않는다. 제거된 하단 세 버튼은 복원하지 않는다.
- 약초·포션의 접힌 행은 모두 **84px**다. 102px에서 반복 두 줄 조건을 대표 실제 조건 한 줄로 압축하고 전체 부족 재료·여러 조건·배율은 상세에 남겼다. 이름·조건·작업/재고 두 막대 자리를 유지하며 상태가 바뀌어도 뒤 행 위치가 같다. 64px 목표는 현재 글자 크기와 두 막대·조건을 자르지 않는 범위에서 84px로 조정했다. 폰트를 줄이지 않았다.
- 작업실에서는 너무 작은 성장 그림 대신 품종 아이콘을 쓴다. 관리의 약초 상세에서 버섯 제외 10종을 `ItemArt.growth_path(id)`의 32×40 프레임과 실제 품종 진행으로 연결했다. 미해금은 정지, 보관 가득은 성숙 상태이며 UI가 수확을 지급하지 않는다.
- 추천은 실제 효과에 맞춰 새 물약 해금·판매 속도·재료 보관·원정 시간 등 짧은 목적을 표시한다. 종류+ID를 고정해 정식 구매 경로로 한 번 실행하는 동작은 유지한다. 제조 시간이 더 줄지 않는 솥 단계는 품질 개선으로 표시한다.

`verify_workshop_followup.gd`는 실제 결과 버튼/장부 신호, 기간·순수입·새 발견, 84px 행 고정/글자 경계, 10종 성장 경로·프레임, 공급원/지역 순서·미해금 재배 제외, 다른 실제 진행값·조회 전후 저장/RNG 동등성, 모드·기존 입력 브리지 구조를 검사했다. 캐릭터·창틀·가구·진열 병, 실제 완급 곡선·반올림을 쓰는 8개 제조 병 경로와 도착 중/진열 후 판매 전달 경로의 좌표 겹침을 검사했다. 이동 병이 최고점에서 닿지 않도록 약초 슬롯을 16px 정사각 아이콘과 막대의 21px 높이로 정리했다. 조건·게이지·추천 구매·코인·원정 용어·예상 결과·관리 드래그·3단 모드·하단 간격·판매 강화·다중 원정 핵심 검사도 통과했다. 과거 실패 로그가 아닌 최종 `followup-workshop.log`와 `followup-verify_*.log`, `followup-test_parallel_expeditions.log`가 이번 결과다.

[파일 기반 배치 검토 이미지](../.verification/workshop-gauge-placement-proof.png)는 실제 headless 데이터·좌표와 기존 아트를 조합한 밝은/어두운 바탕·낮밤/비의 정적 배치 자료다. **실제 화면 캡처나 실제 셰이더/사람의 조작 검증이 아니다.** 게임·에디터·Computer Use·입력·포커스 변경·플레이어 저장 접근은 하지 않았다.

실제 랜덤 보상으로 3시드×3구매 정책의 **9회×8시간 장기 측정 완료**. 모든 5분 장부와 종료 저장 복원이 일치했다. 높은 재고를 줄이는 판매 간격 0.8배 후보도 별도 9회×8시간 측정했으나 전체 해금 시간을 전반적으로 개선하지 못해 실제 게임에는 적용하지 않았다. 일부 기본 실행의 5시간 초과 성장 목표는 후속 균형 검토로 남는다. [측정·후보 전후 비교](랜덤-원정-8시간-경제-검토.md). **특별 레시피 실제 획득은 결정 대기, 오프라인 보상은 보류**다.

## 원정 예상 결과와 재료 보상 풀 연결 완료 · 2026-10-08

- 별·월계수 명성 아이콘을 공용 Atlas로 연결했다. 관리 헤더는 기존 골드 수치와 명성 수치를 분리하고 아이콘의 중심 기준선을 맞췄다. 명성 해금 조건이 있는 레시피·직원·원정·강화 카드에 공용 마커를 사용하고, 명성 부족 원정 버튼에도 같은 아이콘을 붙인다. 명성 레이블·정확한 값·조건 문구를 유지하며 미니 모드에 새 행은 추가하지 않았다.

## 구현

관리 창의 460×660 크기와 기존 픽셀 아트·색감·글자 크기를 유지했다. 메뉴는 가게 운영 / 약초 / 포션 / 레시피 / 원정 다섯 탭이다. 설비·직원은 고정 하단 버튼으로 여는 하위 페이지이며 결과·실내 화면 진입과 화면 설정도 유지한다. 이번 사용자 요청으로 포션과 레시피를 분리했다. 강화 독립 탭은 추가하지 않았다.

운영 화면 상단에 강화 추천을 고정하고 대상·이유·전후 효과·비용을 표시한다. `강화하기` 클릭은 기존 강화 구매 로직으로 비용을 지불하고 바로 강화한다. 페이지는 그대로 유지한다. 버튼을 누른 뒤 추천이 바뀌어도 처음 눌렀던 항목을 강화하며 실행 시 조건을 다시 검사한다. 자금 부족·최대 단계에서는 결제하지 않는다. 실제 조건·자금이 충족되는 투자만 추천하며 최대 단계는 제외한다. 현재 병목(재고 75% 이상, 재료 대기, 손님 대기)을 먼저 검토하고 기존 투자로 보완하는 간단한 초기 선정 로직을 사용했다. 수치 임계값은 기획 확정 경제값이 아니라 UI 구현 선택이다.

운영 본문은 현재 제조와 실제 손님 거래, 채집·자동 재료 구매, 해금 지역별 원정 순서로 진행을 모으고 물약 보유량과 제작 상태 목록은 별도 포션 탭에 둔다. 판매 행과 막대는 거래·대기·휴식 모두 표시하며 높이를 유지한다. 긴 흐름·자동 운영 설명 블록을 제거했다. 제조 타이머는 현재 한 배치만 표시한다. 포션 종류마다 동일 타이머를 복제하지 않는다. 채집·원정은 각각 실제 저장된 진행값을 참조하며 완료 후 다음 실제 회차를 보여준다.

약초 탭에 버섯을 포함한 재료 11종의 보유/한도와 공급 진행을 모았다. 성장·제조의 실제 환경 보너스가 있는 항목만 강조하며 효과가 없다는 반복 문구를 제거했다. 미해금 재료는 이름·해금 안내를 남기고 빈 작업·재고 게이지를 숨긴다. 막힌 공급은 보관 가득·골드 부족·입고 대기를 짧게 표시하며 움직이는 작업 막대를 숨긴다. 별잎은 신규 레시피의 실제 공급 해금까지 참조한다.

재고 막대는 수량/한도, 설비·계열·직원 훈련 막대는 실제 단계/최대 단계다. 임의 애니메이션이나 시간 증가를 넣지 않는다. 구매 전후 효과·비용·필수 조건은 기본 화면에서 읽을 수 있고 재료 구성·성공률 상세·보상 규칙은 상세 버튼으로 접어둔다. 갱신은 기존 행을 재사용하고 열린 상세·목록 순서·탭별 스크롤을 유지한다. 관리 창을 닫았다 열어도 같은 창 인스턴스와 페이지가 유지된다.

본·최소·정보 전환과 하단 공통 버튼, 자동 운영, 32물약·11재료·8지역·125투자·4직원, 가격·경제·원정 결제·저장 형식·정식 아트 원본을 바꾸지 않았다.

## 남은 제안

포션 종류별 병렬 제작은 추가하지 않았다. 독립 배치·슬롯·재료 배분·생산량·저장 이전과 판매 균형을 별도로 정해야 한다. 강화 독립 탭은 추가하지 않았다. 이번 다섯 탭과 기존 하위 페이지, 추천의 초기 우선순위·75% 임계값은 실제 사용 후 조정할 수 있다. 실제 조작 검증을 완료했다고 표시하지 않는다.

## 후속 정정 검사

`verify_management_gauges.gd`에서 재고 가득(배치 있음/없음), 제작 재개, 재료 부족, 준비 중 상태의 제조 행 높이와 다음 채집 행 위치가 같음을 확인했다. 제조 막대는 항상 보이며 실제 진행 중단값 또는 0을 표시한다. 가득 찬 동안 실제 배치 타이머는 보존된다. 추천은 원래 누른 강화만 1회 구매하고 현재 페이지를 유지한다. 자금 부족·최대 단계로 바뀐 대상은 결제 없이 거절한다. 전체 상태를 기존 강화 구매의 대조 상태와 비교해 재료 예약·판정·RNG·재고·원정 회차가 동일함을 확인했다.

이번 정정 후 `verify_management_gauges.gd`, `verify_sales_counter_ui.gd`, `verify_management_drag.gd` 통과. 로그: 워크스페이스 `.verification/gauges-direct.log`, `counter-direct.log`, `defer-direct.log`. 그 밖의 검사 표는 이전 관리 구성 구현 시 실행한 결과다. Computer Use·화면 실행·실제 입력은 하지 않았다.

## 포션 분리·판매 행 고정·구매 강조 검사

포션 32종은 해금된 품목만 표시하며 재고 0에서도 유지한다. 초기 혼합 재고 체력/마나/달빛 각 1개와 총 3/12, 실제 활성 배치의 제작률·가득 찼을 때 대기 표시를 확인했다. 대기 품목에 제조 타이머를 복제하지 않는다. 판매 중 → 손님 없음 → 완성품 없음 → 휴식 → 판매 중 전환에서 판매 행 높이와 다음 채집 행 위치가 동일하며 대기 진행률은 0이다. 다섯 탭 경계와 7페이지 행 경계를 headless 가상 레이아웃으로 검사했다. 구매 버튼의 실제 노란 스타일·짙은 글씨와 골드 앞 코인 텍스처를 확인했다.

이번 변경 후 `verify_management_gauges.gd`, `verify_sales_counter_ui.gd`, `verify_expedition_feedback.gd`, `verify_auto_operation.gd`, `verify_three_stage_modes.gd` 통과. 로그는 워크스페이스 `.verification/potion-tabs.log`, `potion-counter.log`, `potion-expeditions.log`, `potion-auto.log`, `potion-modes.log`. 이전 검사 결과 표는 각 구현 단계의 실행 이력이며 이번에 GPU 렌더·Computer Use·화면 실행은 하지 않았다.
