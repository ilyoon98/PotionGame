# 단골 기록 F22 개발 결과

> 2026-10-22 · 브랜치 `feature/f22-regulars` · **구현·격리 검사 완료, 실제 Windows 화면 미검증.** 사용자가 자리를 비운 동안 "다음에 필요한 것"으로 골라 진행했다. 기준은 [성장과 단골 꾸미기 기획안](성장과-단골-꾸미기-기획안.md)의 "단골은 자동 거래로 쌓이는 기록" 절이다. 모든 수치와 문장은 **초안**이며 사용자 확인 대상이다.

## 한 줄 요약

손님 4명(여행자·여마법사·엘프·고양이 도적)이 실제로 물약을 살 때마다 단골 기록이 쌓이고, 단계가 오르면 짧은 이야기와 기념품이 관리 · 통계 화면에 열린다. 경제(가격·수요·명성)는 전혀 바뀌지 않는다.

## 화면

- **관리 · 통계** 하단에 "단골 손님" 구역을 추가했다. 손님마다 카드 1장: 승인된 손님 대기 시트의 첫 프레임(32×48, 새 그림 없음) · `이름 · 단계` · 다음 단계까지 막대 · `기록 60 / 150 · 다음 믿고 찾는 손님` · 열린 이야기 문장. 기록이 없으면 "아직 거래 기록이 없어요."
- 카드는 방문 수와 이미 갖춘 선호 물약(최대 3개 + "외 N")도 보여준다. 아직 사지 않은 레시피 이름은 드러내지 않는다.
- 이번 집계 기간(“새 집계 시작” 이후)에 오른 단계는 카드에 **"새 이야기"**로 표시된다. 관리 헤더의 **통계** 버튼 오른쪽 위 금색 점은 그런 단계가 있고 이 관리 창에서 아직 통계를 열어 보지 않았을 때 뜬다.
- **읽음 상태는 저장 모델에 쓰지 않는다.** 처음에는 열람 시 `seen`을 저장했지만 기존 불변 조건("통계 화면을 열고 닫아도 모델이 바뀌지 않는다", `tests/test_statistics_persistence.gd`·`tools/verify_f20_ui.gd`)을 깨서 되돌렸다. 그래서 점은 게임을 다시 켜면 다시 뜰 수 있다(기간 중 새 단계가 남아 있으면). 기획안의 "읽음과 집계 기준 분리"와 다르므로 사용자 확인 대상이다.
- 작업실·축소 화면에는 아무것도 추가하지 않았다(기획안: 작업실에 긴 대화 자동 재생 금지, 상시 문구 추가 금지).
- 돌아왔을 때 결과(`report_text`)에 기간 중 오른 단계를 `단골 · 여행자 단골 · 기념품 낡은 나침반`처럼 한 줄씩 붙인다. "새 집계 시작"이 기준 단계를 현재 값으로 옮긴다.

## 저장

- 저장 버전 15 → **16**. 새 키 `regulars`: `{version: 1, points: {id: n}, report_stages: {id: 단계}}`.
- v16 저장은 `regulars`가 없거나 잘못되면(음수·소수·모르는 손님·기준 단계 > 실제 단계·버전 불일치) 저장 전체를 거부하고 기존 상태를 바꾸지 않는다.
- v15 이하 저장은 단골 기록 0에서 시작한다. 기존 손님별 방문 수(`by_customer`)는 판매로 추정하지 않는다(기획안 지시). 과거 소급 보상은 하지 않았다 — 필요하면 사용자 결정.
- 고정 기준 모델과 비교하는 F20/F21 검사 도구는 `regulars` 키도 제외하도록 고쳤다(`verify_f20_recovery`, `verify_f20_unpurchased`, `verify_f21_aging`, `verify_f21_keeper_upgrades`). 마지막 도구의 "v15로 저장" 단언은 "현재 버전으로 저장"으로 바꿨다.

- 실제 `advance()` 900초: 점수 합 = 판매 + 2×선호 판매, 방문은 판매와 별도
- 기록이 가득한 상태와 빈 상태를 1,200초 돌려 `regulars` 외 저장 전체가 동일 (경제 무관)
- 601초 한 번 = 1초 × 601번
- 결과 보고 줄과 새 집계 기준 이동
- 저장 왕복, 잘못된 값 9종 원자적 거부, v15 이관(방문 40회여도 0점)
- 관리 화면: 통계 점 표시/해제/재등장, 카드 4장 문구·막대·새 이야기·방문·선호 물약, 초상 32×48, 통계 화면 열기는 모델을 전혀 바꾸지 않음

## 전체 검사 · 2026-10-22

- `tests/test_*.gd` 13개, `tools/verify_f20_*` 9개, `tools/verify_f21_*` 11개, `tools/verify_f22_regulars.gd`: **전부 통과**. (처음 실행에서 `test_statistics_persistence`·`verify_f20_ui`가 통계 화면 열람 시 `seen` 기록 때문에 실패했고, 읽음 상태를 모델에서 빼서 해결했다.)
- 관리 UI 검사 11개를 이 브랜치와 기준 커밋(`main`)에서 각각 실행해 비교했다. 통과 4개(`verify_management_statistics`, `verify_currency_display`, `verify_stable_management_tabs` 등)는 양쪽 모두 통과다. 실패하는 `verify_lifetime_report`·`verify_management_separators`·`verify_contracts_ui`·`verify_f19_report_ui`·`verify_management_sage`·`verify_adopted180_management`는 **기준 커밋에서도 똑같은 항목으로 실패**한다. F21 이전 기준(통계 12칸, 설정 탭 이전 탭 번호 등)으로 쓰인 낡은 기대값이며 이번 변경의 회귀가 아니다. `verify_readable_management`는 양쪽 모두 시간 초과, `verify_supply_period_report`는 격리 데이터/고정 파일 부재로 양쪽 모두 실행되지 않는다.
- 낡은 기대값 갱신은 별도 정리 작업으로 남긴다.

## 병합 · 2026-10-23

사용자 요청으로 `feature/sfx-v1`(효과음 v1)과 `feature/f22-souvenir-art`(기념품 아트 후보, 미승인)를 이 브랜치에 병합했다. 충돌은 `verify_f20_recovery`·`verify_f20_unpurchased`의 저장 비교 제외 키 한 줄뿐이었고 `regulars`·`audio`를 둘 다 제외하도록 합쳤다. `verify_sfx_v1`의 "저장 버전 15 유지" 단언은 v16(F22)으로 고쳤다(오디오는 선택 키라 버전을 올리지 않는다). 병합본에서 테스트 13개, F20 9개, F21 11개, F22, 사운드, 관리 UI 3개(`verify_management_statistics`·`verify_currency_display`·`verify_stable_management_tabs`)가 모두 통과했다. 기념품 그림은 여전히 후보이며 런타임에 연결하지 않았다. 효과음의 실제 청취는 미검증이다.
