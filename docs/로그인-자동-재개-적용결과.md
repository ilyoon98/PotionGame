# 로그인 자동 재개 적용 결과

> 2026-10-12 후속 수정: 실제 설치 명령 길이와 한글 응답 결함을 수정하고 현재 사용자의 등록·별도 설정을 복구했다. 아래 실제 등록 미실시는 초기 개발 기록이다. [최신 수정·복구·검사 결과](자동-재개-등록-실패-수정결과.md).

2026년 10월 10일 · **구현 완료 / 격리된 headless·PowerShell dry-run 검사 통과 / 실제 시작프로그램 등록·재부팅 검증 미실시**

사용자 선택은 **컴퓨터를 끄기 전 게임이 켜져 있었을 때만 다시 실행**이다. 매 로그인마다 무조건 게임을 여는 방식은 사용하지 않는다.

## 사용하는 곳

관리 → 가구·직원 → 화면 설정에서 `켜 둔 게임을 다음 로그인 때 다시 열기`를 켠다. 처음에는 꺼져 있다. 설정을 켠 뒤에는 게임을 실행 중인 상태로 컴퓨터를 끄거나 로그아웃하면 다음 Windows 로그인 때 마지막으로 저장된 화면 모드로 다시 연다. 게임 닫기/창 닫기로 직접 종료하면 다음 로그인 때 열지 않는다. 관리 창 닫기는 게임 종료가 아니다. 설정을 끄면 앱의 자동 시작 항목만 제거한다.

강제 종료·충돌·전원 차단은 직접 종료 기록을 남기지 못하므로 다음 로그인 때 재개할 수 있다. 이 기능은 게임을 다시 여는 기능이며 종료 중 골드·수확·원정 보상은 지급하지 않는다. 마지막 위치를 새로 저장하는 기능은 추가하지 않고 기존 화면 모드 저장을 따른다.

## 연결한 구현

- `scripts/login_resume.gd`가 별도 `user://login_resume.json`에 사용 여부·실행 중 여부·실행 파일/프로젝트·PID와 기록 시각을 관리한다. 기존 물약상점 저장·경제·시간·RNG와 분리한다. 실행 중 기록은 시작/설정 변경 때만 쓰고 매 프레임 운영에서는 파일이나 Windows를 조회하지 않는다.
- `scripts/windows_startup.gd`가 현재 사용자의 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에서 앱의 `MoonshadePotionShop` 값만 등록/해제한다. 관리자 권한이나 다른 앱의 등록 변경은 사용하지 않는다. 앱 시작 때 상태를 한 번 조회해 캐시하고, 명시적인 설정 조작에서만 등록을 변경한다.
- 숨긴 로그인 도우미 `resume-login.ps1`은 사용 여부와 마지막 실행 여부를 먼저 읽는다. 꺼짐/직접 종료/잘못된 설정이면 게임 프로세스를 만들지 않아 창도 뜨지 않는다. 개발형은 Godot 창 버전과 현재 `--path`, 배포형은 게임 실행 파일을 연다. 게임은 사용자에게 보여야 하므로 정상 창으로 열고 도우미만 숨긴다. 실제 게임도 `--autostart` 시작 때 조건을 다시 확인한다.
- 실행 중 PID·실행 파일·기록 시각과 실제 Windows 명령행의 프로젝트를 확인해 중복 실행을 억제한다. 콘솔 개발 실행과 `--workshop`/`--autostart` 차이를 게임의 실제 프로젝트 기준으로 구분한다. 로그인 도우미의 mutex와 자체 `login_resume.pending.json`은 게임이 아직 초기화 중인 시간도 보호한다. 테스트의 dry-run은 이 임시 실행 기록을 쓰거나 실제 게임을 실행하지 않는다.
- 직접 종료는 실제 저장 성공 또는 저장 실패 후 사용자가 종료를 확정했을 때만 실행 중 표시를 해제한다. 저장 실패에서 계속하기를 선택하면 표시를 유지한다. 일반 노드 해제/시스템 세션 종료 경로에서는 실행 중 표시를 지우지 않는다. 종료 표시 저장에 실패하면 앱의 자동 시작 등록 제거를 시도하며 둘 다 실패하면 종료 전에 실제 가능성을 알려 준다.
- 등록 실패에서 설정 파일 복원이 실패하는 경우도 처리한다. 등록을 제거해 자동 시작을 멈추거나, 제거까지 실패하면 다시 실행될 가능성이 있음을 상태와 체크 표시로 알린다. 설정 갱신으로 구매·재료·진행·수익을 변경하지 않는다.
- 로그인 도우미는 GDScript 상수에도 동봉하므로 배포 시 별도 PowerShell 파일 내보내기 필터에 의존하지 않는다. 공백·한글·특수문자가 있는 경로는 인수 단위로 처리하고 레지스트리 작업의 데이터는 Base64 JSON으로 전달한다. 경로 이동/실행 파일 누락/등록 명령 260자 초과는 오류로 표시하고 끄기는 실행 경로가 사라져도 가능하다.

[Microsoft의 Run/RunOnce 문서](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)의 로그인 실행과 260자 명령 제한을 따른다. 시스템 세션 종료 메시지는 [WM_ENDSESSION 문서](https://learn.microsoft.com/en-us/windows/win32/shutdown/wm-endsession)를 확인했고, [Godot 4.6 Windows 구현](https://raw.githubusercontent.com/godotengine/godot/4.6-stable/platform/windows/display_server_windows.cpp)의 `WM_CLOSE` 전달 경로를 근거로 직접 닫기와 일반 해제를 분리했다. 이 소스 검토를 실제 PC 종료 검증으로 표시하지 않는다.

## 검사 상태

`verify_login_resume.gd`는 실제 사용자 데이터 대신 프로젝트 `.verification` 아래 파일과 가짜 등록 backend를 쓴다. 초기 꺼짐, 잘못된 타입/JSON/외부 소유 설정 거부, 격리 경계, 한 번만 조회, 등록/해제 실패, 직접 종료·재실행, 종료 표시 쓰기 실패의 등록 해제 대안, 실제 관리 토글/실패 복구/반복 갱신, 저장 실패 취소/확정과 main-window 닫기 신호, 일반 해제에서 재개 표시 보존, 경제와 RNG 불변을 검사한다.

`verify_windows_startup.gd`는 가짜 레지스트리와 PowerShell `-DryRun`으로 개발/배포 실행 대상, 창 버전, 경로/인수 처리, 이동한 경로, 260자 제한, 실제 headless 실행 금지, 꺼짐/닫힘/잘못된 설정의 실행 거부와 중복 PID/프로젝트/시각/초기화 중 실행 기록을 검사한다. 실제 레지스트리를 읽거나 등록하지 않고 실제 프로세스를 띄우지 않는다.

관리 글꼴·여섯 탭·스크롤과 3단 모드 자동 검사는 통과했다. Windows 등록/해제·PC 로그아웃/재부팅·시작 앱 허용 상태의 실제 조합은 사용자 확인 항목으로 남는다. Computer Use·마우스/키보드 입력·플레이어 저장 접근은 하지 않았다.

최종 통과 로그는 워크스페이스 `.verification/verify-login-resume.log`, `.verification/windows-startup-final.log`, `.verification/login-readable.log`, `.verification/login-modes.log`다. 로그인 실행기의 PowerShell dry-run **30개 조건 사례**를 모두 완료했고 실제 게임 실행/초기화 중 실행 기록 쓰기 없이 primary/pending fixture가 유지되는 것을 확인했다. 동봉한 PowerShell 상수와 원본 파일의 UTF-8 바이트도 일치한다. 초기 작성 단계의 구문/출력 파싱 실패 로그를 완료 근거로 쓰지 않는다.
