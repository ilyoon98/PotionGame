# 후반 투자와 흥정 훈련 개선 개발 결과

2026년 10월 19일 · 15만/30만/45만 생산 가격 반영·격리 검증 완료 · 최종 기획 검수 대기

현재 생산 코드의 후반 투자 비용은 두 갈래 각각 **150,000/300,000/450,000, 신규6단계 합계1,800,000**이다. 기존에600,000으로 산3단계의 소유·골드·실제 지출은 보존하며 자동 환급하지 않는다. 아래 최초210만 성장과 미적용 후보 비교는 당시 증빙으로 보존하고, 채택 후 생산 적용 검증은 마지막 절에 구분한다. 실제 플레이 게임은 재시작하지 않았다.

## 구현

흥정 훈련의 남은 적용 기회, 기존 성장 완료 이후의 보급 지원·납품 일괄 조제, 직접 구매·성장 추천, 저장 버전 11을 연결했다. 공유 제작 명세와 메인 기획의 완료 표시는 기획 담당이 관리한다.

- 훈련은 거래처별 현재 등급부터 3등급까지 미판정·미수락 기회만 센다. 첫 상태는 9회이며 현재 협의를 마쳤어도 미래 등급이 남으면 구매할 수 있다. 최종 4등급은 100%라 계산에서 제외한다. 기회 0이면 `적용할 흥정 없음`으로 직접 구매와 추천을 막고 실제 구매 단계·과거 판정을 보존한다. 비용 8,000/20,000/50,000과 60→70→80→90%는 유지한다.
- 후반 투자의 기존 완료 범위는 일반 32종, 8곳 일반 조사, 기존 직원 4명, 고정된 기존 16갈래 125단계다. 특별 4종과 흥정 훈련·신규 투자는 포함하지 않는다. 두 갈래는 각각 1/2/3단계에 거래처 중 한 곳의 2/3/4등급과 앞 단계를 요구한다. 수주 자체는 별의 정원 최초 개방을 유지한다.
- 두 투자의 최신 단계 비용은 각각 150,000/300,000/450,000이며 신규6단계 합계는1,800,000이다. 실제 구매 시 골드와 직접 투자 지출에 한 번 반영한다. 추천과 정식 행은 같은 액션 경로를 쓰며 누른 대상과 다음 단계를 고정한다. 오래된 단계·기회 소진·부족 골드를 다시 검사해 거부한다.
- 보급은 구매한 레시피가 실제 사용하는 특수 재료 9종 중 공급원이 열린 품목만 고른다. 기본 약초·자동 발주 버섯은 제외한다. 실제 보관 비율이 가장 낮은 한 종류, 동률은 기존 카탈로그 순서이며 난수를 쓰지 않는다. 주기 시작에 수량을 고정하고 도착 때 대상을 선택한다. 빈 공간만 채우고 가득 참·대상 없음의 미입고분은 적립하지 않는다. 기존 재배·원정 입고를 먼저 반영한 후 보급하고 새 제조를 예약한다. 입고량은 원정 횟수·보상·발견과 분리한다.
- 납품의 한 배치는 같은 품목 최대 2/3/4병이다. 기존 품목 우선순위를 유지하고 실제 재료·현재 회차 계열의 남은 요구량에 맞춰 줄인다. 전체 배합×실제 병수, 품목·회차·제조 시간·성공률·한 번의 판정을 시작 때 고정한다. 성공·실패 병수와 배분용 배치 횟수는 분리한다. 단가×성공 병수, 회차 완료 실적과 1회 정산에 반영하며 일반 FIFO·선반·판매·손님 전달 이벤트에는 섞지 않는다. 진행 중 강화는 현재 예약을 바꾸지 않는다.

일반 4배치 대 납품 1배치는 세 거래처 전체가 공유하는 실제 시작 횟수다. 기존 일반 보관이 가득 차 직접 납품할 수 있는 경우의 제조 허용 예외는 유지한다.

## 저장과 화면

저장 버전은 11이며 1~10을 명시적으로 지원한다. 기존 저장은 신규 투자 0·보급 미시작, 기존 진행 납품은 1병의 동결 배치로 이전한다. 협의 버전과 이력·가격·실적·훈련·원정/제조 난수는 보존한다. 신규 저장은 독립 투자 구조를 먼저 검사하고 임시 경제 객체에서 계약 배치·완료 조건·거래 등급을 검증한 뒤 실제 상태에 적용한다. 병수·전체 배합·동결 판정·제조 시간·보급 주기의 불일치는 부분 적용 없이 거부한다.

저장 실패는 계약 또는 신규 투자 모듈의 소유 필드·골드·직접 투자 지출만 복원한다. 전체 State 로드로 휴업 상태를 다시 열거나 현재 배치를 초기화하지 않는다. 같은 객체와 진행 중 시간·예약 수량을 유지한다.

기존 여섯 탭과 수주 페이지·520px 폭·Pretendard 16/18px·먹색/세이지·구분선을 유지했다. `가구·직원`에 후반 투자 2행, 가게 운영과 약초에는 구매 후 같은 보급 주기의 게이지를 연결했다. 훈련 상세는 남은 기회와 현재→다음 확률, 납품 상세는 최대 병수와 감소 조건을 표시한다. 추천 기본 점수는 훈련 70·보급 65·일괄 60이며 실제 구매 가능한 다음 단계만 제시한다. 새로운 픽셀 에셋·캐릭터·팝업·솥·트레이·창 크기는 추가하지 않았다.

주요 생산 변경은 `scripts/shop_late_investments.gd`, `shop_contracts.gd`, `shop_state.gd`, `shop.gd`, `management_status.gd`, `management_panel.gd`, `management_contracts.gd`다.

기존 설비 강화의 추천에도 표시한 다음 단계 검사를 추가했다. 다른 경로에서 먼저 강화한 뒤 예전 추천을 놓으면 다음 가격을 대신 결제하지 않고 변경 안내를 표시한다. 기존 정식 125단계 행과 일반 구매 모델은 유지한다.

## 최초 구현의 효과 비교와210만 성장 증빙

초기 값은 60초마다 최대 3/6/12개였다. 첫 시험에서는 공급 부족으로 실제 납품 병수가 상한보다 작았으며 표준 계약의 두 투자 1단계·3단계 조합이 목표에 미달했다. 같은 자동 보급·동일 품목 일괄 범위에서 수량을 늘린 후보를 비교했다. 초기 소스는 [동결 모듈](../.verification/f19-20261019/initial-late-investments.gd)과 [SHA256](../.verification/f19-20261019/initial-late-investments.sha256)으로 보존했다. 비용·대상 선택·일반 4배치 대 공유 납품 1배치·일괄 상한은 유지한다.

### 최초 구현 가격과 보급량 조정 근거

아래 비용 표는 최초210만 구현 시점이다. 이후 채택한3단계450,000의 생산 적용·성장 검증과 구분한다.

| 단계 | 각 갈래 비용 | 보급 지원 | 납품 일괄 조제 |
| --- | ---: | --- | --- |
| 0 | 미구매 | 없음 | 기존 1병 |
| 1 | 150,000 | 실행 중 60초마다 최대 7개 | 같은 품목 최대 2병 |
| 2 | 300,000 | 실행 중 60초마다 최대 12개 | 같은 품목 최대 3병 |
| 3 | 600,000 | 실행 중 60초마다 최대 24개 | 같은 품목 최대 4병 |

초기 3/6/12개 시험의 seed73129에서 표준 합의의 두 투자 1단계는 약 +7.51%, 3단계는 약 +20.90%였다. 이 초기 폴더의 미구매 2개 로그에는 보급 미구매 뷰의 형식 오류가 있어 깨끗한 통과 증빙으로 세지 않는다. 해당 오류를 고치고 별도 `initial-clean` 대조군을 남겼다. 다음 6/12/24개 후보의 깨끗한 18조건에서는 표준 1단계 평균 +9.897%로 10%에 못 미쳤다. [후보 분석](../.verification/late-investment-f19-20261019/analysis-double-supply.json), [후보 모듈](../.verification/f19-20261019/double-supply-late-investments.gd), [후보 해시](../.verification/f19-20261019/double-supply-late-investments.sha256)를 보존했다.

이에 1단계만 6→7개로 조정했고 2·3단계, 비용, 주기, 배분 규칙은 유지했다. 12조건의 소규모 확인 후 같은 최종 소스로 180조건 전체를 새로 측정했다. 현재 모듈 SHA256은 `670e91f0ec0c9a1cc0668b52d89b0d5dc07cbdb823640a7ea2ed93052ed2f7d7`이다. 이는 첫 개발의 비교 결과이며 향후 밸런스 변경을 금지하는 수치 확정은 아니다.

### 2시간 효과 비교

합의 2종 × 환경 3종 × 시드 3개(73129/19337/9973) × 조합 10종으로 **180조건**, 각각 게임 시간 7,200초를 진행했다. 조합은 미구매, 보급만 1~3, 일괄만 1~3, 둘 다 1~3이다. 환경은 재료 가득·일반 재고 없음(일반 재고 적음 포함), 상위 희소 재료 4종 없음, 일반 재고 가득을 포함한다. 표준 합의는 거래 등급 이력을 갖췄어도 기존 1등급 기본 합의를 유지하는 가게이며, 최종 합의는 4등급 대금 협의 가게다. 측정 중 재흥정하지 않는다.

- `shop_state.gd`의 `report_supply`가 기간 시작 시점의 실제 누적 보급량을 보관한다. `start_report_period()`는 이 비교 기준만 갱신하며, `report_text()`는 현재 실제 누적−기준의 양수 차이를 `별잎 보급 +7`처럼 재료별로 표시한다. 재료 카탈로그 순서로 고정해 정렬 JSON 저장·복원에서도 본문 순서가 같다.
- `management_status.gd`의 보존 기간 조회 `report_summary()`에도 별도 `supply_materials:[{id,count,source:"supply"}]`를 추가했다. 보급은 기존 원정/수확/구매 `materials`와 합치지 않고 모든 입고 재료를 반환한다. 기존 재료 상위3개·발견·기간·순영업수입의 의미는 유지했다.
- 보급·원정이 같은 별잎을 주는 경우도 별잎 보급7과 원정3으로 분리한다. 기간을 다시 시작하면 현재까지의 보급은 기준에만 남고 이후 실제 입고만 센다. 가득 참·대상 없음·아직 도착하지 않음은0이며 부분 입고는 실제 들어온 수량만 센다. 결과 조회·저장·창 재열기는 지급을 실행하지 않는다.

저장 버전은11을 유지하고 최상위 `report_supply`를 추가했다. 새 필드는 사전 검증 후 실제 상태에 한 번 적용하며, 재료별 값이 실제 누적 입고보다 크거나 잘못된 재료/형식/수량이면 전체 로드를 거부한다. 이미 발행된 v11 저장에 필드가 없으면 저장된 실제 보급 누적 전체를 기준으로 복사한다. 과거 기간의 보급 기준은 복원할 수 없으므로 추측하거나 전체 누적을 현재 기간으로 다시 표시하지 않는다. 이때 다른 매출·원정·계약·기간 시작 시각·골드·재료·예약·RNG는 유지하며, 복원 후 새로 실제 입고된 보급부터 센다. v1~10은 기존 이전과 빈 보급 기준을 유지한다.

현재 런타임은 `report_text()`, `start_report_period()`, `Status.report_summary()`를 호출하지 않고 12개 누적 통계를 사용한다. 이번 수정은 누락된 **보존 기간 API와 저장 집계**의 보완이다. 사용자가 보는 현재 통계창에 새 기간 결과 화면을 만들거나 초기화 버튼을 복구하지 않았다. 실제 기존 관리 화면과 미사용 기간 결과 원문을 구분해 검증했다.
