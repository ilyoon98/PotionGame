### 이전 구현 기록 · 2026-10-07

확정 12항목 중 **11항목 완료, F02 구현 완료·최종 조작 검증 일부 남음**. Windows 클릭 통과를 단일 구현으로 통합하고 일반 실행에 연결했다. 별도 프로세스의 뒤쪽 버튼 클릭, 관리 열기와 전체 복귀를 확인했다. 전체·작음·최소 전환, 빠른 재전환, 종료 시 보조 프로세스 정리 자동 검사를 통과했다. 투명 창 이동은 이벤트 좌표 기준으로 수정했으며 최종 수정 이후의 연속 드래그·관리·최소화 조합 및 125~200% 배율은 추가 확인이 필요하다. 사용자 요청으로 Computer Use를 중단했으며 남은 조작 검증을 완료로 간주하지 않는다. 임시 밸런스와 후속 외형은 별도다.

[항목별 검증 결과·임시 수치·남은 작업](구현-임시값.md)에 근거를 정리했다. 저장은 버전 5로 이전하고 기존 버전 1~4를 읽는다. 레시피·원정·명성·고용·환경·제조 판정·결과 집계가 저장된다. 선호 구매가 추가되어 선호품이 있으면 해당 품목 중 오래된 병, 없으면 전체 선입선출로 판매한다.

### 새 에셋 적용 완료 · 2026-10-07

새 마녀는 대기·제조 2장·판매 포즈를 사용하고, 손님은 새 외형 5종을 적용했다. 여행자·여마법사·엘프·고양이 도적은 걷기·구매 동작을 사용하며, 여기사만 준비된 대기 그림으로 이동한다. 캐릭터는 48×64 원본을 2배 정수 확대하고 제조 시 솥을 향한다. 기존 단순 실내 배경과 투명 창문 위에 새 해·달·구름·비를 연결했으며, 투명 작업실에는 사각 하늘 배경 없이 날씨 사물만 표시한다. 비는 제공된 4프레임을 8fps로 반복한다.

`tools/verify_asset_integration.gd`, `verify_environment.gd`, `verify_management.gd` 및 동작·포션 정렬·진행 테스트 통과. 낮밤×맑음/비, 투명 빈 공간, 효과 끄기, 비 애니메이션, 실제 구매·퇴장 중 재고 일치를 확인했다. 밝고 어두운 배경 비교는 게임 렌더를 검증용 배경에 합성한 자료이며 OS 클릭 통과 검증과는 별개다. 클릭 통과의 최신 상태는 위 F02 구현 기록을 따른다.

`assets/characters/customer_redesign_v4`의 여마법사·엘프·고양이 도적을 연결했다. 새 전신 대기·걷기 2장·구매 완료 자세를 한 세트로 사용해 정지와 이동 때 외형이 바뀌지 않도록 했다. 48×64 프레임을 2배 정수 확대로 표시하고 걷기는 6fps로 반복한다. 입장과 구매 후 퇴장에 모두 적용하며 퇴장 시 이동 방향에 맞춰 좌우 반전한다. 기존 여행자·상점 주인은 유지하고 여기사는 제외한다.

### 관리 창을 연 상태의 작업실 이동 개선 · 2026-10-07

### 원정 진행·귀환과 획득 표시 완료 · 2026-10-07

작업실 판매대 아래에 작은 원정 상태판을 추가했다. 해금 후 탐색·귀환·일시정지·입고 대기를 표시하고, 진행 게이지와 남은 시간을 함께 보여준다. 관리 창의 원정 탭에도 동일한 진행도 게이지를 표시한다. 귀환 시 상태판에 5초 동안 `귀환 완료!` 알림을 표시하며, 보관함이 가득 차면 알림이 사라진 뒤에도 `입고 대기`와 남은 별잎 수량을 유지한다.

골드·기본 약초·별잎 획득 숫자 옆에 해당 픽셀 아이콘을 표시한다. 별잎은 실제 입고 수량만 획득 표시하며, 귀환 알림 자체가 보상을 추가 지급하지 않는다. 원정의 기존 60초 탐색 + 10초 귀환, 자동 입고·재출발 규칙은 유지한다. 진행·정지·재개·보관 대기·중복 보상 방지와 렌더 검사 완료.

### 새 작업실 시안 적용 완료 · 2026-10-07

환경 표현 기본값 확정·적용 완료: **밤의 밝기 하한 60%, 날씨 효과 강도 100%**. 현재 플레이 저장에도 반영하며 관리 화면에서 조절할 수 있다.

제공된 `output/transparent-workshop-v1` 원본을 게임 에셋으로 연결했다. 달무늬 카펫 위에 솥과 마녀, 오른쪽에 독립 판매대, 판매대 왼편에 화분을 배치한다. 판매대 원본의 예시 포션은 그리지 않고 실제 재고를 표시한다. 작업실 진열은 위아래 4병씩 총 8병으로 변경 완료. 총 보유 한도 12병은 유지하며 초과분은 보관했다가 빈 칸으로 이동한다. 선입선출과 제조·판매 이동, 기존 저장 재고는 보존한다. 관리 창에는 진열과 보관 수량을 나누어 표시한다.

하단 바는 금색 모서리 장식과 `동전·골드 / 시간 아이콘 / 날씨 아이콘·낮밤 / 관리 / 고정 / 닫기` 한 줄이다. 중복 골드·별도 진행 HUD·작업실의 축소 아이콘은 제거했다. 전체·작음·최소 모드는 보존하며 전체 실내 화면은 관리 패널 또는 Esc로 돌아간다. 창 크기는 408×288, 그림은 y=0~247, 하단 조작 바는 y=248~287이다. 시간 UI 추가 및 왼쪽 위 해·달·구름 구현 완료. 추가 창틀 적용 완료: 왼쪽 칸은 해·달로 낮밤을, 오른쪽 칸은 구름·비로 날씨를 표시한다. 양쪽 칸을 각각 잘라 효과가 틀 밖으로 새지 않게 하고 창의 빈 부분은 투명하게 유지한다. 하단 시간 아이콘은 낮/밤, 날씨 아이콘은 맑음/흐림/비를 독립적으로 표시한다. 왼쪽 위 해·달 전환과 구름 이동은 동일한 환경 시간을 따르며 사물의 낮밤 색감과 픽셀 비·물튐도 유지한다.

해·달의 시간별 이동 구현 완료. 기존 게임 시간에 맞춰 왼쪽 창 안에서 왼쪽→위쪽→오른쪽으로 움직이며, 뜨고 지는 동안에도 창 내부에서만 보인다. 낮밤 밝기 하한 60%, 날씨 강도 100%는 유지한다.

빈 선반·8병 진열과 보관 재고 보충·모드 전환 후 재고 순서, 네 환경과 관리 메뉴, 제작·판매 및 기존 화면 검사를 통과했다. 해·달의 상승·정점·하강 렌더 검사에서 시간 칸 밖으로 새는 픽셀은 0개였다. 새 크기에서 네이티브 클릭 통과 시작·종료 자동 검사도 통과했다. 실제 마우스 조작 확인은 사용자가 진행하며 Computer Use는 사용하지 않았다.

### 확정 화면 구성

```text
  주인 / 솥 / 화분 / 판매대 / 손님     ← 사이 공간은 투명
  보유 골드 · 자동 운영 상태   [관리]

[관리]를 눌렀을 때
  달그늘 물약상점           골드   [닫기]
  [가게 운영] [약초] [레시피] [원정]

  가게 운영 : 상단 강화 추천 → 강화하기 (즉시 결제·강화)
              포션·채집·원정·실제 판매 게이지 / 얇은 재고 막대 / 대기 이유
  약초      : 전체 재료 목록 / 보유량·한도 / 현재 환경의 영향 항목 강조
  레시피    : 미구매 목록 → 1회 구매 → 구매 완료·자동 제작
  원정      : 최초 해금 후 즉시 자동 시작 / 탐색 진행 / 귀환 결과

  [지난 영업 결과]
```

기존 방에서 물약을 만드는 설정은 유지한다. 투명 작업실을 야외 노점으로 바꾸거나 차양을 필수로 추가하지 않는다. 운영 화면에서 자동 구매·제작·판매를 각각 별도 최상위 탭으로 쪼개지 않는다. 약초 분리는 확정이며, 강화 독립 탭과 `물약·레시피` 이름을 적용한 전체 다섯 탭은 배치 제안이다. 강화·직원·물약 보유 목록의 최종 위치는 관리 개선안의 역할에 맞춰 정한다.

투명 작업실은 벽과 바닥을 제거한 시각적 투명화를 뜻한다. 투명한 빈 영역의 OS 클릭 통과도 함께 검증하되, 기술 제약이 있으면 실제 지원 범위를 보고한다. 관리 버튼과 패널까지 클릭이 통과되어 조작할 수 없게 만들지 않는다. 패널의 정확한 크기·색상·좌우 위치, 날씨용 마법 창문·수정구슬은 최종 선택 전이며 필수 외형으로 고정하지 않는다.

[인터랙티브 화면 구성 참고](reference/potion-shop-management.html)와 [기본 화면 캡처](reference/potion-layout-desktop.png)는 구조 참고용이다. 시안 속 가격·레벨·골드·진행 시간은 제품 수치가 아니다. 기존 최소 모드나 전체 실내 화면을 삭제하는 것은 이 작업의 요구사항이 아니다.

기존 시안의 바깥 화면에 남아 있는 `달꽃 성장`, `이슬풀 성장` 문구와 매끈한 구름 표현은 최신 확정안이 아니다. 구현 시 아래의 목록 하이라이트와 픽셀 날씨 표현 기준을 따른다.

### 확정 약초와 물약 목록의 환경 하이라이트

투명 작업실의 평소 화면에는 `밤 · 비` 같은 낮밤·날씨 상태만 간단히 남기고, `달꽃 성장`, `이슬풀 성장`처럼 품목별 환경 효과를 나열하지 않는다. 약초 목록은 별도 `약초` 탭에서 확인하며 실제 환경 효과 하이라이트를 유지한다. 물약 목록은 보유·생산 상태 확인용이며 레시피의 1회 해금 구매와 역할을 구분한다. 물약 보유 목록의 최종 페이지 위치는 배치 제안으로 남기되 환경 하이라이트 기능은 보존한다.

현재 환경 때문에 성장 조건이나 제조 성공률이 달라지는 항목은 해당 목록의 행 또는 카드에서 하이라이트한다. 예를 들어 밤의 영향을 받는 약초는 약초 목록에서, 비로 제조 성공률이 달라지는 물약은 물약 목록에서 강조한다. 강조는 실제 환경 효과가 적용되는 데이터와 연결하며, 단순 선택 표시나 수동 생산 지시로 취급하지 않는다. 긍정·부정 효과가 모두 있다면 둘을 같은 보너스로 보이게 하지 않는다. 정확한 색상·테두리·아이콘 방식은 UI 구현 시 정한다.

완료 조건은 관리 패널을 처음 열 때 현재 환경의 영향 항목이 강조되고, 패널을 연 상태에서 낮밤·날씨가 바뀌면 해당 강조가 갱신되며, 조건이 끝난 항목의 강조가 해제되는 것이다. 목록 확인이나 하이라이트 여부와 관계없이 구매·제작·판매는 자동으로 계속된다.

### 확정 레시피 구매 규칙

상태는 `미구매 → 구매 완료`다. 구매 때만 골드를 한 번 차감하고 보유 목록에 저장한다. 구매 완료된 항목은 다시 결제하지 못한다. 잔액 부족 때는 구매할 수 없고 부족 금액을 표시한다. 레시피 구매·보유와 실제 재료 소비·제조는 서로 다른 일이다.

구매한 레시피는 재료가 있으면 자동 제작에 합류하고 재료가 없으면 기존 제조로 돌아간다. 기존 사용 가능한 체력·마나 물약을 새 구매 화면 도입 때문에 다시 잠그거나 재결제하지 않는다. 새 재료 공급원과의 연결은 필요하지만, 화분을 레시피와 함께 지급할지 별도 구매할지는 상세 설계 대상이다. 반복 제조·수동 조합·자동 생산 기능 자체에 구매비를 추가하지 않는다.

이전에 제안한 연구 슬롯, 연구 대기 시간, 연구 완료 후 추가 해금비는 이번 1회 구매 흐름의 요구사항이 아니다. `레시피 연구`라는 성장 방향은 이 단계에서 레시피 해금 구매로 표현한다.

### 확정 자동 운영과 성장의 경계

자동으로 진행할 것은 실행 직후 재료 조달·구매, 재료 소비, 포션 제작, 판매, 최초 해금 직후 원정과 결과 반영이다. 플레이어가 직접 선택할 것은 레시피·아이템 구매, 설비 강화, 고용과 원정 최초 해금이다. 별도 시작·활성화 버튼을 두지 않는다. 이후 자동 운영을 위해 생산 정책·제조 예약·선호 손님용 재고 예약 설정을 요구하지 않는다.

기존 영업 켜기·끄기, 버섯 자동 발주 전환, 원정 활성화·일시정지는 제거한다. 예비금·보관 한도와 진행 중 재료의 1회 차감은 보존하고, 부족 조건이 해소되면 자동 재개한다. 기존 저장의 꺼짐 상태는 자동 진행으로 전환하되 자산·제조·원정 진행을 초기화하지 않는다. 자동 운영이라는 이유로 해금·강화·고용 비용까지 사용자 모르게 지출하지 않는다. 신규 자동 반복 비용은 별도 합의 전에는 추가하지 않는다.

### 확정 환경과 손님 방향

낮밤·날씨는 게임 내부 환경을 사용하고 조달·제조·손님 출현의 공통 상태를 참조한다. 패널 전환·재실행으로 진행 중 제조를 다시 판정하거나 환경 시간을 초기화하지 않도록 저장한다. 현실 위치·현실 날씨 연동은 요구사항이 아니다.

**환경 이름만 표시하는 것으로 F07의 시각 구현을 완료하지 않는다. 투명 화면 자체에서 밤과 비가 식별돼야 한다.** 낮밤과 날씨는 독립되어 비 오는 낮과 비 오는 밤을 모두 표현한다.

**날씨 아트 방향은 픽셀 아트로 확정한다.** 구름·빗줄기·물튐 등 날씨 요소는 캐릭터와 소품에 어울리는 픽셀 표현으로 통일한다. 2026-10-07 제공된 `assets/weather/v1`의 해·달·별·맑은 구름·비구름과 4프레임 비를 게임에 연결했다. 물튐은 2픽셀 단위 절차적 표현이다. 목록 하이라이트와 같은 환경 시간을 사용하며, 아래 시각 기준으로 렌더를 확인했다. 새 에셋이 없는 물튐을 별도 제작 에셋으로 보고하지 않는다.

밤을 표현하려고 사용자 바탕화면이나 작업 창 전체를 어둡게 만들지 않는다. 비를 표현하려고 벽·전체 하늘 배경을 다시 채우지 않는다. 빛·빗줄기·물튐은 입력을 가로채지 않아야 하며, 조절 가능한 효과 강도와 밝기 하한을 둔다. 정상 전환은 부드럽게 하되 번쩍이는 번개는 필수로 추가하지 않는다.

완료 검증은 밝은 문서와 어두운 바탕화면 각각에서 낮·맑음, 밤·맑음, 낮·비, 밤·비를 확인한다. 이름표를 보지 않아도 낮밤과 비가 구분되고 사물 사이 투명도와 UI 가독성이 유지되어야 한다. 시안의 낮·밤·맑음·비 버튼은 비교용이며 실제 플레이에서 날씨를 바꾸는 기능을 뜻하지 않는다.

### 구현 순서와 인수 확인

1. F01~F04: 기존 경제·저장을 보존하면서 투명 작업실, 관리 버튼, 세 관리 메뉴를 먼저 연결한다.
2. F05·F10·F11: 1회 구매·보유 저장·자동 제작 연동, 기존 설비 관리, 실제 영업 결과를 연결한다.
3. F07~F09: 환경 효과와 손님별 출현·선호 거래를 데이터로 분리해 연결한다. 바깥 화면의 품목별 성장 문구를 제거하고, 관리 패널의 약초·물약 목록에 환경 하이라이트를 우선 연결한다. 제공된 캐릭터·픽셀 날씨 에셋을 실내와 투명 작업실에 연결한다(2026-10-07 완료).
4. F06·F12: 별도 자동 원정, 명성과 고용의 기본 구조를 연결한다. 메뉴 존재만으로 기능 완료를 보고하지 않는다.

각 단계에서 실제 Windows 독립 창을 확인한다. 투명 영역에 뒤 프로그램이 보이는지, 패널을 닫아도 경제가 진행되는지, 구매가 한 번만 차감되는지, 재실행 후 보유·진행·환경이 복원되는지 확인한다. 기존 저장 버전 1~3과 백업 복구를 보존하고, 테스트는 별도 상태로 실행해 플레이어 기록을 덮어쓰지 않는다. 도입한 환경·손님·원정의 결과는 실제 상태와 UI가 일치해야 한다.

최종 구현 보고는 F01~F12별로 `완료 / 부분 완료 / 미구현`을 구분하고 검증 결과, 임시 밸런스 값, 남은 에셋·수치 결정을 적는다. HTML 시안의 샘플 골드나 고정된 진행도를 실제 게임 UI에 그대로 넣은 것은 완료로 인정하지 않는다.

## 개발 이후 후속 기획

### 확정 장기 콘텐츠 방향

**2026-10-08 추가 확정: 제작이 판매보다 빨라 재고가 쌓이는 구간과 판매가 제작보다 빨라 손님이 기다리는 구간이 번갈아 나타나는 균형을 성장의 핵심 기준으로 삼는다.** 강화·새 레시피·환경 변화에 따라 병목이 바뀌어야 한다. [재고와 손님 대기 균형 기준](재고와-손님대기-균형.md)과 [제작과 판매 밸런스 조정안](제작과-판매-밸런스-조정안.md)에 투자·상태·후보 C의 수치를 정리했다. C는 판매대 간격과 후반 조제 훈련을 조정하는 게임 미적용 비교안이며 최종 수치 확정은 아니다. 설비 우선 경로의 장기 적체와 실제 게임 측정은 남아 있다.

상세 구현 후보는 [콘텐츠 연결표와 가격표](콘텐츠-연결표와-가격표.md)에 물약 32종·재료 11종·원정 8곳·강화와 훈련 125단계·직원 고용 4종의 ID와 비용·효과·선행 조건으로 정리했다. 디자인 목록의 영문 ID와 맞췄으며 실제 에셋 제작 상태는 디자인 목록을 따른다.

[성장 속도 계산 결과](성장-속도-검증.md)는 후보 C와 기존 B를 같은 0.05초 계산 간격으로 각각 3전략·3난수 총 9회 비교한 기록이다. 강화 한 항목의 효과를 분리한 실험도 포함한다. 최신 30·60·120분 상태와 전체 완료 시점은 해당 결과표를 따른다. 2시간에 성장 목표가 남는지와 긴 재고 적체를 함께 점검하며 3~5시간 주요 콘텐츠 목표를 모든 전략이 충족한 것은 아니다. **실제 Godot 구현·플레이 검증 결과가 아니며 데이터·가격·생산 정책은 아직 후보**다.

2026-10-08 사용자 요청으로 **물약·원정·레시피·강화를 크게 늘려 실행 2시간 이후에도 새 성장 목표가 남는 방향**을 확정한다. 구체안은 [장기 콘텐츠 확장안](장기-콘텐츠-확장-기획안.md)의 **물약·레시피 32종, 원정 8지역, 재료 11종, 설비·계열·직원 투자와 훈련 125회**다. 주요 콘텐츠 완성 3~5시간, 전체 강화·수집 5~8시간을 테스트 목표로 둔다.

이 숫자와 지역·가격·시간·효과는 **구체 제안이며 구현 완료나 세부 밸런스 확정이 아니다**. 원정의 중간 발견으로 한 지역에서 세 레시피를 순차 개방하고, 여러 계열의 재료·생산·선호 판매를 연결한다. 이전 3지역·신규 3물약안은 기본 구조의 참고로 유지하고 전체 콘텐츠 규모는 새 확장안을 우선 검토한다. 자동 시작·아이콘·1회 구매와 기존 보유 기록은 유지한다.

관리 화면의 정보량과 용어를 줄이고 페이지 역할을 나누는 [관리 페이지 개선안](관리-페이지-개선안.md)을 따른다. **약초 별도 탭, 가게 운영의 게이지 모음, 상단 강화 추천의 즉시 실행, 현재 흐름·자동 운영 설명 영역 제거를 확정했다.** 이전 네 탭·세 탭 비교는 이력이며, 강화 독립 탭과 추천 선정 수식은 배치 제안이다. 항목 아이콘과 즉시 자동 시작·전환 버튼 제거는 유지한다.

사용자가 다음으로 깊게 기획할 영역은 **원정·새 레시피 콘텐츠**다. [원정과 신규 레시피 콘텐츠 기획안](원정과-신규-레시피-콘텐츠-기획안.md)에 지역별 발견, 재배 품종, 레시피 구매, 자동 제작과 선호 손님, 복귀 결과를 연결한 제안을 정리했다.

첫 범위로 제안하는 흐름은 **숲 귀환 누적 → 이슬풀 표본 발견 → 활력 레시피 1회 구매(첫 화분 포함) → 자동 재배·제작 → 여행자의 상위 선호품 판매**다. 이후 온실의 집중 물약과 유적의 야행 물약을 지역 확장 후보로 둔다. 첫 발견은 확률에만 맡기지 않고 귀환 횟수로 보장하는 안이다.

이 절과 연결 문서의 신규 콘텐츠·수치는 **제안**이며 최신 확정 방향을 제외하고 F01~F12의 구현 범위를 자동으로 확대하지 않는다. 연구 대기·수동 보상 수령은 추가하지 않는다. 원정은 최신 확정에 따라 여러 지역 동시 진행·회차 출발비 자동 결제·자동 반복으로 변경하고, 금액과 보상은 별도로 조정한다. 기존 개발 상태와 플레이어 저장은 기획 편집만으로 변경하지 않는다.

나머지 성장 구조는 [성장과 단골 꾸미기 기획안](성장과-단골-꾸미기-기획안.md)에 정리했다. 첫 90분의 경험 목표, 판매대·보관함 투자, 판매 보조 훈련과 재배 보조, 손님 4종의 자동 단골 기록, 장식 영구 소장, 복귀 결과의 주요 변화와 다음 목표를 다룬다. 명성은 구매 조건, 단골은 이야기·기념품, 원정 발견은 신규 생산 콘텐츠로 역할을 구분한다.

후속 순서는 **숲 발견·활력 → 결과·판매대·소품 → 단골·접객 훈련 → 온실·재배 보조 → 유적·상위 외형**을 제안한다. 각 단계·가격·효과를 합의하기 전에는 신규 기능 전체를 확정 범위에 넣지 않는다. 전체 소비 목록과 문서의 우선순위는 [성장과 골드 사용처](성장과-골드-사용처-테이블.md)에서 확인한다.

## 아래 본문의 적용 범위

이하 본문은 현재 구현 분석과 상세 검토 자료다. 위 F01~F12를 설명하는 범위에서 참고하며, 위 표에 없는 세부 기능·수치·출시 범위를 별도의 확정 사항으로 간주하지 않는다. 상충하면 위 구현 지시와 최신 사용자 요청을 우선한다.

**달그늘 물약상점은 재료 조달·제조·판매가 완전 자동으로 진행되고, 낮밤과 날씨에 따라 얻는 약초·포션 제조 결과·방문 손님이 달라지는 데스크톱 방치형 연금술 상점 게임이다.** 플레이어는 해금·강화·꾸미기를 선택한다. 재배 품종 교체, 제조 예약, 판매 대상 지정 없이도 해금한 콘텐츠가 자동 운영에 합류한다. 환경이 경제에 영향을 주는 기능은 후속 구현 제안이다.

현재 자동 운영과 창 제어 기반은 구현돼 있다. 다음 개발은 **환경 변화 → 특수 약초 자동 수확 → 재료에 맞는 포션 자동 제조 → 손님에게 자동 판매 → 결과 확인과 성장 투자**의 흐름을 검증한다. 투명 노점과 꾸미기는 운영 경험을 보여주는 화면과 소비 목표로 발전시킨다. 아래에서 ‘현재’는 코드에 있는 동작을, ‘제안’과 목표 수치는 앞으로 검증할 설계를 뜻한다.

성장 시스템의 상세 범위는 [성장과 골드 사용처 테이블](성장과-골드-사용처-테이블.md)에 정리한다. 레시피 연구·아이템 구매·설비 투자·종업원·원정·꾸미기를 골드 사용처로 두고, 명성은 소비하지 않는 해금 조건으로 사용한다. 원정은 종업원이 자동 탐색하는 후속 콘텐츠이며 직접 전투를 요구하지 않는다.

현재 기반의 강점은 자동 생산·판매와 낮밤·날씨가 이미 있다는 점이다. 보완할 점은 환경이 바뀌어도 재료와 제조·거래 결과가 같고, 돈을 쓸 목표도 생산 강화에 집중돼 있다는 점이다. 작은 모드와 최소 모드에서도 현재 환경, 자동 제조 중인 포션, 대기 이유가 읽혀야 한다.

## 플레이어와 핵심 경험

대상은 문서 작업·공부·개발·영상 시청 중에 작은 게임을 함께 켜두고 싶은 PC 사용자다. 짧은 선택으로 가게가 달라지는 것을 좋아하고, 접속 시간 약속이나 잦은 수령 버튼에는 부담을 느끼는 사람을 우선한다.

세 가지 경험을 지킨다.

- **손을 놓아도 운영된다.** 기본 재료 수급부터 제조·판매까지 자동으로 이어진다. 재료나 골드가 부족해도 기본 물약으로 회복한다.
- **환경이 자동 운영에 변화를 만든다.** 비와 밤을 거치며 특수 약초·포션·손님 거래가 자동으로 쌓이고, 돌아왔을 때 그 결과를 발견한다.
- **내 취향이 화면에 남는다.** 효율 강화 외에 모자·찻잔·조명·진열품 등 돈을 쓰고 싶은 이유를 만든다.

기본 플레이는 15~30분에 한 번, 30~90초 정도 살펴보는 리듬을 목표로 한다. 더 자주 꾸미는 것은 허용하되, 보상을 놓치지 않으려면 계속 확인해야 하는 구조는 피한다. 이 시간은 사용자 테스트를 위한 목표이며 현재 측정값은 아니다.

## 생산과 경제 설계

### 유지할 자동 운영 규칙

기본 약초는 무료로 공급한다. 재료는 제조 시작 때 한 번만 차감하고 진행 중인 제조는 끝까지 처리한다. 현재 체력·마나 물약의 확정 생산은 유지하고, 새 특수 레시피부터 성공·실패 판정을 적용하는 안으로 검증한다. 특수 재료가 있으면 해금된 특수 포션을 자동 제조하고, 없으면 기존 체력·마나 생산으로 돌아간다. 진열대가 차면 진행과 투입 재료를 보존한다. 강화와 장식 구매는 플레이어가 직접 결정한다.

### 현재 수치와 성장 병목

| 항목 | 현재 값 |
| --- | --- |
| 체력 물약 | 약초 2개, 기본 5초, 판매 6 G |
| 마나 물약 | 약초 2개·버섯 1개, 체력 제조 시간의 1.25배, 판매 18 G |
| 약초 수확 | 기본 4초마다 2개, 초기 보관 24개 |
| 버섯 발주 | 12초마다 최대 2개, 개당 4 G, 보관 6개 |

현행 상태 로직으로 충분한 자금 1,000 G에서 자동 발주를 켜고, 레벨을 고정한 채 1시간 안정화 후 다음 1시간을 계산했다. 강화 구매비는 넣지 않았으며 플레이어 저장 파일은 사용하지 않았다.

| 솥 레벨 | 화분 레벨 | 분당 판매 병수 | 분당 매출 | 분당 재료 지출 | 분당 운영 순수입 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 9.60 | 172.80 G | 38.40 G | 134.40 G |
| 6 | 3 | 18.75 | 232.50 G | 40.00 G | 192.50 G |
| 15 | 12 | 18.75 | 232.50 G | 40.00 G | 192.50 G |

운영 순수입은 매출에서 재료 구매 지출만 뺀 값이다. 시작 자금 0 G에서의 초반 수익이나 강화 비용까지 포함한 회수 시간과는 다르다. 재현 코드는 `.verification/planning_economy_probe.gd`다.

**솥 6·화분 3 조합이 이미 판매 상한에 도달한다.** 이 조건에서는 최고 레벨까지 올려도 지속 수입이 늘지 않는다. 강화가 순간 재고 회복에 도움을 줄 수는 있지만, 이를 지속 수입 증가로 설명하면 안 된다.

후속 성장에는 판매 처리량도 함께 설계한다. 초기에는 ‘진열 정리’ 한 계열로 구매 간격을 줄이는 방식부터 검증한다. 그다음 고급 재료 공급과 레시피 이익을 맞춘다. 방문 수, 방문 간격, 구매 묶음 수를 한꺼번에 추가하면 병목을 이해하기 어려우므로 한 축부터 확장한다. 진열대 용량 증가는 일시적 완충에 유용하지만 판매 속도 자체를 올리지는 않는다.

강화 화면에는 현재 상태를 ‘약초 대기 / 제조 중 / 판매 대기’로 보여주고, 다음 강화의 변화도 수확·제조·판매 중 해당 항목으로 표현한다. 전체 화면에는 매출과 재료비를 구분하고, 작은 화면의 기존 수치는 ‘판매 수입’으로 명확히 부른다.

### 소비와 보상

효율 강화는 운영 속도를 바꾸고, 사치품은 가게의 모습을 바꾼다. 초기 장식에 생산 보너스는 붙이지 않는다. 가장 마음에 드는 모자를 썼는데 효율이 낮아지는 상황을 만들지 않는다.

첫 장식은 첫 환경 레시피를 경험한 뒤 15~30분 안에 선택할 수 있는 소비 목표로 둔다. 후속 소품은 해당 해금 단계의 운영 순수입 약 10~20분치, 큰 테마 목표는 약 1~2시간치를 초기 기준으로 삼는다. 가격은 단계별로 검증한 뒤 고정하며, 보유 골드나 현재 수입에 따라 실시간으로 오르지 않는다. 환경 설비와 꾸미기 소비가 서로 과도하게 지연시키지 않는지 함께 확인한다.

## 꾸미기와 수집

첫 구현은 README에 있던 **모자 3종 + 탁자 소품 3종**을 따른다. 배치 위치를 고정해 작은 화면에서도 읽히는 크기와 겹침 순서를 먼저 확보한다.

| 슬롯 | 초기 후보 | 구현 규칙 |
| --- | --- | --- |
| 주인 모자 | 별 장식 모자, 약초 리본 모자, 달빛 모자 | 현재 머리 위치에 맞추고 캐릭터 동작마다 어긋남 확인 |
| 탁자 소품 | 찻잔, 간식 접시, 작은 마법책 | 지정 위치에 한 개 장착하고 손님·솥을 가리지 않음 |

구매 → 소장 → 장착을 분리한다. 구매한 물건은 영구 보유하며 교체와 기본 모습 복귀는 무료다. 이미 가진 물건을 다시 결제하지 않는다. 미리보기에서는 골드를 차감하지 않고 구매 버튼에서만 확정한다.

관리 UI는 상단 확정안의 가게 운영·약초·레시피·원정 구분을 따른다. 강화 독립 탭과 꾸미기 화면의 위치·장식 슬롯은 후속 검토다. 탭을 바꿔도 생산은 계속되고, 장식을 도입하면 작은 모드에도 장착 결과가 보여야 한다. 자유 배치와 방 크기 변경은 초기 검토 범위에서 제외한다.

단골은 환경별 특수 손님을 기반으로 확장한다. 특정 포션 판매로 거래 실적이 쌓이면 새 레시피·공급 경로·소품을 해금하는 후보를 둔다. 방문과 거래는 보유 재고에 따라 자동 진행한다. 해당 환경을 놓쳐도 다음 순환에 다시 거래할 수 있고, 접속하지 않았다고 관계가 감소하지 않는다.

## 환경에 따라 달라지는 생산과 판매

차별화의 중심은 **낮밤·날씨에 따라 자동으로 들어오는 재료, 포션 성공률, 방문 손님이 달라지는 것**이다. 환경은 자동 운영의 결과에 변화를 만든다. 플레이어는 어느 설비와 레시피를 먼저 해금·강화할지 선택하며, 날씨마다 생산 설정을 바꾸지 않는다. 캐릭터별 날씨 애니메이션과 반응형 장식은 후순위다.

현재는 게임 속 하루 4분, 맑음·흐림·비의 90초 순환과 시각 효과가 구현돼 있다. 환경별 생산·판매 효과는 아직 없으며 아래 내용은 설계 초안이다. 낮밤과 날씨는 독립된 축으로 두고, 초기에는 둘의 희귀한 조합까지 요구하는 레시피를 만들지 않는다.

| 조건 | 재배와 수급 후보 | 제조 효과 후보 | 특수 손님 후보 |
| --- | --- | --- | --- |
| 맑은 낮 | 햇빛풀 성장 | 활력 계열 성공률 상승 | 활력 포션을 선호하는 여행자 |
| 비 | 이슬풀 성장 | 정화 계열 성공률 상승 | 정화 포션을 찾는 숲의 손님 |
| 밤 | 달꽃 성장 | 달빛 계열 성공률 상승 | 달빛 포션을 높은 가격에 사는 마법사 |

흐림은 초기에는 기본 조건으로 두고 전용 콘텐츠를 나중에 확장한다. 어느 한 환경이 모든 레시피에 가장 유리하지 않도록 계열별 강점을 나눈다. 품종명·레시피명·효과 수치는 확정 전이다. 현행 자동 발주 재료인 달빛 버섯과 새 재배 재료 달꽃은 별개다.

### 특수 약초의 자동 수급

기본 약초 화분은 항상 운영하고, 전용 화분을 해금하면 해당 특수 약초의 자동 재배가 추가된다. 달꽃 화분은 밤 동안 성장도가 쌓이고 낮에는 멈추며, 진행도와 이미 수확한 재료는 유지된다. 이슬풀도 비가 오는 시간만 성장한다. 조건이 맞으면 자동 재배·수확을 반복하고 보관 한도에서 대기한다. 씨앗 심기·수확 클릭·날씨별 품종 교체는 요구하지 않는다.

수확한 특수 약초는 환경이 바뀌어도 사라지지 않고 자동 제조에 사용된다. 화분과 대응 레시피를 함께 해금해 제조할 수 없는 재료만 쌓이는 상황을 피한다. 플레이어는 다음 화분의 해금과 성장 속도·보관량 강화를 선택한다.

새 계열의 공개 조건은 명성·거래 실적과 연결하는 방향으로 검토한다. 최신 레시피 흐름은 골드 1회 구매 후 즉시 자동 제작 대상에 추가하는 것이다. 연구 대기 시간과 연구 슬롯을 요구하지 않는다. 기본 재료 공급원을 함께 제공하는지는 미정이며, 도구·추가 설비·장식은 별도의 효과를 가진 구매로 구분한다.

### 포션 성공률과 실패 결과

현재 체력·마나 물약의 확정 제조를 기본 운영으로 유지하고, 새 특수 레시피부터 환경별 성공·실패를 적용하는 안을 먼저 검증한다. 예를 들어 달빛 포션 성공률을 낮 60%, 밤 90%로 두면 밤에는 완성품이 더 잘 쌓이는 변화가 생긴다. 제조 시점은 자동으로 정해지며 플레이어가 예약하지 않는다. 수치는 효과 설명용 예시이며 밸런스 확정값이 아니다. 자동으로 낮은 확률의 제조를 강행해 해금 전보다 장기 수입이 낮아지지 않는지 반드시 검증한다.

특수 제조는 시작할 때 재료를 차감하고 그때의 환경·성공률을 고정한다. 제조 도중 낮밤이 바뀌어도 진행 중인 배치의 확률은 바뀌지 않는다. 한 배치에 성공 여부를 한 번만 결정하고 저장·불러오기로 다시 추첨하지 않게 한다. 표시한 성공률은 실제 판정에 그대로 사용한다.

실패한 배치는 목표 포션을 만들지 못하고 소량의 재활용 잔재를 남기는 안을 우선 비교한다. 잔재는 고정량을 모아 기본 약초로 교환하며, 기본 생산보다 실패 반복의 보상이 높아지지 않게 조정한다. 실패 비용과 제조 시간을 명확히 표시하고, 최근 제조 결과에서 성공·실패 횟수와 소비 재료를 확인할 수 있게 한다.

설비 성장은 ‘제조 시간 단축’, ‘불리한 환경에서 성공률 보완’, ‘특수 재료 보관 확대’처럼 운영 목적이 다르게 설계한다. 성공률에는 상한을 두고, 초반 설비 하나로 모든 환경 차이가 없어지지 않게 한다.

### 환경별 손님과 자동 판매

일반 손님은 기본 물약을 계속 구매하고, 특수 손님은 조건에 맞는 환경에서 방문 후보에 포함된다. 마법사는 밤에 방문해 달빛 포션을 선호하며 일반 매입가보다 높은 가격을 제시하는 식이다. 첫 구현에서는 특수 손님을 기존 방문 슬롯의 일부로 배정하고, 별도의 추가 방문으로 판매량까지 동시에 늘리지 않는다.

일반 손님도 특수 포션을 기본 가격에 살 수 있고, 특수 손님은 선호 포션이 있으면 그것을 우선 구매하며 추가 값을 낸다. 선호 포션이 없으면 기존 물약을 구매하는 안으로 시작한다. 초기에는 판매 예약이나 특정 손님용 재고 잠금 없이 모든 판매를 자동 처리한다. 특수 손님에게 팔지 못한 재고도 다음 일반 판매에서 소진될 수 있어 진열대가 막히지 않는다.

특수 손님의 등장 빈도·구매량·가격을 함께 제한하고 기대 수입으로 평가한다. 일반 판매가 기본 수입을 만들고 특수 손님 거래가 추가 성과로 남도록 조정한다. 사용자가 판매 시점을 제어할 수 없으므로 재고 예약을 하지 않았다는 이유로 손해 보는 가격 구조를 만들지 않는다.

손님 기본안은 여행자·여기사·여마법사·엘프·고양이 도적 5종이다. 시간·날씨와 선호 품목의 매핑은 [손님 테이블](성장과-골드-사용처-테이블.md#명성과-손님의-연결)을 따른다. 선호 거래와 첫 발견은 명성 성장에 연결하며, 명성이 쌓이면 연구·상품·고용·원정 지역의 접근 조건이 열린다. 방문 경향은 초기에는 시간·날씨별 출현 비중으로 구현해 특정 조합을 기다리느라 기본 영업이 막히지 않게 한다.

### 설정 없이 이어지는 자동 운영

첫 특수 레시피는 재료가 있으면 자동으로 제조하고, 없으면 기존 체력·마나 생산으로 돌아간다. 여러 특수 레시피가 해금되면 재료가 있는 레시피를 고정된 순서로 돌아가며 제조하는 안부터 검증한다. 사용자는 레시피 우선순위·제조 시간·재료 예비량을 설정하지 않는다. 최신 확정에 따라 영업·버섯 발주는 별도 조작 없이 즉시 자동 진행하며 켜기·끄기 전환은 제거한다.

예를 들어 밤이 되면 달꽃 수확이 시작되고, 재료가 모이면 달빛 포션이 자동 제조되며, 방문한 마법사가 재고를 구매한다. 낮이 되어도 남은 달꽃은 계속 제조에 쓰이고 떨어지면 기존 물약을 만든다. 환경 표시는 ‘밤 · 달꽃 성장 · 달빛 제조 성공률 상승’처럼 현재 결과의 이유를 설명한다. 돌아온 사용자는 수확량·제조 성공·특수 거래 결과를 확인하고 다음 해금이나 강화에 투자한다.

### 시간 처리와 경제 검증

현행 환경 시간은 실행 때 초기화된다. 후속 구현은 환경 시간을 게임 상태로 옮겨 저장하고, 재실행·모드 전환으로 날씨나 성공 판정을 다시 고르지 못하게 한다. 게임 내부 시간을 사용하며 현실 시간·위치·날씨 연동은 초기 범위에 넣지 않는다. 특수 약초는 실제로 조건이 맞았던 시간만 성장한다. 제조는 시작 시점, 손님 출현은 방문 판정 시점의 조건을 사용한다.

종료 중 진행을 추가할 때도 같은 환경 순서, 성장 조건, 제조 판정, 방문 규칙으로 계산한다. 복귀 순간의 날씨를 부재 시간 전체에 적용하지 않는다. 저장에는 진행 중 제조와 난수 상태를 포함해 중복 정산·재추첨을 방지한다. 시각 효과를 줄이거나 꺼도 생산 규칙은 같다.

현행 4분 하루·90초 날씨는 초기 실험값이다. 좋은 환경 한 번 안에 약초 수확과 여러 번의 제조를 경험할 수 있는지 먼저 검증한다. 시간 조정으로 유리한 조건이 너무 희귀해지거나 한 번의 실패가 지나치게 긴 대기가 되지 않게 한다.

경제 비교는 기본 운영만 해금한 상태, 특수 계열 하나를 해금한 상태, 여러 계열을 해금한 상태를 여러 난수 시드에서 수행한다. 평균 순수입뿐 아니라 재고 점유, 미판매 수량, 연속 실패, 재료가 없는 시간도 본다. 예상 제조 가치는 ‘성공률 × 성공 포션 가치 + 실패율 × 잔재 가치 − 재료 비용’이며, 최종 시간당 수익에는 제조·재배·환경 대기·방문 대기를 함께 포함한다. 새 레시피 해금이 기존 제조 시간을 차지하므로 재료비뿐 아니라 기본 물약을 만들지 못한 기회비용도 비교한다. 해금할수록 자동 운영이 불리해진다면 가격·성공률·소요 시간·자동 배분 규칙을 조정한다.

첫 기능 검증은 **밤 → 달꽃 자동 수확 → 달빛 포션 자동 제조와 성공률 차이 → 마법사 자동 거래** 한 흐름으로 제한한다. 다음으로 비·이슬풀·정화 포션·숲의 손님을 추가한다. 설정 없이도 환경별 결과가 달라지고 해금·강화의 목표가 생기는지 확인한 뒤 날씨별 동작과 장식 연출에 투자한다.

## 화면과 데스크톱 사용성

전체 모드는 운영 판단과 구매, 작은 모드는 가게 관찰, 최소 모드는 업무 중 상태 확인에 사용한다. 세 모드가 같은 생산·영업 상태를 공유하고 모드 전환으로 시간이 초기화되지 않아야 한다.

상주 화면은 **배경이 투명한 작업실**을 따른다. 주인·솥·화분·판매대·손님을 남기고 직사각형 벽과 큰 배경을 숨긴다. 별도 야외 노점·차양·바닥판은 필수 요소가 아니다. `관리` 버튼으로 열고 닫는 패널에 운영·레시피·원정을 배치한다. 기존 전체 실내 모드와 최소 모드의 존치·통합은 기존 기능을 보존하는 범위에서 구현하며, 현재 화면 정리 때문에 임의로 삭제하지 않는다.

투명 작업실에서는 캐릭터·글자의 선명도를 유지한 채 배경을 분리한다. 기존 불투명도 슬라이더는 장면 전체를 흐리게 하는 기능이므로 배경 숨기기와 구분한다. 투명한 빈 영역의 클릭 통과는 실제 Windows 창에서 검증하고, 가게의 조작 영역과 이동 손잡이는 사용할 수 있게 남긴다. 비 입자나 빛의 영역이 클릭을 가로채지 않아야 한다.

다음 데스크톱 개선은 창 위치 복원, 화면 밖으로 벗어났을 때 복구, 다중 모니터와 125~200% 배율 검증이다. 불투명도 조절과 마우스 클릭 통과는 서로 다른 기능이므로 혼동해 안내하지 않는다. 화면 가장자리 붙이기는 창 위치 조절을 돕는 후보이고, Windows 작업 표시줄 자체와의 통합은 별도 기능으로 취급한다.

팝업으로 작업 창의 포커스를 빼앗지 않는다. 해금 안내는 가게 안에 조용히 남긴다. 음향을 추가할 때는 기본 음소거와 명확한 볼륨 제어를 제공한다. 현재 30 FPS 제한은 있으나 저전력 동작을 입증하지는 않는다. 숨김·최소화 시 렌더링 감소와 생산 시간 유지를 함께 검증한다.

## 종료 중 진행 제안

장시간 PC를 켜두지 않아도 다시 돌아올 이유가 생기도록 종료 중 운영을 추가한다. 첫 규칙은 **마지막 정상 저장으로부터 최대 8시간을 기존 자동 운영과 같은 규칙으로 정산**하는 안으로 검증한다. 8시간은 초기 설계값이다.

영업 중 종료했다면 제조·판매·발주를 함께 계산한다. 휴업 중이었다면 수확과 제조만 환경 조건과 보관 한도 안에서 진행한다. 자동 발주 설정, 해금된 화분·레시피, 제조 순서를 보존한다. 해금·강화·장식 구매는 대신 수행하지 않는다.

재접속 시 경과 시간, 판매 매출, 재료비, 최종 골드 증가를 한 번에 보여준다. 확인 버튼을 누르지 않아도 정산 결과는 저장돼 있어야 한다. 시계가 뒤로 이동하면 보상 시간을 0으로 처리하고, 과도한 경과 시간은 상한으로 제한한다. 정상 종료·비정상 종료·중복 실행 복구에서 같은 기간을 두 번 정산하지 않게 설계한다.

현재 `advance()`는 사건 순서에 따라 시간을 계산할 수 있어 출발점으로 쓸 수 있다. 다만 저장 시각·중복 정산 방지·절전 복귀 처리는 아직 없다. 긴 시간을 계산하는 성능도 별도로 확인해야 한다.

## 돌아왔을 때의 결과

앱을 켜둔 채 다른 일을 한 뒤에도 지난 확인 이후의 영업 결과를 볼 수 있게 한다. 매출·재료비·순영업수입, 약초 수확, 포션 성공·실패, 선호 거래, 구매 해금, 명성 증가를 요약한다. 원정에는 실제 구현된 지출·귀환·발견만 포함한다. 종료 중 진행은 별도 검토 항목이며 F10의 실행 중 결과 기능과 구분한다.

모든 보상은 발생 시점에 반영하고 결과 창은 기록 확인용으로 사용한다. 작업 중 강제 팝업을 띄우지 않으며, 사용자가 결과를 닫아도 자동 운영이 멈추지 않는다. 상세 표와 예시는 [영업 결과 테이블](성장과-골드-사용처-테이블.md#돌아왔을-때의-영업-결과)을 참고하되 미도입 시스템의 예시 결과를 실제 수치처럼 표시하지 않는다.

## 장기 확장 순서 검토

다음 표는 장기 콘텐츠 검토용이다. 이번 코딩 순서는 상단 `구현 순서와 인수 확인`을 따라 투명 작업실과 관리 UI부터 진행한다. 데모 범위와 출시 일정은 별도 결정한다.

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 환경과 자동 생산 | 환경 시간 저장, 첫 특수 약초·포션, 손님 선호 구매 | 설정 없이 수확·제조·판매 진행, 조건 일치, 저장 재추첨 없음 |
| 2 성장과 성과 | 레시피 1회 구매, 명성, 판매대 투자, 영업 결과 | 구매 후 자동 제작 가능, 성장 효과와 지출 내역 확인 |
| 3 상주 경험과 공개 데모 | 투명 노점, 첫 장식, 종료 중 진행, 배율·성능 검증 | 빈 영역 클릭 통과, 부재 중 동일 규칙, 중복 정산 없음 |
| 4 종업원 | 판매 보조 1명, 고용과 훈련 | 고용 전에도 기본 자동 운영 지속, 직원 효과와 비용 명확 |
| 5 원정 | 탐색 담당 1명, 지역 1곳, 자동 보급·귀환 | 예비금·보관 한도 준수, 반복 출발·보상 중복 없음 |

첫 기능 검증은 기존 물약 2종에 특수 약초·포션·손님을 각각 1종 추가한다. 공개 데모 목표는 방 1개, 기본 물약 2종과 특수 물약 2종, 특수 약초 2종, 특수 손님 2종, 장식 6개다. 낮 계열과 여러 환경을 조합하는 희귀 레시피는 이후 확장으로 둔다.

손님 외형 5종은 기본 캐릭터 목표다. 데모의 특수 거래 구현 수와 출시 시점은 검토 중이다. 명성·영업 결과와 원정·고용의 기능 범위는 상단 확정 목록을 따르고, 이전의 연구 1슬롯·연구 타이머 제안은 현재 구현에 적용하지 않는다.

초기 범위에서 제외할 것은 전투, 파티 편성, 실시간 멀티플레이, 플레이어 간 거래, Steam 마켓 경제, 환생 반복, 자유 배치, 다점포 운영이다. 일일 숙제·확률형 유료 뽑기·작업 도중 강제 광고도 채택하지 않는다.

## 판매 방식과 소개 방향

판매 방식은 **핵심 기능이 포함된 유료 본편**을 우선 검토한다. 종료 중 진행·창 제어·기본 자동화는 기본 경험에 포함한다. 이후 외형 테마 확장은 가능하지만 데모에서 꾸미는 재미를 확인한 다음 결정한다. 구체적인 출시 가격은 아직 정하지 않는다.

상점 소개 문구 초안: “밤에는 달꽃이 자라고, 비가 오면 특별한 포션이 만들어집니다. 당신이 다른 일을 하는 동안에도 재료를 모으고 물약을 파는 작은 연금술 상점을 키워보세요.” 환경별 생산·거래 구현 이후 사용할 소개안이다.

첫 소개 영상은 다른 프로그램 옆의 가게, 밤이 되며 성장하는 달꽃, 달라진 성공률과 포션 제조, 마법사의 구매, 수익으로 설비를 확장하는 순서로 구성한다. 실제 구현한 장면만 출시 소개에 사용한다. 현재는 환경별 생산·특수 거래·투명 노점을 구현 예정으로 구분해야 한다.

## 검증 기준

초기 사용자 5~8명에게 다른 작업과 함께 사용하게 하는 탐색 테스트를 제안한다. 표본이 작으므로 통과 여부는 다음 개발 결정을 위한 기준이며 시장 전체의 반응으로 일반화하지 않는다.

| 확인할 가설 | 초기 기준 | 부족할 때 바꿀 것 |
| --- | --- | --- |
| 방치 구조가 이해된다 | 5명 중 4명이 1분 안에 자동 제조·판매를 설명 | 안내와 상태 표시 |
| 환경의 효과가 이해된다 | 5명 중 4명이 15분 안에 밤의 약초·제조·손님 변화를 설명 | 환경 효과·자동 제조·결과 안내 |
| 돈 쓸 목적이 생긴다 | 5명 중 4명이 30분 안에 다음 설비·레시피·장식 목표 선택 | 노출 순서·가격·해금 효과 |
| 변화가 작은 화면에서 보인다 | 5명 중 4명이 장착 전후 차이를 바로 알아봄 | 소품 크기·배색·가게 구도 |
| 일을 방해하지 않는다 | 30분 미조작에도 운영 지속, 강제 팝업·필수 수령 없음 | 자동 운영 규칙·안내 방식 |
| 다음 목표가 있다 | 30분 뒤 다음에 얻고 싶은 것을 한 가지 말함 | 해금 예고·수집 보상 |

성능은 기준 PC의 CPU·GPU·메모리·화면 배율을 기록하고 측정한다. 초기 목표는 작은 모드 30 FPS에서 평균 CPU 2% 이하, GPU 5% 이하, 메모리 300 MB 이하로 둔다. 이 값은 아직 달성 여부를 측정하지 않았고 하드웨어에 따라 조정한다. 먼저 30분 동안 평균·최댓값을 측정하고, 공개 데모 전에 2시간 실행의 메모리 증가와 절전 복귀를 확인한다.

경제는 무강화·솥 우선·화분 우선·장식 우선 경로와 환경 계열별 해금 순서를 10분·1시간·8시간으로 비교한다. 예비금 때문에 발주가 멈춰도 기본 운영이 이어지는지, 판매 병목 뒤의 강화가 과장된 효과를 약속하지 않는지 확인한다. 여러 난수 시드로 실패 손실과 수익 분포를 확인한다. 저장은 기존 버전 이전, 환경·성장 진행도·확정된 제조 판정·자동 제조 순서·장식 복원, 손상 파일 복구, 종료 중 정산 재실행을 검사한다.

## 구현 참고와 근거

기존 `shop_state.gd`는 자동 운영과 저장 데이터를, `shop.gd`는 화면·창 제어를, `shop_art.gd`는 가게 연출을 맡는다. 장식은 항목 ID·슬롯·가격·에셋 정의와 소장 목록·장착 ID를 분리하면 기존 운영 로직에 미치는 영향을 줄일 수 있다. 저장 형식을 확장할 때 기존 버전 1~3의 기록을 이전하는 경로를 유지한다.

| 근거 | 확인 내용 |
| --- | --- |
| `README.md` | 플레이 설명, 저장 방식, 기존 사치 요소 후보 |
| `scripts/shop_state.gd` | 제조·판매·발주·강화 수치와 저장 데이터 |
| `scripts/shop.gd` | 창 크기, 30 FPS 제한, 최근 판매 수입, 초기 창 위치 |
| `scripts/shop_sky.gd` | 현재 낮밤·날씨 순환, 실행 시 초기화, 창밖 시각 효과 |
| `.verification/shop-auto-supply.png`, `.verification/shop-mini.png` | 기존 전체·작은 모드 화면 구성 |
| `.verification/planning_economy_probe.gd`와 같은 이름의 `.log` | 레벨 고정 조건의 경제 비교 결과 |

바로 이어서 구현할 작업은 **F01~F04의 투명 작업실과 관리 UI**다. 이후 1회 구매·결과 확인·환경·손님·원정·성장 기능을 상단 확정 ID의 순서로 연결한다. 이 참고 본문에 등장하는 추가 애니메이션·장식·출시 수량은 자동으로 구현 범위가 되지 않는다.
