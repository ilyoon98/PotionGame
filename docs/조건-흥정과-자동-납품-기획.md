2026년 10월 13일 확정 · 2026년 10월 15일 **첫 버전 구현·격리 검사·파일 미리보기 검수 완료**

캐릭터 디자인·애니메이션 완료 후 요청한 첫 버전을 연결했다. 구체 범위와 조정한 개발 검증용 초기값은 [제작 명세](조건-흥정과-자동-납품-제작명세.md), 실제 코드·저장 이전·검사·경제 비교는 [개발 결과](조건-흥정과-자동-납품-개발결과.md)를 따른다. 아래 제안과 미정 목록은 확장 기획이며 첫 버전에 선택한 값도 최종 밸런스 승인과 구분한다. 실제 Windows 화면·입력 및 현재 플레이어 저장은 검증하지 않았다.

후반 성장에는 거래처와 납품 조건을 합의하고 완성한 생산망으로 대량 주문을 처리하는 목표를 추가한다. 플레이어는 **거래처의 첫 계약과 거래 등급이 올라갈 때만 조건을 흥정**한다. 합의한 계약은 제작·분할 납품·정산·다음 회차까지 자동으로 이어진다.

흥정은 새로운 거래 관계와 조건을 고르는 짧은 선택이며 성공과 실패가 있다. 후속 강화로 흥정 성공률을 높일 수 있게 한다. 매 주문의 가격 조정이나 납품 버튼을 반복해서 누르는 흐름은 만들지 않는다. 기존 일반 손님 판매와 한 솥의 자동 제조를 함께 유지한다.

## 확정한 진행 방식

| 구분 | 확정 내용 |
| --- | --- |
| 흥정 방식 | 손님이 제시한 주문의 물량·품목 구성·보상 조건을 비교해 합의하는 **조건 흥정** |
| 흥정 결과 | 더 유리한 조건을 요청할 때 성공·실패가 있으며, 성공하면 개선 조건으로 계약 가능 |
| 성공률 강화 | 가구·직원의3단계 훈련. 미래의 적용 가능한 확률 협의가 남아 있을 때 구매·추천. 현재 수치와 가격은 최신 F19 명세를 따름 |
| 첫 계약 | 거래처별 최초 계약에서 플레이어가 조건을 선택하고 수락 |
| 이후 반복 | 합의한 조건으로 제작·납품·정산과 다음 회차가 자동 진행 |
| 다시 흥정하는 시점 | 해당 거래처의 거래 등급이 올라갈 때 |
| 수동 조작의 범위 | 첫 계약과 등급 상승의 조건 선택·수락. 매 병 납품·매 회차 재수락·보상 수령은 자동 |
| 후반 목표 | 납품 실적을 쌓아 거래 등급을 올리고 다음 계약 조건을 선택 |

물량·가격·거래처 수·등급 기준·보상 종류·해금 시점과 흥정의 기본 성공률·강화 증가량·상한은 아래 제안 및 미정 항목으로 구분한다. 확정한 진행 방식과 구체적인 경제 수치를 혼동하지 않는다.

## 계약과 거래 등급의 의미

**거래처**는 반복해서 주문하는 상대다. 기존 일반 손님과 별도의 계약 기록을 가지며 거래처를 추가한다고 작업실에 일반 손님이 여러 명 동시에 등장하는 것은 아니다.

**계약 조건**은 요구 품목 범위, 물량, 보상과 자동 반복 내용을 묶은 합의다. **납품 회차**는 그 조건으로 한 번 주문량을 채우는 과정이다. 같은 계약으로 여러 회차를 완료해도 매번 다시 흥정하지 않는다.

**거래 등급**은 해당 거래처와의 누적 실적을 나타낸다. 기존 가게 명성과 구분하며 소비하는 화폐로 만들지 않는다. 등급 상승 조건과 등급별 계약 수는 검증 후 정한다.

## 첫 계약부터 자동 반복까지

1. 거래처를 처음 만났을 때 주문과 조건 선택지를 보여준다. 수락하지 않은 계약은 생산과 납품에 합류하지 않는다.
2. 플레이어가 요구 물량·품목·보상과 성공률을 확인한다. 기본 제안을 그대로 수락하거나 더 유리한 조건을 흥정하고, 결과에 따른 최종 계약을 수락한다. 흥정 결과와 수락한 조건을 저장한다.
3. 기존 솥에서 일반 판매용과 납품용 제조가 함께 배분된다. 성공한 완성품이 실제로 출고될 때 납품 누계를 올린다.
4. 주문량을 채우면 자동으로 정산하고 거래 실적을 반영한다. 결과를 열거나 확인 버튼을 눌러야 보상을 받는 방식은 쓰지 않는다.
5. 같은 조건의 다음 회차를 자동으로 시작한다. 재료가 부족하면 해당 납품이 기다리며 일반 운영은 계속한다.
6. 거래 등급이 올라가면 새 조건을 흥정할 기회를 표시한다.

## 등급 상승과 새 조건 적용

등급 상승 협상을 미뤄도 **기존 조건으로 자동 납품을 계속한다.** 강제 팝업이나 협상 응답 대기로 가게를 멈추지 않는다. 관리 화면에는 `새 계약 조건 협의 가능`처럼 짧게 알린다.

새 조건을 수락해도 진행 중인 회차의 물량·보상·납품 누계를 바꾸지 않는다. 현재 회차를 기존 조건으로 완료한 뒤 다음 회차부터 새 조건을 적용한다. 이미 합의한 새 조건이 적용을 기다리는 동안 같은 등급의 협상을 다시 요구하지 않는다.

등급 상승과 새 조건 합의는 별도로 저장한다. 조건을 아직 고르지 않았다는 이유로 등급을 내리거나 완료한 회차를 취소하지 않는다. 강화·날씨 전환·레시피 구매·관리 재열기·재접속은 흥정 발생 조건이 아니다.

## 조건 선택의 구성 제안

다음은 조건 흥정의 **선택지 예시**다. 수치와 보상 종류는 확정값이 아니다. 거래처마다 의미가 다른 조건을 제시하며 모든 거래처에 같은 선택지를 강제로 적용하지 않는다.

| 선택 예시 | 바뀌는 요구 | 바뀌는 보상 | 선택할 이유 |
| --- | --- | --- | --- |
| 기본 계약 | 기본 품목과 물량 유지 | 기본 대금과 거래 실적 | 현재 생산망으로 부담 적게 반복 |
| 대금을 더 받기 | 다른 계열 추가 또는 더 큰 물량 | 더 높은 계약 대금 | 필요한 재료를 충분히 공급할 수 있을 때 |
| 재료로 받기 | 합의한 품목 구성과 물량 | 골드 일부 대신 원정 재료 | 부족한 재료 수급을 보완할 때 |
| 거래 관계에 투자 | 여러 계열 납품 등 다른 요구 | 거래 실적 또는 기념품·장식 진척 | 다음 거래 조건이나 가게 외형을 목표로 할 때 |

예를 들어 `회복 계열 40병`을 제시한 거래처와 대금을 더 받기로 협의하면 `회복 계열 40병 + 마나 계열 10병`을 최종 조건으로 제시할 수 있다. **40병·10병은 설명용 예시이며 기존 포션 데이터의 계열 이름과 대응은 구현 설계에서 맞춘다.**

조건을 고르면 달라지는 품목·물량·보상과 **시도 전에 실제 성공률 및 실패 시 조건**을 함께 보여준다. 단순히 금액만 더 높은 무조건 유리한 선택지나 같은 제안을 반복해서 눌러 보상을 올리는 구조는 피한다. 반복 가격 입력은 이번 핵심 방식에 포함하지 않는다.

## 흥정 성공과 실패의 연결 기준

성공·실패는 **기본보다 유리한 조건을 얻는 요청의 결과**다. 거래처 자체의 개방, 이미 달성한 거래 등급이나 기존 납품 계약을 실패 대상으로 삼지 않는다. 기본 제안을 그대로 수락할 때에는 흥정 성공 판정을 요구하지 않는다.

| 시점과 결과 | 적용할 흐름 |
| --- | --- |
| 첫 계약 흥정 성공 | 성공한 개선 조건을 확인하고 수락하면 자동 납품 시작 |
| 첫 계약 흥정 실패 | 기본 제안으로 계약 가능. 첫 실패 때문에 거래처가 영구 잠기거나 일반 영업이 멈추지 않음 |
| 등급 상승 흥정 성공 | 새 조건을 수락하면 현재 회차를 보존하고 다음 회차부터 적용 |
| 등급 상승 흥정 실패 | 거래 등급과 기존 계약 유지. 기존 조건의 자동 납품은 계속 진행 |

실패에 골드·재료 벌금, 거래 실적 감소, 계약 해지나 납품 중단을 붙이지 않는다. 실패의 결과는 요청한 개선 혜택을 얻지 못하는 것이다. 재료·물량 등 납품 요구도 실패한 개선 조건으로 임의 변경하지 않는다.

**재시도 제한의 초기 검토안은 거래처별 첫 협의 및 협의 등급마다 개선 요청 판정 1회**다. 기본 제안 수락으로 해당 협의를 끝내거나 개선 조건 중 하나를 시도하면 같은 기회의 다른 선택지·관리 재열기·재접속·강화 구매로 다시 추첨하지 않는다. 실패 후 다음 기회는 다음 거래 등급에 도달할 때 생기는 안이다.

이 제한의 횟수와 최종 등급 처리는 제작 전 검증한다. **최종 등급에서 실패한 뒤 성공률 강화까지 쓸 곳이 없어지는 문제**를 함께 확인하고, 최종 등급 보장이나 추가 협의 기회를 도입할지는 별도로 정한다. 단순히 버튼을 계속 누르거나 골드로 같은 판정을 재추첨하는 흐름은 쓰지 않는다.

방치 중 여러 등급이 올랐을 때에는 현재 도달한 등급의 협의 한 개만 보여주고 과거 미시도 기회를 적립하지 않는 안을 검토한다. 돌아왔을 때 이전 등급의 흥정을 연달아 처리해야 하거나 낮은 등급 조건이 높은 계약을 덮지 않게 한다. 누적 등급 상승 처리도 아직 확정 수치·규칙에 포함하지 않는다.

## 흥정 성공률 강화

**흥정 훈련은 가구·직원의3단계 골드 투자로 확정한다.** 별도 직원 선고용은 요구하지 않는다. 초기 가격8,000/20,000/50,000 G과 일반 성공률60→70→80→90%를 유지하고, 최종 협의100%와 이미 나온 판정은 바꾸지 않는다. 현재 등급과 미래1~3등급에 적용할 미판정 기회가 전부 없으면 직접 구매·추천을 막는다.

| 강화 표시 제안 | 효과와 적용 시점 |
| --- | --- |
| 흥정 훈련 | 더 유리한 계약 조건을 요청할 때 성공률 증가 |
| 구매 전 효과 | 현재 성공률과 강화 후 성공률을 비교. 가격·조건과 동일한 실제 값을 표시 |
| 효과 적용 | 아직 판정하지 않은 협상에는 현재 강화값 적용 |
| 이미 판정한 협상 | 성패·확률·조건 유지. 구매 때문에 재추첨하거나 실패를 성공으로 변경하지 않음 |

일반 성공률은 기본60%에 훈련 단계당10%p를 더하고90% 상한을 적용한다. 최종4등급은 별도로100%를 보장한다. 이 수치는 제작 초기값이며 `성공률 +N%p`와 `보상 +N%`를 같은 효과로 표시하지 않는다. 남은 적용 기회·오래 열린 버튼·표시 조건은 F19 명세에 맞춘다.

강화는 계약 대금이나 자동 납품 속도를 함께 올리는 효과로 임의 확장하지 않는다. 생산·판매·원정 및 포션 제조 성공률과 흥정 성공률은 구분한다. 흥정은 드물게 발생하므로 다음 협상까지의 간격과 실제 강화 가치를 함께 검증한다.

## 기존 제조와 판매에 연결하는 기준

**솥은 하나이고 한 번에 한 배치만 제조한다.** 수주를 추가해 포션별 병렬 제조나 별도의 수동 제조 예약을 도입하지 않는다. 이미 시작한 배치의 재료·판정·진행·용도는 계약 수락이나 새 조건 적용 때문에 변경하지 않는다.

납품은 실제로 출고한 병을 누적한다. 주문 전체를 공용 물약 보관 한도인 최대 60칸에 동시에 모을 필요가 없어야 한다. 제조 실패, 제조 중인 병, 일반 손님에게 판매된 병은 납품량에 포함하지 않는다. 한 병은 일반 판매 또는 계약 납품 중 한 곳에만 사용한다.

일반 영업용과 납품용 제조를 함께 배분해 어느 한쪽이 계속 밀리지 않게 한다. 남는 재고만 기다리는 방식은 현재 후반의 낮은 재고 상태에서 납품이 멈출 수 있으므로 단독 진행 규칙으로 쓰지 않는다. 납품용 제조 몫과 보관·출고 처리 방식은 실제 생산 및 손님 대기 측정으로 정한다.

납품 대상은 **구매해 실제 제조할 수 있는 레시피**에서 정한다. 미발견·미구매 특별 레시피를 필수 요구로 넣거나 수주 화면에서 숨겨진 이름·그림을 공개하지 않는다. 특별품 납품 조건이 있는 계약은 해당 레시피 구매 이후에 제시한다.

초기 요구는 계열과 허용 품목 범위를 사용하는 안을 우선 검토한다. 현재 일반 제조는 계열의 상위품을 우선하므로 하위 포션 하나를 정확히 요구하면 납품이 진행되지 않을 수 있다. 허용 품목의 판정과 실제 납품용 제조 후보를 함께 연결해야 한다.

## 후반 해금과 보상 제안

| 항목 | 검토할 방향 | 아직 정하지 않은 부분 |
| --- | --- | --- |
| 콘텐츠 첫 해금 | 마지막 원정 `별의 정원`을 처음 열었을 때 거래처 소개 | 최초 개방 또는 일반 조사 완료 중 최종 기준 |
| 후속 계약 | 거래 등급 상승으로 새 조건과 거래처 콘텐츠 확장 | 거래처 수·등급 수·누적 실적 기준 |
| 골드 보상 | 납품 계약의 대금과 추가 보너스 | 금액·재료비·일반 판매 기회비용과의 균형 |
| 재료 보상 | 부족한 재료를 받을 수 있는 계약 조건 | 대상 재료·수량·보관 가득 처리 |
| 외형 보상 | 거래처 기념품이나 가게 장식 | 품목·그림·해금 및 적용 화면 |
| 신규 투자 | F19 확정: 기존 성장 완료 후 보급 지원·납품 일괄 조제 각3단계 | 각15만/30만/45만 G, 총180만 G 적용·검수 완료. 기존60만 구매의 실제 지출·골드·소유·예약 보존, 소급 환급 없음. 세부 효과·해금은 F19 명세 |

마지막 원정의 **최초 개방과 일반 조사 완료는 다른 상태**다. 특별 레시피 전부 발견·구매, 모든 기존 강화 완료를 필수로 묶는 방향은 이번 확정에 포함하지 않는다.

골드 대금만 늘리면 모든 투자를 끝낸 가게의 다음 목표가 약해질 수 있다. 재료 수급, 거래 관계, 외형 소장을 보상 후보로 함께 검토하되 새로운 재화를 먼저 추가하지 않는다. 신규 레시피·새 지역·실시간 경매는 별도의 후속 콘텐츠로 결정한다.

## 관리 화면 구성 제안

가게 운영에는 현재 납품의 **거래처 아이콘·납품 수량 게이지·짧은 상태·상세 진입**을 둔다. 계약을 처음 합의하거나 등급이 올라가 새 조건을 고를 때만 선택 화면을 연다. 별도 수주 페이지를 두는 안은 검토하되 여섯 탭을 글씨 축소로 억지로 끼워 넣지 않는다.

| 화면 | 기본 표시 | 상세에서 확인할 정보 |
| --- | --- | --- |
| 가게 운영의 납품 행 | 거래처·`납품 23/40`·실제 누계 게이지·대표 상태 | 품목별 누계·합의한 보상·거래 등급 |
| 첫 계약과 등급 상승 협의 | 주문 아이콘·물량·조건별 차이·수락 | 허용 포션·배합과 공급 조건 |
| 거래처 상세 | 현재 등급·계약 조건·자동 반복 상태 | 완료 실적·다음 등급 조건·적용 예정 조건 |

`납품 중`, `재료 대기`, `새 조건 협의 가능`처럼 짧고 직접적인 용어를 사용한다. 여러 품목을 요구하면 실제 품목별 필요량과 완료량도 상세에서 읽을 수 있어야 한다. 합계 게이지만 채웠다고 부족한 다른 품목까지 완료 처리하지 않는다.

작은 투명 작업실과 최소·정보 화면의 크기, 기존 대표 게이지는 유지한다. 수주 때문에 새 소품·팝업·상시 숫자를 화면 밖에 계속 늘리지 않는다. 먹색·세이지, Pretendard, 기존 글씨 크기와 구분선 스타일을 이어간다.

## 저장과 정산 기준

거래처별 첫 계약 여부, 거래 등급·실적·협의 가능 여부, 합의한 조건과 적용 예정 조건, 흥정 강화 단계를 저장한다. 각 협의에는 기회 식별·대상 거래처와 등급·선택 조건·시도 여부·판정 당시 성공률과 강화값·성패·최종 제안 조건을 기록한다. 각 납품 회차는 고유한 회차 식별, 적용 조건, 요구 품목과 수량, 보상, 실제 납품 누계, 완료 지급 여부를 가진다.

흥정 버튼을 누르면 판정과 결과 저장을 한 번 처리한다. 표시한 성공률을 실제 판정에 사용하며 결과 화면은 저장한 기록을 보여준다. 같은 틱의 중복 클릭, 선택지 변경, 재접속·날씨·시간 전환·강화 구매로 재추첨하거나 혜택을 중복 적용하지 않는다. 흥정용 난수 상태는 기존 제조·판매·원정 추첨의 순서를 바꾸지 않게 분리해 보존한다.

납품품의 출고와 누계 반영은 한 처리로 묶고 완료 보상은 한 회차에 한 번만 지급한다. 재접속·관리 재열기·같은 틱의 동시 완료·저장 복원으로 계약 대금, 재료, 거래 실적이나 기념품이 중복 지급되지 않아야 한다. 보상 재료의 보관 가득 때문에 일반 운영이 멈추거나 지급 기록 없이 보상이 사라지지 않도록 처리한다.

대금은 **회차 완료 때 일괄 지급하는 안**을 우선 검토한다. 병별 기본 대금과 완료 보너스를 나누는 안을 채택한다면 이미 지급한 기본 대금을 완료 때 다시 지급하지 않는다. 두 정산 방식을 동시에 적용하지 않으며 정산 시점과 부분 납품 상태의 표시는 세부 설계에서 결정한다.

기존 저장에는 수주 미시작·흥정 훈련 미구매 상태를 추가하고 골드·명성·레시피·기존 강화·원정·현재 제조를 보존한다. 과거 일반 판매나 원정 기록을 새 납품 실적으로 소급해 완료 보상을 지급하지 않는다.

관리 UI를 닫거나 다른 프로그램을 쓰는 동안 **게임이 실행 중이면** 납품과 자동 반복이 계속된다. 앱을 완전히 종료한 동안의 제조·납품·수익은 기존 오프라인 보상 보류 정책을 따른다. 계약에 현실 시간 마감을 두거나 재접속을 이유로 만료·손실을 적용하지 않는다.

## 초기 기획의 검토 항목과 후속 확장

아래는 첫 기획에서 정리한 검토 목록이다. 첫 버전에서 선택·검증한 해금·거래처·확률·훈련·배분·정산·UI는 최신 제작 명세와 개발 결과를 따른다. 재료 보상·외형 소장·특별품 납품 등 첫 버전 밖의 확장은 계속 제안으로 남긴다.

- 마지막 원정 최초 개방과 일반 조사 완료 중 수주 해금 조건.
- 거래처 목록, 거래 등급 수와 실적 기준, 동시 납품 회차 수와 대기 순서.
- 조건별 요구 품목·수량·대금·재료 보상·거래 실적·외형 보상.
- 조건별 기본 성공률, 흥정 훈련의 위치·단계·증가량·가격·상한과 실제 강화 가치.
- 첫 계약·등급별 시도 횟수, 최종 등급 실패의 보완 여부, 방치 중 여러 등급이 오른 경우의 협의 처리.
- 일반 제조와 납품 제조의 배분, 공용 보관과 출고 처리, 재료 대기 때의 진행.
- 대금 지급 시점, 보상 재료의 보관 가득 처리, 계약 조건과 회차의 저장 형식.
- 수주 페이지 진입과 배치, 거래처·계약·보상 아이콘 및 신규 에셋 범위.
- 납품 관련 설비·직원 도입 여부와 골드 사용처.

물량을 크게 늘려 기다리는 시간만 늘리는 방식으로 플레이 시간을 보장하지 않는다. 일반 손님 대기, 포션별 생산·판매·납품, 재료 소모, 회차 완료 시간, 순수입과 새 등급 도달을 함께 측정한다. 흥정은 성공·실패 및 훈련 전·후 경로를 비교한다. 초반 가게와 후반 가게, 간헐적으로 확인하는 플레이를 구분해 검증한다.

## 구현 완료 확인 기준

- 첫 계약 수락 이전에는 납품하지 않고 수락 이후에는 수동 수령 없이 회차가 반복된다.
- 흥정은 첫 계약과 거래 등급 상승에만 발생하며 일반 회차 완료마다 다시 요구하지 않는다.
- 시도 전에 실제 성공률과 성공·실패 조건을 표시한다. 성공하면 개선 조건으로 계약 가능하고 실패해도 기본 계약 또는 기존 납품으로 성장할 수 있다.
- 흥정 훈련 구매는 미판정 협상의 확률에만 적용한다. 판정 완료 협상은 강화·중복 입력·재열기·재접속·저장 복원으로 다시 추첨하지 않는다.
- 등급 상승 협의를 미뤄도 기존 계약이 반복된다. 새 합의는 현재 회차를 보존하고 다음 회차부터 적용된다.
- 한 솥의 일반 제조·판매와 납품이 함께 진행된다. 주문 재료가 부족해도 일반 영업은 계속한다.
- 실제 출고한 성공품만 품목별로 집계하며 창고 한도를 넘는 주문도 분할 납품으로 완료할 수 있다.
- 숨겨진 특별 레시피와 미구매 품목을 요구하거나 공개하지 않는다.
- 회차 완료와 저장 복원으로 보상·거래 실적이 중복 반영되지 않고 기존 저장의 진행이 보존된다.
- 현재 UI의 글씨·아이콘·화면 크기·관리 선택 및 스크롤과 오프라인 보류 정책을 유지한다.

검증은 격리 저장과 headless 검사 및 파일 미리보기로 진행한다. **Computer Use, 실제 사용자 화면·입력·포커스, 실제 플레이어 저장, 실행 중인 게임의 재시작·종료·조작은 사용하지 않는다.**
