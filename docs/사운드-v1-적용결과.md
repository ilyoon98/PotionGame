# 사운드 v1 적용 결과 · 2026-10-22

상태: 첫 효과음 4종과 재생 노드, 설정 저장, 관리 창 토글을 연결했다. headless 검사는 통과했다. **실제 스피커 청취는 하지 않았다(미검증).** 기본값(볼륨 0.5·효과음 켜짐)과 소리 빈도는 사용자 확인 대상이다.

## 효과음 4종

`tools/build_sfx_v1.py`가 외부 에셋·numpy 없이 표준 라이브러리(`wave`, `math`, `struct`)만으로 합성한다. 같은 입력이면 같은 파일이 나온다(재실행 해시 동일 확인). 형식은 16-bit PCM mono 22050Hz다. 모든 소리의 피크는 −6dBFS 이하이고, 각 음의 3ms 시작·12ms 끝 처리와 전체 4ms 페이드 인·25ms 페이드 아웃으로 첫·끝 샘플을 0으로 맞춰 클릭을 막는다.

| id | 파일 | 길이 | 피크 | 구성 |
|---|---|---|---|---|
| `coin` | `assets/audio/sfx_v1/coin.wav` | 0.15s | −10dBFS | 판매 동전. 맑은 두 음 B5→E6, 짧은 종소리 감쇠 |
| `brew_done` | `assets/audio/sfx_v1/brew_done.wav` | 0.30s | −12dBFS | 제조 완료. 위로 미끄러지는 작은 거품 4개 |
| `expedition_return` | `assets/audio/sfx_v1/expedition_return.wav` | 0.50s | −10dBFS | 원정 귀환. C5-E5-G5 3음 아르페지오 |
| `unlock` | `assets/audio/sfx_v1/unlock.wav` | 0.60s | −11dBFS | 기념·해금. C6-E6-G6-C7 반짝임과 E7 잔향, 은은한 떨림 |

음 높이·시작 시각·감쇠·배음·목표 피크·실측 피크·SHA256은 `assets/audio/sfx_v1/manifest.json`에 있다. Godot 가져오기 설정은 기본값(반복 없음, 압축 모드 2)이며 `.import` 파일을 함께 넣었다. 다시 만들 때는 `py -3 tools/build_sfx_v1.py` 다음 `--headless --import`를 실행한다.

## 재생 노드 `scripts/shop_audio.gd`

- Shop의 자식 노드 `ShopAudio`. 소리마다 AudioStreamPlayer 2개 풀을 돌려 쓴다(Master 버스, 새 버스 없음).
- 같은 소리 최소 간격: 동전 0.25s, 제조 완료 0.6s, 원정 귀환 1.0s, 해금 0.4s(`MIN_INTERVAL`). 같은 프레임의 여러 요청은 한 번만 재생된다.
- Shop은 한 번의 갱신에서 판매가 여러 건이어도 `coin`을 한 번만 요청한다. 제조 완료도 같다.
- 마스터 볼륨 0~1(기본 0.5, 선형 값을 `linear_to_db`로 적용), 음소거. 잘못된 볼륨은 기본값, 범위 밖은 0~1로 자른다.
- `DisplayServer.get_name() == "headless"`이면 `play()`를 절대 호출하지 않는다. 대신 `requests`(모든 요청)와 `plays`(음소거·간격을 통과한 요청)를 세어 테스트에 쓴다.
- ShopState를 읽거나 바꾸지 않는다. 경제·RNG·저장 시점에 영향이 없다.

## 기존 파일 변경 (병합용 요약)

- `scripts/shop.gd`
  - 상단 상수/변수 2줄: `const ShopAudio = preload(...)`, `var shop_audio: Node`.
  - `_ready()`의 `system_tray` 추가 직후 4줄: ShopAudio 생성·이름·`apply_settings(state.audio_volume, state.audio_muted)`·`add_child`.
  - `_advance_game()` 3줄: 원정 귀환 분기 안 `play_sound("expedition_return")`, `art.apply_potion_events(...)` 다음 `if events["sold"] > 0: play_sound("coin")`, `if events["brewed"] > 0: play_sound("brew_done")`.
  - `_save()` 앞에 새 함수 2개: `play_sound(id)`(노드가 없으면 무시), `set_audio_muted(value)`(실행 보호 확인 → state와 노드 반영 → `_save()`).
- `scripts/management_panel.gd`
  - 변수 1줄 `var sound_toggle: CheckButton`.
  - 설정 탭 `GameSettings`의 "밤의 밝기 하한" 슬라이더 바로 아래에 `CheckButton` "효과음"(이름 `SoundToggle`, 기존 자동 실행 토글과 같은 42px 높이·본문 글자 크기·INK 색) 10줄. 켜짐=소리 남, 끄면 `host.set_audio_muted(true)`.
  - `buy(kind)`에 2줄: 구매 전 `totals["unlocks"]`를 기억하고, 증가했을 때만 `host.play_sound("unlock")`. 레시피·원정/지역·직원·여과기 같은 해금·고용이 대상이고 일반 강화(`upgrade:`)나 실패한 구매는 소리가 없다. 계약·작업실·숙성·주인공 투자 등 `perform_*` 경로는 바꾸지 않았다.
- `scripts/shop_state.gd`
  - 변수 3줄: `DEFAULT_AUDIO_VOLUME := 0.5`, `audio_volume`, `audio_muted`.
  - `to_data()`에 선택 키 1줄 `"audio": {"volume": float, "muted": bool}`.
  - `load_data()` 끝(`management_position` 처리 뒤) 6줄: `window_position`과 같은 방식. 키가 없거나 사전이 아니거나 값이 잘못되면 그 항목만 기본값으로 돌아가며 저장 전체를 거부하지 않는다. 볼륨은 유한한 숫자 0~1만, 음소거는 bool만 받는다. `SAVE_VERSION`(15)은 바꾸지 않았다.
- `tools/verify_f20_unpurchased.gd`, `tools/verify_f20_recovery.gd`: 고정 참조와 비교할 때 이미 제외하던 `window_position`/`management_position` 옆에 `audio`도 제외(각 1줄).

## 검증

`tools/verify_sfx_v1.gd`(headless, 격리 Shop, 플레이어 저장 미접근, 재생 없음):

- WAV 4개: RIFF 헤더가 16-bit PCM mono 22050Hz, 피크 −6dBFS 이하, 첫·끝 샘플 무음, 계획 길이. `AudioStreamWAV`로 로드되고 mono·22050Hz·반복 없음·길이 일치. manifest 프레임 수 일치.
- 간격 제한: 같은 시각 동전 3번 → 1회, 0.2s 뒤 → 건너뜀, 0.25s 뒤 → 재생. 소리별 간격은 서로 독립.
- 실제 Shop 연결: 60초를 한 번에 진행해 판매·제조가 여러 건이어도 coin·brew_done 요청 각 1회. 0.5초 단계 300초 진행에서 판매·제조·원정 귀환이 일어난 단계 수와 요청 수가 정확히 같다. 관리 창 `buy("expedition")`은 unlock 1회, 거절된 재구매와 솥 강화는 0회.
- 음소거: 설정 토글을 끄면 state·노드가 함께 음소거되고, 이후 600초 진행과 해금 구매에서 요청은 세지만 재생 0회. 다시 켜면 해제.
- 저장: JSON·SaveStore 왕복 유지. 키 없음/문자열/배열/빈 사전/볼륨 2.0·−0.1·NaN·INF·"0.7"/음소거 1·"true" 11가지 모두 저장은 읽히고 해당 항목만 기본값.
- 시뮬레이션 무관: 오디오 있는 Shop, 오디오 노드를 제거한 Shop, 음소거 Shop, Shop 없는 순수 State를 0.25초×2400(중간 솥 강화 포함) 진행한 전체 `to_data()`가 같다(State 생성 벽시계 시각 `report_started`와 headless 창 모드만 비교에서 제외).
- 근거: `.verification/sfx-v1/proof.json`.

## 남은 확인

- **실제 스피커 청취는 미검증.** 음색·크기·거슬림 여부는 사용자가 들어 보고 판단해야 한다.
- **기본값 볼륨 0.5·효과음 켜짐은 사용자 확인 대상.** 처음부터 꺼 둘지, 볼륨 슬라이더를 노출할지는 결정하지 않았다(지금 UI는 켜기/끄기 토글만 있고 볼륨은 저장 키로만 존재).
- 빈도: 초반 기본 상태에서 300초 동안 판매 소리 약53회·제조 소리 약52회·원정 귀환 약4회가 요청됐다(약 3초에 한 번 어떤 소리). "드물게"에 비해 잦다고 느껴지면 `MIN_INTERVAL`을 늘리거나 제조 완료 소리를 빼는 조정이 필요하다.
- 트레이로 숨겨진 상태에서도 소리가 난다. 숨김 중 소리를 끌지는 결정하지 않았다.
- 실행 중인 게임은 다음 정상 재실행부터 반영된다. 플레이어 저장(AppData)·Windows 자동 실행 등록·실행 중인 게임은 건드리지 않았다.

## 빈도·숨김·볼륨 조정 · 2026-10-23

첫 실제 실행 직후 저장에 음소거가 켜져 있었다(코드상 음소거는 설정 토글로만 바뀐다). 후반 가게는 초당 여러 병을 팔아 0.25초 간격이면 동전 소리가 거의 계속 나므로, 위 "남은 확인"의 세 항목을 기본값으로 정리했다. 수치는 사용자 확인 대상이다.

- `MIN_INTERVAL`: 동전 0.25 → **5초**, 제조 완료 0.6 → **10초**, 원정 귀환 1.0 → **2초**, 해금 0.4초 유지.
- 본 창이 최소화(트레이 숨김)된 동안 판매·제조·원정 소리는 쉰다(`ShopAudio.AMBIENT`, `ambient_paused`). 해금은 플레이어가 직접 산 것이므로 유지한다. headless의 가짜 창은 최소화로 보고되므로 이 조건에서 제외한다.
- 관리 → 설정의 효과음 토글 아래에 **"효과음 크기"** 슬라이더(0~1, 0.05 단위)를 추가했다. 값은 10초 자동 저장·종료 저장으로 남는다.
- F22 단골 단계 상승(`regular_events`) 때 해금 소리를 낸다. 게임 전체에서 16번뿐이다.
- 검증: `tools/verify_sfx_v1.gd` 152개 통과(간격 상수, 숨김 중 주변 소리만 쉼, 슬라이더→상태·노드, 음소거 중 단골 소리 요청 수 포함).
