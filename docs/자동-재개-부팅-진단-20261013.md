# 2026-10-13 자동 재개 부팅 진단

**현재 게임 재개 확인 / 부팅 당시 실패 원인 미확정 / 다음 로그인 진단 설치 완료**

사용자는 게임을 켠 채 컴퓨터를 종료하고 다시 켰지만 게임이 자동으로 열리지 않았다고 보고했다. Windows 마지막 부팅은 2026-10-13 09:14 KST였다. 조사 시 실행 중인 게임 프로세스는 없었고, 게임 로그 및 실행 기록은 전날 것이었다.

읽기 확인 결과 `login_resume.json`에는 `enabled=true`, `was_running=true`가 남아 있었다. 현재 사용자의 `MoonshadePotionShop` Run 명령, 실행 파일, 프로젝트 폴더가 존재했고 StartupApproved의 해당 항목 차단 및 확인한 Run 비활성화 정책은 없었다. 설치된 도우미를 실제 Windows PowerShell로 dry-run하면 `ready`였다. 따라서 조사 시점의 닫힘 표시·누락 경로·등록 누락으로는 증상을 설명할 수 없었다.

등록된 로그인 도우미를 실제로 호출했을 때 게임 PID 43540이 생성되고 실행 기록이 해당 PID로 갱신됐다. 게임 창이 응답하고 중복 방지 및 데스크톱 입력 프로세스도 유지됐다. 다음 dry-run은 `already_running`으로 게임을 추가 실행하지 않았다. 실제 컴퓨터 재부팅이나 로그아웃을 수행한 검사가 아니므로 부팅 자동 실행 성공으로 단정하지 않는다.

기존 도우미는 결과를 표준 출력에만 쓰기 때문에 숨겨진 로그인 실행의 결과가 남지 않았다. 이번에는 별도 `login_resume.last-result.json`에 UTC 시각, 도우미 PID, 자식 PID, 게임 실행 기록 확인 여부와 결과·오류를 남긴다. 최초 호출부터 기록하고 최종 결과로 갱신하며 파일 크기는 누적되지 않는다. dry-run은 기록을 생성·변경하지 않는다. 기록 실패는 실행 판단에 영향을 주지 않으며 진행 저장과 실행 의도 파일은 진단에서 변경하지 않는다.

기존에는 Start-Process 후 게임이 바로 종료돼도 `started`를 반환했다. 이제 실행 기록 확인 전에 자식이 종료되면 `child_exited`와 종료 코드를 남기며, 2초 안에 확인되지 않았지만 실행 중이면 `launched_unconfirmed`로 구분한다. 느린 부팅을 실패로 단정하거나 임의로 중복 실행하지 않는다.

원본 파일과 동봉 GDScript 상수를 같이 수정하고 현재 사용자의 설치된 도우미에도 적용했다. 원본 백업 및 설치 확인은 프로젝트 `.verification/login-diagnostics-20261013/`에 있다. 실제 설치 검사는 `already_running` 결과가 기록되면서 기존 실행 기록은 그대로 유지됨을 확인했다. Run 등록은 변경하지 않았고 현재 게임은 계속 켜져 있다.

검증:

- `verify_windows_startup.gd`: 30개 실행기 dry-run과 5개 실제 PowerShell 파일 전달 검사 통과, 동봉 원문 일치 확인.
- `verify_login_resume.gd`: 설정·등록 실패·수동 종료·일반 해제·실제 관리 UI·경제/RNG 불변 검사 통과.
- `verify_login_diagnostics.ps1`: 호출 결과, JSON 오류, 시각, dry-run 읽기 전용, 실행 의도 보존, 진단 쓰기 실패 격리 및 네이티브 fixture 즉시 종료 검사.
- 테스트는 별도 작업 폴더와 APPDATA로 격리했다. 기본 샌드박스 사용자 APPDATA로 실행한 초기 headless Godot는 시작 시 crash가 발생했으며, 격리 경로로 재실행한 검사가 최종 결과다. controller fixture의 APPDATA는 프로젝트 `.verification` 밖으로 두어 실제 사용자 경로 거부 검사를 유지했다.

다음 로그인에서 확인할 사항:

- 새 시각의 결과가 없으면 도우미 호출 전 경로(Windows 로그인 실행)를 조사한다.
- `error` 또는 `child_exited`면 기록된 오류와 게임 로그를 확인한다.
- `started`면 게임 실행 기록까지 확인됐다. `launched_unconfirmed`면 해당 PID와 이후 게임 로그를 확인한다.
- `closed` 또는 `disabled`면 로그인 직전 실행 의도 기록과 사용자의 종료·설정 변경을 비교한다.

Windows Run은 사용자 로그인에서 실행되며 실행 시점이 즉시라는 보장은 없다. 이 일반 특성만으로 이번 실패의 원인을 지연으로 단정하지 않는다. [Microsoft Run/RunOnce 문서](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).
