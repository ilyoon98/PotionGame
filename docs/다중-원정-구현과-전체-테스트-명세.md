# 다중 원정 구현과 전체 테스트 명세

> 후속 보상 방향 · 2026-10-08: 사용자가 지역별 여러 재료·수량의 보상 풀 추첨과 낮은 확률의 특별 레시피를 요청했다. [랜덤 보상 풀과 특별 레시피](원정-랜덤-보상풀과-특별-레시피.md)의 방향과 초기안을 참고한다. 아래 고정 보상 표·모든 고정 보상 공간 확인은 기존 구현/경제의 기준이며 랜덤 보상에 그대로 재사용하지 않는다. 초기 수치·특별 레시피 획득 방식·반복 규칙은 설계 중이다. 이후 사용자 요청에 따라 **현재 개발은 Computer Use와 사용자 화면 조작 금지**, headless 검사만 진행한다.

기준일: 2026-10-08 · **사용자 제작 요청에 따른 개발 범위**

여러 해금 지역에 동시에 원정을 보내고, 매회 출발비를 자동 결제해 탐색·귀환·보상 반영·재출발을 반복한다. 새 지역은 이전 지역의 조사 완료 후 구매한다. 플레이어가 매회 보내기나 수령 버튼을 누르지 않는다. 기본 구매·재배·제작·판매는 계속 자동이다.

사용자는 이 기능 정리를 제작하고 개발에 전달하며 **Computer Use를 포함한 전체 테스트**를 요청했다. 이전의 Computer Use 중단 요청은 이번 개발 테스트에 대한 최신 요청으로 갱신한다. 기획 담당은 문서와 독립 계산만 작성하고, 게임 코드·실제 창 조작은 개발 담당이 수행한다.

## 이번 개발 범위

| 항목 | 연결할 범위 |
| --- | --- |
| 물약·레시피 | 기존 5종 포함 32종, 레시피 1회 구매·영구 보유·자동 제작 |
| 재료 | 기존 포함 11종, 레시피와 자동 재배 공급원·원정 보상 연결 |
| 원정 | 8지역, 지역별 1개 원정이 서로 동시에 진행, 회차 출발비 자동 결제 |
| 설비 | 8계열 85회 투자, 기존 단계·효과 보존 |
| 물약 계열 | 활력·비술·자연·기교 4계열 × 5회 = 20회 강화 |
| 직원 | 4역할 고용·각 5회 훈련 = 20회 훈련, 기본 영업의 필수 조건으로 만들지 않음 |
| 관리 화면 | 기존 3탭에서 확장 목록·지역별 상태·비용·보상·병목 안내 연결 |
| 작업실 원정 표시 | 떠 있는 단일 원정 상태판을 지도 아이콘·진행 중 지역 수로 정리, 클릭하면 원정 탭 |
| 복귀 결과 | 원정별 귀환·재료·발견, 회차 출발비와 순영업수입 표시 |
| 저장과 검증 | 기존 저장 이전, 지역별 진행·지출·보상 보존, 자동 검사와 실제 Computer Use 테스트 |

이번 요청에서는 위 콘텐츠 규모를 개발 기준으로 채택한다. 단골 이야기·꾸미기·지역 기념품 신규 아트·4탭 재구성·새 캐릭터 미니 화면은 이번 필수 범위에 추가하지 않는다. 기존 투명/전체/작음/320×112 최소 모드와 항상 위 기능은 유지한다.

입력은 [다중 원정 초기 데이터](balance/content-data-multi-expedition-v1.json)의 `candidate-d-multi-expedition`이다. 후보 C의 물약·배합·가격·설비·훈련 데이터를 유지하고 원정 동시 진행·출발비·보상·대기 규칙을 추가했다. 금액은 **개발 초기 적용값**이며 실제 로직 측정에서 문제가 확인되면 데이터로 조정하고 변경 이유와 결과를 보고한다. 미정 숫자를 이유로 기존 숲 1곳에만 적용하고 전체 확장 완료로 보고하지 않는다.

아트는 [정식 catalog.json](../assets/content_expansion_v1/catalog.json)의 안정적인 ID와 실제 경로로 연결한다. 원본 PNG·manifest·디자인 비교 시안을 덮어쓰지 않는다. 설비는 기본·개량·고급 3외형과 단계 표시를 조합하며 125개의 개별 아트를 새로 만들지 않는다. 한 작업실에 화분 8개를 모두 배치할 필요는 없다.

## 지역별 초기 수치

영구 개방비는 기존 후보 C를 유지한다. 이 비용은 한 번만 지불하며 재실행 때 다시 청구하지 않는다. 회차 출발비는 별도 운영비로, 실제 출발 순간 한 번 차감한다. 구매 화면은 두 비용을 구분해 안내한다.

숲의 발견은 3·6·10회, 6회 조사 지역은 2·4·6회, 5회 조사 지역은 1·3·5회에 해당 지역 레시피 구매 후보를 연다. 발견 자체가 구매비를 자동 차감하지 않는다. 최종 3레시피는 정원 조사 완료와 선행 레시피 조건을 유지한다.

동시 진행은 해금 지역별 1개이며 같은 지역에 팀을 중복 투입하지 않는다. 8지역 동시 운영이 가능하되 출발비·보관 조건을 만족해야 실제 출발한다. 새 지역 접근 순서를 유지하므로 직렬 조사 최단 하한은 이전처럼 원정 시간 단축 30%를 처음부터 보유한 가정에서 141분 52초다. 실제 완료 시간과 매출은 새 모델·실제 엔진에서 측정한다.

## 자동 출발과 비용 대기

1. 자동 재료 구매 보호 예비금은 초기 **30 G**다. 출발 후 골드가 30 G 아래로 내려가면 새 회차를 시작하지 않는다. 플레이어의 직접 구매는 기존 조건을 따르며 원정용 별도 강제 예산 설정을 요구하지 않는다.
2. 영구 개방을 구매하면 해당 지역을 자동 운영에 추가한다. 출발비까지 부족하면 해금은 유지하고 `출발비 부족 · 자동 대기`를 보여준다. 돈이 모이면 자동 출발한다.
3. 미완료 조사 지역을 먼저 출발시킨다. 같은 우선순위에서는 대기 시작이 오래된 지역, 같으면 지역 순서로 처리한다. 새로 해금한 지역도 해금 시점을 대기 시작으로 기록한다.
4. 미완료 원정의 출발비가 부족할 때 완료 지역을 재출발시키려면 예비금에 더해 우선 대기 중인 조사 원정의 출발비도 남긴다. 값싼 옛 원정이 새 조사의 예산을 계속 소진하지 않게 한다.
5. 같은 시점의 귀환·보상 입고를 먼저 처리한 뒤 재출발 후보를 판단한다. 여러 원정의 중복 결제나 골드 음수가 생기지 않게 순차 결제한다.
6. 출발 시 회차 ID·비용 결제 여부·지역·시간·보상을 고정한다. 훈련·날씨·저장 복원으로 진행 중 회차의 비용이나 보상을 다시 뽑지 않는다. 원정 시간 단축 효과는 다음 회차부터 적용한다.

회차 출발비 합계는 원정 운영 지출로 기록한다. `현재 골드 = 시작 골드 + 물약 매출 − 자동 재료비 − 원정 출발비 − 영구 구매·강화 지출`을 실제 로직 검증의 장부 기준으로 사용한다. 순영업수입은 물약 매출에서 자동 재료비와 원정 출발비를 뺀 값이며 영구 투자는 별도로 표시한다.

## 보관과 완료 지역의 반복

조사 미완료 지역은 보관이 가득 차도 조사·발견을 진행한다. 재료는 자동 입고하고 초과분은 종류별 대기 수량으로 합산한다. 재배 공급원을 아직 사지 않았어도 원정 보상은 정상 보관하며, 레시피 구매가 재배 공급원을 추가하는 기존 규칙을 유지한다.

완료 지역은 보상 재료 중 하나의 `보유+미입고` 수량이 한도의 50% 이하이고 **모든 보상 재료에 이번 보상을 받을 공간이 있을 때** 재출발한다. 이슬풀과 별잎을 함께 주는 숲은 두 재료 모두 이번 보상 공간이 있어야 한다. 슬롯이 부족하면 `재료 충분 · 자동 대기` 또는 `보관 공간 대기`를 표시한다. 재료가 소비돼 조건을 만족하면 자동 재출발한다.

진행 중 원정은 보관 변화로 취소하지 않으며 이미 결제한 비용을 다시 요구하지 않는다. 귀환 직후 가득 찬 재료를 삭제하거나 수동 수령을 요구하지 않는다. 원정 보상과 원정 발견은 따로 기록해 입고 대기 때문에 다음 레시피의 발견이 정지하지 않게 한다.

## UI와 기존 저장

작업실에는 지도 아이콘과 실제 진행 중 원정 수만 우선 표시한다. 여러 원정의 평균 진행률을 하나의 진행바로 표시하지 않는다. 지도 클릭은 기존 관리의 원정 탭을 열며 결제를 실행하지 않는다. 새 발견에 작은 표시를 남기고 일반 귀환마다 고정 팝업을 띄우지 않는다.

지역 카드는 아이콘·이름·출발비·보상·현재 상태·해당 지역 진행률을 보여준다. 잠김/구매 가능/탐색/귀환/비용 대기/보관 대기를 구분한다. 상세에는 누적 조사·다음 발견·영구 개방비와 효과를 둔다. 지역 순서를 고정하며 자동 갱신으로 스크롤·접힘·상세 선택이 초기화되지 않게 한다. 자동 켜기·끄기·매회 보내기·수령 버튼은 추가하지 않는다.

기존 버전 1~6 저장의 골드·재료·재고·제조 예약과 판정·진행·소유·직원·판매대 단계를 보존한다. 숲의 기존 누적 귀환은 조사 기록으로 인정하고 과거 비용을 소급 청구하지 않는다. 이미 진행 중인 숲 회차는 추가 결제 없이 기존 시간·보상으로 마친 뒤 다음 회차부터 신규 출발비와 보상을 적용한다. 기존 입고 대기 보상도 추가 지급·삭제 없이 이전한다. 새 지역·설비·직원은 이미 산 것으로 무료 지급하지 않는다.

| 시간과 장부 | 프레임 간격 차이·동시 귀환·큰 경과시간·8시간 계산에 중복 사건과 장부 오류 없음 |
| 영업 결과 | 반복 출발비가 별도 표시되고 결과 재열기로 비용·보상·집계가 중복되지 않음 |

실제 `shop_state` 로직으로 3난수 × 레시피 우선·설비 우선·15분 복귀 정책을 비교한다. 30·60·120분과 5분 창의 제조·판매·재고·제조 정지·손님 대기·원정 지출·진행 지역 수를 기록한다. 8시간 범위의 전체 레시피·지역·투자 완료 시점도 확인한다. 120분에 모든 성장 목표가 끝나면 완료 기준 실패다. 긴 재고 적체는 숨기지 않고 다음 조정 항목으로 보고한다.

독립 Python 기획 모델은 실제 로직과 Computer Use 검증을 대체하지 않는다. 신규 원정 지출을 포함한 결과를 이전 후보 C의 무료 단일 원정 결과와 혼합하지 않는다.

## Computer Use 실제 전체 조작 테스트

Computer Use 스킬의 `node_repl + @oai/sky` 초기화와 공식 지침을 따른다. 실제 반환된 앱/창 목록에서 테스트 Godot 창을 선택하고 스크린샷·UI 상태를 관찰한 뒤 한 동작씩 조작하고 다시 확인한다. 창 이름·좌표를 추측하거나 관찰 없이 구매를 반복하지 않는다.

테스트는 별도 저장 경로와 명확한 테스트 창 이름으로 실행한다. 기존 사용자 게임 창·플레이어 저장·다른 앱의 데이터는 테스트에 사용하지 않는다. 새 게임, 구매 가능, 골드 부족, 여러 원정 진행, 보관 가득, 후반 전체 콘텐츠, 옛 저장 이전 fixture를 준비하고 각 상태에서 실제 UI를 검사한다. 개발 fixture는 테스트 도구로 격리하며 일반 플레이에 무료 재화 지급을 넣지 않는다.

| 실제 조작 | 확인할 결과 |
| --- | --- |
| 새 게임 실행 | 시작 클릭 없이 가게 진행, 원정 미해금 표시, 한국어·아이콘·가격 읽힘 |
| 관리 열기와 3탭 전환 | 내용이 올바르고 가게 진행 유지, 확장 목록에 겹침·잘림 없음 |
| 레시피·설비·계열·직원 구매 | 실제 골드 1회 차감, 소유·효과·잠긴 조건 갱신, 불가능 구매는 차감 없음 |
| 첫 지역 해금 | 영구 개방비와 출발비 구분, 자동 출발 또는 정확한 비용 대기 |
| 여러 지역 원정 | 각각 다른 시간과 상태로 진행, 카드 순서·상세·스크롤 유지 |
| 비용 부족 후 수입 증가 | 실제 대기 이유 표시 후 자동 재출발, 기본 영업 유지 |
| 조사 완료·보관 가득·재료 소비 | 발견 정상 지급, 보관 대기 후 자동 재개, 수령 클릭 없음 |
| 낮밤·날씨 전환 | 작업실 환경·손님 경향·약초/물약 행 하이라이트 일치, 목록이 재정렬되지 않음 |
| 작업실 지도 클릭 | 원정 탭으로 이동, 작업실 그림 가리는 기존 고정 원정 상자 없음 |
| 창 이동·전체·작음·최소·복귀 | 창이 잘리지 않고 자동 진행·항상 위·원래 모드 복귀 유지 |
| 투명 빈 영역과 버튼 클릭 | 테스트용 뒤 창의 무해한 영역에는 클릭 전달, 관리·지도·창 조작 버튼은 게임이 처리 |
| 종료와 재실행 | 진행·현재 손님·예약 재료·원정 결제·미입고·화면 모드 복원, 비용/보상 중복 없음 |
| 복귀 결과 반복 열기 | 매출·원정 지출·발견 표시 정확, 상태·잔액 변동 없음 |

긴 성장 시간은 실제 로직 가속 측정으로 확인하고, Computer Use는 대표 상태의 실제 화면과 입력을 검증한다. 두 검증의 범위를 결과에 구분한다. 화면 증거는 테스트 창으로 제한하여 전후 캡처를 저장한다. 투명 렌더 스크린샷만으로 OS 클릭 전달 검사를 통과했다고 처리하지 않는다.

문제가 나오면 수정 후 관련 자동 검사와 해당 실제 조작을 다시 수행한다. 도구 연결·권한·지원 문제로 Computer Use를 실제 수행하지 못하면 사유와 미실행 항목을 보고하며 전체 테스트 완료로 표시하지 않는다. 이전 Computer Use 중단 요청만을 이유로 이번 테스트를 생략하지 않는다.
