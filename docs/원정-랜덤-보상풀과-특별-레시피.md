사용자는 원정에서 한 재료의 정해진 수량만 가져오는 대신, 보상 풀에서 여러 재료와 수량을 뽑고 낮은 확률로 특별 레시피도 얻는 방식을 요청했다. 기존 지역별 고정 재료 보상은 이 방향으로 변경한다. 아래 값은 개발 검토용 초기안이며 기존 경제 계산을 그대로 적용하지 않는다. 기획 담당은 게임 코드·아트·플레이어 저장을 수정하지 않는다. 이번에도 Computer Use 금지를 유지한다.

| 요소 | 규칙 |
| --- | --- |

## 재료 추첨 초기안 · 수치는 제안

지역의 **주재료 1종은 보장**하고, 보조 풀에서 **추가 1~2종**을 뽑아 매회 총 2~3종을 가져오는 안을 추천한다. 주재료와 같은 보조 후보 또는 중복 후보는 제외한다. 보조 1종은 75%, 2종은 25%의 초기 후보이며, 수량은 아래 정수 범위에서 균등 추첨한다. 보조 후보의 60/30/10은 선택 가중치이고 여러 종류를 뽑을 때는 중복 없이 남은 후보를 재정규화한다.

## 특별 레시피 획득 방식 확정

2026년10월13일 사용자가 발견 후1회 구매를 선택했다. 아래 비교에서 실제 적용 대상은 발견 후 구매이며 발견 즉시 습득은 채택하지 않는다. 구현·저장·미발견 표시·특별 탐색은 최신 명세를 따른다.

| 방식 | 발견 시 결과 | 이후 동작 |
| --- | --- | --- |
| 획득 즉시 영구 습득 | 희귀 원정 보상으로 레시피 자체를 영구 획득 | 필요한 공급원과 자동 제작에 합류. 별도 레시피 구매비 없음 |
| 발견 후 1회 구매 | 특별 레시피를 구매 후보로 영구 개방 | 레시피 탭·성장 추천에서 골드로 한 번 구매하면 자동 제작 합류 |

기존 32종의 일반 레시피는 그대로 유지하고, 특별 레시피는 필수 진행과 분리된 소량의 추가 수집 콘텐츠를 추천한다. 초기 후보는 숲·계곡·유적·정원의 4종이며 이름·배합·가격·효과·아트는 별도 설계 대상이다. 아직 실제 아이템·무료 공급원·새 재료를 만든 것으로 표시하지 않는다.

**추가 제작 요청 · 2026-10-08:** 사용자가 특별 레시피와 대응 포션 이미지 제작을 요청했다. [특별 레시피와 포션 디자인 제작 요청](특별-레시피와-포션-디자인-제작요청.md)에 4종의 이름·기존 재료 배합·외형 초안과 레시피 아이콘 4개·포션 아이콘 4개·작은 병 4개의 제작 범위를 정리했다. 후보로 디자인을 제작하는 단계이며 실제 레시피 등록·경제값·획득 방식 확정이나 아트 완료를 뜻하지 않는다.

- 낮은 확률의 초기 후보는 해당 지역의 원정 완료당 3%다. 실패가 누적되면 30번째 유효 완료에서 보장하는 보완안을 제안한다. 확률·보장 횟수는 아직 확정 수치가 아니다.
- 해당 지역에 있는 미발견 특별 레시피만 추첨한다. 이미 발견한 것은 다시 뽑지 않는다. 미발견 대상이 없으면 재료 보상만 처리한다. 중복 보상용 새 재화는 추가하지 않는다.
- 일반 조사 완료는 특별 레시피 발견의 필수 조건으로 추가하지 않는 안을 추천한다. 보장 횟수는 특수 레시피 기능 적용 이후 실제 완료한 회차로 세며 과거 완료 횟수를 이유로 즉시 무료 지급하지 않는다.
- 특별 레시피를 못 얻었어도 다음 지역·일반 레시피·기존 강화 진행이 막히지 않는다.
- 완료 지역은 현재 재료가 충분하면 반복을 쉬므로 특별 발견 시도도 멈출 수 있다. **미발견 특별 레시피가 있으면 비용을 내고 탐색을 계속할지**는 반복·보관 규칙의 추가 설계 항목이다. 재료를 무한 적체시키거나 무료 추첨용 타이머를 UI에만 만들지 않는다. 이 부분을 정하기 전 특별 레시피 전체 구현 완료로 표시하지 않는다.

## 회차 추첨·보관·저장 원칙

기존 코드는 출발 시 회차 보상을 저장한다. 새 재료 보상도 **출발 때 한 번 추첨·저장하고 실제 원정 완료 때 공개·지급**하는 안을 사용한다. 사용자는 결과를 원정 완료 때 알게 되며 관리 화면 갱신·날씨 변화·강화·재실행으로 다시 뽑지 않는다. 기존 진행 중 회차는 저장된 고정 보상으로 마친 뒤 다음 출발부터 보상 풀을 적용한다.

완료 지역의 현재 반복 규칙은 고정 보상 전부를 받을 공간이 있어야 출발한다. 랜덤 풀에서는 아직 뽑지 않은 전체 후보를 기준으로 막지 않도록 변경이 필요하다. 주재료 수요·공간으로 출발을 판단하고 실제 추첨된 보조 보상은 초과분을 보존하는 안, 또는 한 번 저장한 추첨 결과가 입고 가능해질 때까지 대기하는 안을 비교한다. 공간이 부족하다는 이유로 좋은 결과가 나올 때까지 다시 뽑거나 재료를 삭제하지 않는다. 기본 약초·버섯 보상의 입고는 각 재료의 실제 전용 수량·한도를 사용해야 한다.

레시피 추첨을 추가할 때는 회차별 발견 결과·완료 처리 여부, 지역별 미발견/발견·획득 상태, 실패 누적 횟수·난수 상태를 저장한다. 여러 지역 동시 완료에도 획득·공급원 지급·구매 후보 개방은 한 번만 반영한다. 이미 보유한 이전 저장과 일치하는 결과를 다시 무료 지급하지 않는다.

## UI

- **추가 확정 · 2026-10-08 / 기존 실제 재료 결과 아이콘 구현 완료·headless 검사 통과 / 특별 발견 게임 연결 후속:** 원정 결과의 각 재료·특별 레시피 옆에 해당 아이템 아이콘을 표시한다. 해당 지역의 최근 결과와 영업 결과의 원정 보상 내역에 공통 적용한다.
- 결과 항목은 `[재료 아이콘] 재료 이름 × 실제 수량`으로 표시한다. 여러 재료는 각자의 아이콘을 가진 항목으로 나란히 배치하며 좁은 화면에서는 줄바꿈한다. 하나의 대표 재료 아이콘으로 전체 보상을 대신하지 않는다. 수량과 이름은 계속 읽을 수 있게 남긴다.
- 특별 레시피가 발견되면 `[해당 레시피 아이콘] 레시피 이름 · 특별 발견`으로 따로 표시한다. 획득 방식이 확정되어 실제 습득한 경우에만 `획득`으로 표시한다. 재료 수량과 같은 의미의 `×1`은 붙이지 않는다. 아직 특별 레시피 전용 아트가 없으면 공통 레시피 아이콘을 임시 사용하며 다른 물약 아이콘으로 혼동시키지 않는다.
- 재료는 기존 실제 아이템 ID와 연결된 픽셀 아이콘을 재사용한다. 결과 아이콘은 작은 크기에서도 형태가 읽히도록 정수 배율·최근접 표시를 사용한다. 이 표시 때문에 강제 팝업·수령 버튼·긴 설명을 추가하지 않는다.
- 원정 기본 카드에는 가능한 보상 재료 아이콘과 수량 범위를 짧게 표시한다. 실제로 가져올 재료와 후보 전체를 같은 의미로 표시하지 않는다.
- 원정 완료 후 최근 결과는 `이슬풀 3 · 별잎 2 · 달빛 버섯 1`처럼 실제 추첨된 항목만 표시한다. 예시 수량을 실제 결과처럼 고정하지 않는다.
- 특별 발견은 `특별 레시피 발견` 또는 획득 방식 확정 후 `특별 레시피 획득`으로 구분한다. 작은 새 발견 표시를 두고 강제 팝업·수령 버튼을 추가하지 않는다.
- 가중치·세부 확률·보장 진척·전체 보상 풀은 접힌 상세에서 확인한다. 가게 운영의 게이지 모음에 긴 보상 규칙을 나열하지 않는다.

## 검증과 반영 순서

1. 현재 진행 중 관리 UI·원정 용어 변경은 계속 완료한다. 보상 풀 변경과 특별 레시피를 UI 표시 변경으로 섞어 완료 처리하지 않는다.
2. 재료 풀 데이터·추첨·각 재료 입고·저장 복원·출발/보관 대기를 설계하고 여러 지역·여러 난수로 범위·중복·공급량을 검사한다.
3. 기존 고정 보상과 비교해 30/60/120분 및 8시간 성장·재료 대기·재고 적체·순수입·원정 지출을 검증하고 초기 숫자를 조정한다.
4. 특별 레시피 획득 방식·반복 규칙·실제 아이템을 정한 뒤 희귀 결과, 보장 경계, 발견 이후 반복 제외, 동시 완료·재실행과 기존 저장의 한 번 지급을 검사한다.
5. Computer Use와 사용자 화면 조작 없이 headless 검사로 확인한다. 미구현 설계·실제 조작 미실시는 결과에 분리 기록한다.

결과 아이콘은 실제 지급된 항목의 ID·이름·수량과 일치하는지, 여러 지역 동시 완료·긴 이름·좁은 화면에서도 겹침이나 수량 누락이 없는지 확인한다. 특별 발견이 없는 회차에는 특별 레시피 아이콘을 표시하지 않는다. 표시 갱신은 보상 추첨·지급을 다시 실행하지 않는다.
