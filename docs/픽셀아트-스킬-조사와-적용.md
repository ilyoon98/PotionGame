# 픽셀아트 스킬 조사와 적용

조사일: 2026-11-06. 사용자 제공 영상의 자동 자막·설명란과 각 프로젝트의 공식 저장소를 대조했다. 영상은 「AI 게임 리소스 제작에 사용할 수 있는 오픈소스 8가지」 [1편](https://www.youtube.com/watch?v=_U5wuMhZXI0)과 [2편](https://www.youtube.com/watch?v=ZN019l8wGBg)이다. 모두 설치형 Agent Skill인 것은 아니다. 스킬, 제작 라이브러리, MCP, 연구용 모델이 섞여 있다.

## 선택과 실제 적용

이번에는 **Pixelbolt**를 사용한다. 기존 픽셀을 무손실 JSON으로 가져와 제한된 부분의 움직임을 만들고, 검사 후 PNG 시트와 Godot `SpriteFrames`를 출력하는 작업이 이 게임에 잘 맞는다. 새 그림을 자동으로 잘 그려 준다는 의미는 아니다.

- Codex 스킬: `pixelbolt-pixel-art`. 공식 `skills/pixel-art/SKILL.md`를 commit `771e4428ba1fdc0698c5faa7ea9330fc03bc505f`에서 `skill-installer`로 설치했다. 다음 대화 턴부터 스킬 목록에 반영된다.
- 제작 엔진: **npm `pixelbolt@0.11.0`**, `tools/pixelbolt/package-lock.json`으로 고정. 공식 main의 최신 문서와 npm 릴리스가 다를 수 있으므로 이번 재현에는 설치된 0.11.0 문서를 사용한다.
- 설치 스크립트는 비활성화했다. 엔진은 Node 20 이상에서 실행하며 별도 이미지 API 키나 모델 다운로드가 필요 없다. 게임 실행 파일에는 Node나 Pixelbolt가 들어가지 않는다.
- 실제 적용 산출물: [F25 직원 움직임 비교](../art/mockups/f25-staff-motion-v1/review.html). 기존 v2의 정지 모습에서 작은 대기 움직임을 만드는 제작 실험이다. 외형 승인이나 게임 연결 완료를 뜻하지 않는다.
- 재현: `node tools/build_f25_staff_motion_v1.mjs --force`. 저장소에 보존한 원본을 입력으로 사용하며 다른 작업 브랜치는 필요 없다. `--force`는 이 후보 폴더의 생성본을 재현한다. 편집한 후보를 보존하려면 먼저 새 버전으로 복사한다.
- 기존 후처리 검사에는 Python + Pillow + NumPy도 필요하다. Codex에 묶인 Python을 우선 사용하고, 다른 PC에서는 해당 패키지가 있는 Python 실행 파일을 환경 변수 `PYTHON`으로 지정할 수 있다.
- 검증: 4명 × 15프레임(4상태 + 11타이밍 구간), 원본 정지 픽셀 동일, 5색·이진 알파·공통 경계색·손/발/소품 고정·후처리 전후 동일성 통과. 별도 Godot 4.6 프로젝트에서 `.tres` 4개를 실제 로드했고, 11타이밍 구간의 **9초 루프**가 보존됨을 확인했다([Godot 결과](../art/mockups/f25-staff-motion-v1/godot-validation.json)).
- 프레임 시트와 HTML 구문은 확인했다. 자동 브라우저의 로컬 접근 제한으로 실제 속도 재생의 시각 검증은 완료하지 못했다. 리뷰 HTML과 GIF에서 사용자가 움직임을 확인할 수 있으며, 자연스러움이나 외형이 승인됐다는 뜻은 아니다.

## 영상의 8개 도구

| 도구 | 실제 종류 / 라이선스 | 우리 게임에서의 용도와 제한 |
|---|---|---|
| [2dimg2motion](https://github.com/WU-HAOTIAN34/2dimg2motion) | Codex·Claude 스킬, MIT | 새 동작의 전신 키포즈를 이미지 생성으로 준비할 때 유용. 정체성·손의 방향·접지를 검사한다. 기본 14프레임과 큰 캔버스를 그대로 사용하지 않고 32×48 및 실제 필요한 포즈 수를 명시해야 한다. |
| [sprite-gen](https://github.com/aldegad/sprite-gen) | 스킬 + Python CLI, Apache-2.0 | 생성 이미지/영상에서 프레임 추출·배경 제거·루프 정리. 영상 경로에는 추가 도구가 필요하다. 외부 API를 선택하면 별도 인증·비용이 생긴다. 우리 팔레트와 Godot 포맷으로 후처리해야 한다. |
| [PixelFX](https://github.com/patch-gg/pixelfx) | 스킬 + Node 효과 라이브러리, MIT | 244개 코드 기반 효과. 수확·귀환·조제 완료 효과에 후보. 기본 효과의 glow, 흰색, 부분 알파가 우리 규칙과 충돌할 수 있어 그대로 붙이지 않는다. Patch Pixel 폰트는 라이브러리 MIT 범위 밖이다. |
| [PixelOE](https://github.com/KohakuBlueleaf/PixelOE) | 이미지 변환 라이브러리, Apache-2.0 | 고해상도 원화의 윤곽을 보강하며 픽셀화하는 용도. 동작 생성 도구가 아니다. torch 등 의존성이 크고 승인된 재질별 램프를 자동 보장하지 않는다. 기존 네이티브 그림 일괄 변환에는 부적합. |
| [Agent Sprite Forge](https://github.com/0x0funky/agent-sprite-forge) | 스킬 + Python 파이프라인, MIT | 캐릭터 기준 이미지에서 여러 동작 생성·추출·엔진 내보내기. 생성 경로에 따라 모델/API 및 ffmpeg가 필요하다. 기본 최대32색을 우리 5색 규칙으로 조정해야 한다. |
| [Codixel](https://github.com/mankidev/codixel) | 스킬 + Node 픽셀/리깅 코어, MIT | 참고 그림을 부위로 나눠 코드로 움직이거나 프레임을 패킹할 때 유용. 기본 quantize·dither·selective outline은 우리 규칙과 다르다. edgeCheck의 잎끝·눈·1px 선 경고는 자동 삭제 근거가 아니다. |
| [Pixelbolt](https://github.com/skulitom/Pixelbolt) | 스킬 + CLI + 선택적 MCP, MIT | **이번에 사용.** PNG 무손실 가져오기, 텍스트 레시피·프레임 단위 수정, 색·크기 검사, Godot `.tres` 출력. 도구가 제안하는 일반 아트 스타일보다 이 저장소의 규칙을 우선한다. |
| [Sprite-Sheet-Diffusion](https://github.com/chenganhsieh/Sprite-Sheet-Diffusion) | 로컬 생성 모델 연구 코드 | 캐릭터 그림과 포즈 시퀀스로 재생성. 사전학습 가중치·CUDA 추론 환경이 필요하다. README의 MIT/학습 자료 CC0 표기 외 별도 배포 조건은 추가 확인 대상이다. 이번 즉시 제작용으로 설치하지 않았다. |

추천 순서: **지금은 Pixelbolt**, 새 전신 행동이 필요할 때 **2dimg2motion**, 짧은 효과를 추가할 때 **PixelFX**. 셋 모두 결과를 기존 팔레트·외곽선·접지 검사와 시각 검토에 통과시켜야 한다.

## 사용하는 방법

Codex에는 이렇게 요청하면 된다.

> `$pixelbolt-pixel-art`로 이 프로젝트의 AGENTS.md를 읽고, 지정한 약초 아이콘을 32×32·기존 5색·공통 외곽선으로 수정해줘. 원본은 보존하고 수정 전후와 변경 픽셀을 보여줘. 프로젝트에 설치된 0.11.0을 사용해줘.

> `$pixelbolt-pixel-art`로 직원 캐릭터의 기존 모습과 손·발 위치를 유지하고 대기 움직임을 만들어줘. 32×48, 발 y46, 공통 3배로 정지/움직임을 비교하고 Godot SpriteFrames까지 내보내줘.

새 PC에서 프로젝트 루트의 PowerShell로 1회 설치:

```powershell
Push-Location tools/pixelbolt
npm ci --ignore-scripts --no-audit --no-fund
Pop-Location
```

기존 약초 그림을 수정 가능한 레시피로 가져오는 예:

```powershell
./tools/run_pixelbolt.ps1 import assets/ui_pixel_v2/icons/herb.png --name herb --out art/mockups/herb-edit-v1.json
./tools/run_pixelbolt.ps1 validate art/mockups/herb-edit-v1.json
./tools/run_pixelbolt.ps1 inspect art/mockups/herb-edit-v1.json --out art/mockups/herb-edit-review-v1.png --native --diagnostics
./tools/run_pixelbolt.ps1 render art/mockups/herb-edit-v1.json --out art/mockups/herb-edit-export-v1
```

이미 존재하는 출력 폴더와 충돌하면 다음 버전 폴더를 사용한다. 런타임 PNG를 임의로 덮어쓰지 않는다. 수정은 레시피의 해당 프레임이나 Pixelbolt `patch`를 사용하고, 단일 프레임 수정에는 `scope: "frame"`을 지정한다. 일반적인 `outline`·`cleanup` 결과도 눈·잎끝·기존 접합을 훼손하지 않는지 살핀다.

Godot용 결과는 출력된 PNG 시트와 `.tres`를 함께 사용한다. `AnimatedSprite2D.sprite_frames`에 `.tres`를 연결하고 Nearest 필터와 정수 배율을 유지한다. 실제 게임 연결은 해당 캐릭터의 채택 여부와 화면 배치 결정을 따른다.

## 신규 캐릭터 기획 확인

찾은 것은 F25 직원 4명이다. 원 기획은 [성장·단골·꾸미기 기획안](성장과-단골-꾸미기-기획안.md), 시안은 `feature/f25-staff-concept`의 `art/mockups/f25-staff-concept-v2/`에 있다.

| 역할 | 컨셉 | 원 기획의 행동 후보 |
|---|---|---|
| 판매 보조 | 올림머리·머리띠·앞치마 점원 | 가벼운 인사, 손 흔들기 |
| 재배 보조 | 밀짚모자·멜빵 작업복·물뿌리개 | 물 주기 |
| 조제 보조 | 고글·가운·플라스크 | 흔들기, 붓기 |
| 원정 길잡이 | 후드·여행 망토·등불 지팡이 | 등불 들기, 출발·귀환 |

마지막 결정은 **작업실 직원 배치 없음(D안), 관리 화면 역할 아이콘 유지**다. v2 외형은 미승인이다. 판매 보조 얼굴·길잡이 옷·4명의 신발은 사용자가 직접 고치기로 한 메모가 있다. 이번 움직임 실험은 이 부분을 새로 디자인하지 않으며, 이를 캐릭터 디자인 완성으로 보고하지 않는다.
