# 관리 통계와 헤더 정리 적용 결과

2026년 10월 13일 · **구현·누적 데이터·UI 격리 검사·파일 미리보기 검수 완료 / 실제 Windows 입력 미검증**

관리 제목줄의 `결과`를 `통계` 버튼으로 바꾸고, 통계 페이지를 누적 숫자 중심으로 정리했다. 상세 장부, 새 집계 시작, 재료·발견 보고 UI를 제거했다. 기존 먹색·세이지 팔레트·폰트와 관리 열기/숨기기·이동·포커스, 회색 창 초기화 방지 처리는 유지한다.

사용자 추가 요청 반영 완료: 통계에는16px 그래프 SVG, 닫기에는 같은 선 두께의16px X SVG를 추가했다. 두 버튼의80×34px 클릭 영역을 유지하고 아이콘과 글자 사이6px, 좌우 최소12px 여백으로 묶음을 가운데 정렬한다. [최종 버튼 검사](../../.verification/statistics-header-icons-20261013.log) 475개 PASS: 두 리소스 정상 로드, 내용 경계와 중심, 열기·숨기기·같은 창 재열기 및 통계·스크롤·모델·RNG 보존을 확인했다. 아래9개 미리보기는 아이콘 추가 전 통계/헤더 정리의 증빙이다.

| 통계 행 | 표시 기준 |
| --- | --- |
| 플레이 시간 | 실제 진행 누적 시간 |
| 순영업수입 | 누적 매출 − 재료비 − 원정 출발비 |

`Status.lifetime_summary(state)`는 저장된 `progression.clock`과 누적 카운터를 읽기만 한다. 플레이 시간은 앱이 실제 `_advance_game`으로 진행한 시간이며, 휴업·재고 가득·모드 전환에서도 누적된다. 앱 종료 중 벽시계 시간은 더하지 않는다. clock이 없던 v1~4 저장은 기존 불러오기 규칙에 따라0부터 기록한다. 새 저장 필드를 추가하지 않았다.

누적 통계는 기존 기간 집계의 baseline과 무관하다. 기존 `report_summary`, 기간 초기화 모델과 저장 형식은 보존했다. 순영업수입은 기존 정의에 따라 설비 강화·레시피·지역 열기·직원 등의 직접 투자 비용을 제외한다. 보유 골드와 순영업수입은 의미가 다르다. 금액은 천 단위 쉼표와 코인으로 표시하며, 순수입의 양수에는 `+`, 음수에는 `−`를 붙인다. 지출도 `−`로 표시한다.

상단 골드·명성은 각각 아이콘24px, 이름14px(`골드`·`명성`), 값18px로 구분한다. 값에는 숫자만 표시하고, 공간이 부족한 긴 값에는 기존 축약 규칙을 적용하며 전체 숫자는 툴팁에 보존한다. 기존520px 폭·목록48px 아이콘·본문/탭/버튼16px와 작업 게이지·구매 대상 고정·스크롤을 유지한다.

[lifetime-report-final-20261013.log](../../.verification/lifetime-report-final-20261013.log)는 **57개 검사·실패0개**다. 휴업/보관 가득·다섯 모드의 실제 시간 증가, 초·분·시간 경계와26시간 표시, 누적 비용/활동량, 기존 기간 초기화와의 독립, 직접 투자 비용 제외, 양수·0·음수·큰 금액, 메모리 JSON 저장 복원과 구버전 fallback, 통계 조회의 경제·저장 데이터·RNG 불변이 통과했다. 실제 플레이어 저장 파일은 사용하지 않았다.
