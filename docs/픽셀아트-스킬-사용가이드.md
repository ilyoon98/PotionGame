# 픽셀아트 스킬 사용 가이드

최신 결과: [직원 실제 속도 검토와 수정](직원-애니메이션-F25-실속도-검토.md). 별도 Godot 창에서 기존 캐릭터와 1배 재생을 확인하고 직원별 호흡·깜빡임 타이밍을 수정했다. [함께 움직이는 비교](../art/mockups/f25-staff-playback-v2/review.html).

확인일: 2026-11-06. [영상 1편](https://www.youtube.com/watch?v=_U5wuMhZXI0)·[2편](https://www.youtube.com/watch?v=ZN019l8wGBg)의 전체 도구 비교는 [조사 문서](픽셀아트-스킬-조사와-적용.md)에 있다. 이 문서는 지금 무엇을 요청하면 되는지와 애니메이션 후보 두 가지의 사용법을 정리한다.

**현재 직원 작업은 비교 결과를 보고 선호를 알려 주면 된다.** 기준 그림과 머리·가슴·다리 정렬 요청은 이미 제공됐다. 추가 설치나 좌표 입력, 터미널 명령, JSON 작성은 필요 없다. 도구 선택·위치 정렬·연결 픽셀 보정·프레임 제작·검사는 에이전트가 맡는다. 설치된 스킬은 `pixelbolt-pixel-art`, 프로젝트 제작 엔진은 Pixelbolt 0.11.0이며 직원 정렬과 작은 대기 움직임 제작에 사용 중이다.

| 사용자 입력과 현재 상태 | 에이전트가 처리할 것 |
|---|---|
| 기준 그림은 이미 지정됐다. 이후 직접 고친 원본으로 바꾸고 싶을 때만 새 파일을 지정하면 된다. | 원본을 보존하고 같은 캔버스·발 위치·표시 배율로 비교한다. |
| 머리·가슴·다리를 같은 기준으로 정렬하라는 요청이 이미 있다. 좌표와 프레임 수를 따로 정할 필요는 없다. | 원래 외형·색·역할을 유지하며 부위 위치를 옮기고 목·허리·다리의 연결 픽셀을 보정한다. 정렬한 그림을 기준으로 움직임과 타이밍을 만든다. |
| 현재 필요한 것은 비교 결과에 대한 선호 피드백이다. 예: “두 번째 직원만 커 보여”, “호흡을 더 약하게”, “이 얼굴 인상은 유지”. | 차이를 수정하고 크기·색·투명도·외곽선·접점을 검사한다. 프레임 시트와 실제 속도 재생의 확인 결과를 구분해 보고한다. |

현재 요청을 풀어 쓴 예이며, 다시 입력할 필요는 없다:

> `$pixelbolt-pixel-art`로 현재 직원 4명의 머리·가슴·다리를 같은 기준에 정렬해줘. 32×48 원본과 발 y=46을 유지하고 모두 3배로 비교해줘. 모자 높이에 맞추려고 몸을 늘리지 말고, 원래 외형 콘셉트·색·역할을 유지해줘. 정렬에 필요한 위치 이동과 목·허리·다리 연결 픽셀 보정은 진행해줘. 정렬 후의 손·발 접점을 기준으로 작은 대기 움직임을 만들고 정지/움직임을 함께 보여줘. 프로젝트의 Pixelbolt 0.11.0을 사용해줘.

F25 직원의 기존 결정은 작업실 배치 없음, 관리 화면 역할 아이콘 유지다. 현재 정렬·움직임 제작은 별도 후보이며 외형 승인이나 게임 연결 완료를 뜻하지 않는다. 얼굴·옷·신발의 원래 외형 콘셉트와 색은 유지하되, 이번 명시적 정렬 요청에 필요한 위치 이동과 목·허리·다리 연결 픽셀 보정은 진행한다. 전혀 다른 얼굴이나 의상으로 디자인을 바꾸는 작업은 이번 요청 범위 밖이다.

**새로운 전신 행동이 필요할 때: 2dimg2motion**

한 장의 기준 그림에서 인사·걷기·물 주기처럼 자세가 달라지는 동작을 만드는 후보다. 공식 스킬은 내장 `image_gen`으로 전신 포즈를 생성하고, 로컬 스크립트는 배경 정리·프레임 분리·시트 포장에 사용하도록 구분한다. 팔만 잘라 회전시켜 전신 동작을 만드는 방식은 이 스킬의 작업법이 아니다. [공식 스킬](https://github.com/WU-HAOTIAN34/2dimg2motion/blob/main/SKILL.md)

사용자는 기준 그림과 행동만 지정하면 된다. 에이전트는 얼굴·옷·소품을 유지하는 기준을 잡고, 먼저 주요 포즈를 비교한 뒤 연결 프레임을 만든다. 우리 프로젝트에서는 기본 14프레임·300~400px 기준을 그대로 적용하지 않는다. 최종 32×48과 발 기준선을 지키고, 프레임마다 몸을 따로 축소하거나 확대하지 않는다. 큰 동작이 캔버스에 들어오지 않으면 동작 범위를 먼저 조정한다. 생성 원본과 실패 비교도 별도 버전 폴더에 보존한다.

> 재배 보조의 현재 그림으로 물 주기 동작을 만들고 싶어. 물뿌리개를 든 손이 바뀌지 않게 하고, 서 있는 모습 → 기울이기 → 원래 자세로 돌아오기를 비교해줘. 2dimg2motion 도입이 적합한지 확인하고 우리 픽셀 규칙에 맞는 후보로 진행해줘.

코드는 MIT이며 Python·Pillow와 이미지 생성 기능이 필요하다. 공식 안내에 Codex용 PowerShell 설치 예제가 있다. 내장 이미지 생성 경로에는 별도의 외부 API 키를 설정하는 단계가 없지만, **무료 무제한 이미지 생성 도구라는 뜻은 아니다.** 사용하는 계정의 이미지 생성 이용 조건을 따르며, 외부 API 경로를 선택하면 해당 서비스의 인증과 요금 확인이 따로 필요하다. 이번 조사에서는 설치하거나 실행하지 않았다. [공식 설치·의존성 안내](https://github.com/WU-HAOTIAN34/2dimg2motion#quick-start)

**기존 그림의 부분 움직임을 연구할 때: Codixel**

기준 그림을 부위로 나누고 관절이나 긴 곡선을 따라 움직이는 코드 중심 후보다. 망토 끝·긴 머리·꼬리처럼 제한된 부분을 다룰 때 검토할 만하다. 사용자에게 관절 좌표를 요구하지 않고, 에이전트가 부위별 마스크와 연결점을 만들어 움직이기 전후를 보여 준다. 32×48의 작은 그림은 회전만으로도 선이 끊어지거나 굵어질 수 있어 현재 직원 작업의 기본 도구는 Pixelbolt로 유지한다. 이 용도 판단은 프로젝트 규격을 고려한 추천이다. [공식 작업법](https://github.com/mankidev/codixel/blob/main/SKILL.md)

> 이 캐릭터의 망토 끝만 작게 흔들리는 후보를 비교해줘. 몸·손·발과 기존 색을 유지하고, Codixel의 부위 분리 방식이 도움이 되는지 먼저 판단해줘. 움직임 때문에 외곽선이 끊기거나 두꺼워지면 그대로 결과로 내지 말고 수정해줘.

Codixel은 MIT 스킬과 로컬 Node 코어를 제공한다. 코어 자체의 PNG 입출력·리깅·GIF 제작에는 외부 이미지 API 키가 필요 없다. 별도의 원화 생성 서비스를 사용한다면 그 서비스 비용은 따로다. 공식 설치 안내는 Claude Code 기준이며, 이번 조사에서 Codex 설치·실행까지 확인한 것은 아니다. [공식 저장소](https://github.com/mankidev/codixel), [코어 구현](https://github.com/mankidev/codixel/blob/main/core/pixel.js)

**우리 그림에 적용할 때 에이전트가 지킬 기준**

- 캐릭터 32×48, 일반 아이콘 32×32. 직원은 발 y=46과 같은 배치 기준을 쓰고, 비교 화면은 모두 최근접 3배로 표시한다. 모자·장식 높이 때문에 각 캐릭터의 몸을 다르게 확대하지 않는다.
- 승인된 공통 24색 안에서 물체별 외곽선 포함 최대 5색, 알파는 0 또는 255, 경계는 1픽셀 `#241C32`로 검사한다. 디더링·그라데이션·부드러운 보간은 사용하지 않는다.
- 재질 마스크와 승인 램프로 색을 정리한다. 모든 색을 한꺼번에 가장 가까운 RGB색으로 바꾸는 양자화는 사용하지 않는다.
- Codixel의 자동 윤곽 정리는 잎끝·눈·관절을 지울 수 있어 제안을 확인한 뒤 선택한다. `P.outline`은 캔버스를 가로·세로 2픽셀 키우고 그림을 1픽셀 옮기므로, 외곽선이 있는 원본에 중복 적용하지 않는다. 두 색 외곽선·림 라이트도 우리 공통 경계색 규칙으로 대체한다. [공식 코어 사용 설명](https://github.com/mankidev/codixel/blob/main/SKILL.md)
- 검사 통과와 자연스러운 움직임은 별개다. 원본·변경 픽셀·프레임 시트·실제 속도 재생을 함께 검토하는 것이 작업 기준이다. 직원 v2는 별도 Godot 1배 재생 화면과 라이브 시간 기록으로 확인했다. 프레임 검사나 파일 내보내기 성공만을 재생 확인으로 보고하지 않는다. 선택한 후보에 맞춰 Godot용 PNG와 `SpriteFrames`를 내보낸다.

Pixelbolt의 로컬 제작 엔진에는 별도의 이미지 생성 API 키가 필요 없다. Codex 사용 자체의 이용 조건과는 별개이며, 이 프로젝트에서는 자동으로 `latest`를 설치하지 않고 고정된 0.11.0을 사용한다. 추가 두 후보는 조사만 마쳤고 설치하지 않았다.
