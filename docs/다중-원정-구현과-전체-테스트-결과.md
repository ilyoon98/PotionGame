자동 제조는 새 레시피의 첫 성공 제조를 먼저 시도하고 이후 물약 계열을 순환하면서 만들 수 있는 상위 레시피를 선택한다. 부족하면 기존 특수/기본 물약으로 복귀한다. 실패한 첫 시도는 성공 제조까지 재시도한다. 예약 재료·진행률·성공 판정은 강화와 저장으로 다시 지불하거나 다시 추첨하지 않는다.

## 원정 결제·보관·저장

개방비와 회차 출발비를 분리했다. 출발비는 지역 순서대로 8 / 12 / 20 / 30 / 45 / 60 / 80 / 100 G이며 초기 데이터 금액을 변경하지 않았다. 자동 구매 보호 예비금 30 G를 남긴다. 조사 미완료 지역, 오래 대기한 지역, 고정 지역 순서로 판단하며 미완료 출발비가 부족하면 완료 지역의 반복 출발에 그 예산도 남긴다.

같은 틱의 모든 귀환과 보상 입고를 처리한 뒤 출발 후보를 순차 결제한다. 각 회차는 ID·지불 여부·실제 지불 금액·지역 키·진행 시간·고정 기간·고정 보상을 저장한다. 원정 단축 투자와 직원 훈련은 다음 회차에만 적용한다. 조사 중에는 보관 가득 상태에서도 발견을 기록하고, 보상은 종류별 미입고 수량으로 보존한다. 화분 구매 초기 재료도 공간이 없으면 대기 수량에 보존한다.

완료 지역은 보상 중 하나의 보유+미입고가 한도의 50% 이하이고 모든 보상에 공간이 있을 때 반복한다. 그 외에는 재료 충분/보관 공간 대기. 소비와 입고 여건이 바뀌면 자동 재개한다. 원정 보상은 화분을 사기 전에도 보관된다.

버전 1~7 읽기를 지원한다. 기존 버전 1~6의 골드·재고·재료·제조 예약·고용·손님·진행은 보존한다. 진행 중인 옛 숲 회차는 기존 시간과 별잎 2개로 무료 완료한 뒤 다음 회차부터 새 비용·보상을 적용한다. 과거 출발비를 소급하지 않는다. 기존 별잎 입고 대기는 한 번만 이전한다. 신규 지역·직원·설비를 무료 소유로 만들지 않는다. 버전 7은 이전 확장 개발 중간 저장의 호환용이다.

결과 화면에는 매출, 자동 재료비, 원정 출발비, 순영업수입, 별도 직접 투자, 지역별 귀환·조사·발견·재료 보상을 표시한다. 결과를 반복 열어도 잔액이나 보상이 바뀌지 않는다.

## 화면 증거와 Computer Use 상태

아래 파일은 **Godot 렌더 자동 검사 산출물**이다. 실제 Windows 클릭 검사의 증거로 쓰지 않는다.

- [다중 원정 관리](../.verification/parallel-expedition-management.png), [작업실 지도/실제 진행 수](../.verification/parallel-expedition-map.png).
- [미니 작업실 밤·비](../.verification/companion/night-rain.png)와 같은 폴더의 day-clear/night-clear/day-cloud/day-rain.
- [관리 원정 페이지](../.verification/companion/management-2.png), [정보 최소 화면](../.verification/compact-progress.png).

Computer Use 스킬의 `node_repl + @oai/sky` 초기화, 앱/창 목록에서 `달그늘 TEST new` 선택, 상태 캡처까지 실제 수행했다. 반환 화면이 Windows 잠금 화면이었고 창 활성화도 실패했다. 필수 지침 **“If the Windows desktop is locked, stop immediately”**에 따라 입력 조작을 중단하고 사용자에게 잠금 해제를 요청했다. 잠금 화면 이미지는 테스트 증거로 저장하지 않았다.

실제 구매 클릭·탭 전환·다중 원정 대표 상태·비용 대기 복구·날씨 하이라이트·지도 클릭·드래그·모드 복귀·뒤 창 OS 클릭 전달·UI 종료와 재실행·결과 재열기는 **Computer Use 미실행**이다. 자동 신호 호출·렌더·native 수명 검사는 이 목록을 대체하지 않는다. `tools/cu_expansion_fixture.gd`에 new/buy/low/parallel/full/late/legacy/resume 격리 fixture를 준비했고 테스트 창은 정리했다. 잠금 해제 후 동일 명세로 실제 입력 검사를 이어가야 한다.
