# 자동 실행 콘솔 잔류 수정 — 완료

2026-10-26 사용자 부팅 화면 제보를 반영했다.

## 원인과 수정

현재 사용자의 시작 작업은 이미 PowerShell `-WindowStyle Hidden`과 Godot 창 버전을 사용했다. 실제 부팅 진단은 `started`/시작 확인 완료였고, 실행 중인 게임의 부모 PID는 종료된 로그인 도우미였다. 창 버전도 부모 콘솔에 연결을 시도하는 [Godot4.6 실행 코드](https://github.com/godotengine/godot/blob/4.6-stable/platform/windows/os_windows.cpp#L150-L170) 때문에 단순 숨김만으로 콘솔 연결을 막지 못했다.

`native/windows/ResumeLogin.ps1`에서 새 게임을 생성하기 직전에 **로그인 도우미 자신의 콘솔만 FreeConsole로 분리**한다. 이미 실행 중인 게임·콘솔·관리 창을 조작하지 않는다. 게임 창은 기존대로 표시하고, 시작 인자·중복 실행 검사·시작 확인·실패 기록은 유지한다. 일반 자동 실행의 결과는 기존 단일 진단 JSON에 남기며, dry-run/캡처된 호출은 계속 표준 출력으로 결과를 받는다. 게임에 배포되는 `scripts/windows_startup.gd`의 내장 원문도 동기화했다.

## 검증

- 시작 도우미30개 dry-run과5개 PowerShell 파일 전송 검사 통과. 시작 설정을 실제로 등록하거나 플레이 저장을 읽지 않는 격리 검사다.
- 진단·오류·잘못된 JSON·자식 조기 종료·기록 실패 검사 통과.
- 별도 네이티브 가짜 프로그램으로 부모 콘솔 연결을 재현했다. 수정 전에는 연결 성공, 수정 후에는 연결 실패/콘솔 핸들0이었다. 두 경우 모두 도우미 종료 후 자식이 계속 살아 있고 시작 확인과 캡처된 JSON 출력도 유지됐다. 가짜 프로그램은 자동 종료하며 실제 게임을 실행하지 않는다.
- 근거: `.verification/startup-console-20261026/startup.log`, `diagnostics.log`, `console-probe.log`와 `native-4cd0c686935f42d28d857c3449e0b2e2/`.

## 사용자 PC 반영

`tools/install_login_console_fix.ps1`로 기존 활성 시작 작업의 현재 사용자 소유권과 정확한 도우미 경로를 확인한 뒤, 설치 파일을 백업하고 교체했다. 기존 작업 XML·활성 설정·세션 메타데이터는 변경하지 않았다. 설치 파일이 수정 원문과 같음을 확인했다. 원래 게임 PID38160은 계속 살아 있었으며 재시작·종료·입력·플레이 저장 변경은 하지 않았다.

설치 근거는 `.verification/startup-console-20261026/installed-repair.json`과 백업 파일이다. 실제 재부팅/로그오프 확인은 수행하지 않았다. 이미 실행 중인 게임의 콘솔 연결을 소급해서 바꾸지는 않으며, 다음 자동 실행부터 적용된다. 현재 검은 창은 게임의 저장 후 종료 버튼으로 정상 종료한 다음 정리한다.
