# 특별 발견 런타임 검증 결과

2026년 10월 13일 · **발견·저장·구매·자동 제작 핵심 구현 및 격리 검사 완료 / 수치는 개발 검증용 초기값 / 실제 Windows 플레이 미검증**

일반32종의 원본 `content_expansion.json`과 조사·다음 지역 조건을 유지하고, 특별4종을 `Rare.ROWS`와 `Content.RARE_ROWS`로 별도 등록했다. 기존 `lookup("potions")`, 제조/재고 종류와 판매에 합류하며 승인된12개 PNG 경로를 연결한다. 아트 파일과 공유 기획 명세는 변경하지 않았다.

| --- | --- | --- | --- |
| 숲숨결 물약 | 이슬풀2 + 별잎1 + 달빛 버섯1 | 900 / 80 | 1.9 / 90% |

| 성운 증류액 | 별씨2 + 달꽃1 + 수정초1 | 26,000 / 280 | 3.4 / 80% |

가격·판매가·제조 배율·성공률과 **3% 발견 / 30번째 유효 완료 보장**은 조정 가능한 개발 초기값이다. 사용자 확정 밸런스나 실제 수집 시간의 보장이 아니다. 실제 제조 시간·성공률·판매대금에는 기존 설비·직원·계열·환경 효과를 적용한다.

`rare_recipes.gd`는 Content를 참조하지 않는 독립 데이터·상태 모듈이다. `state(id,p)`의 미발견/발견/구매 상태를 공유하며, `recipe_info`와 `preview`는 미발견 이름·전용 그림·배합·가격을 숨긴다. 이 조회와 `production_candidates`, `production_preview`, `departure_mode`는 재료·커서·회차·두 난수를 변경하지 않는다.

발견 결과는 실제 유료 출발 때 한 번 정하고 mode·대상·결과·시도 번호와 함께 회차에 저장한다. 실제 완료 때만 발견을 공개하고, 실패도 유효 완료에서만 기록한다. 발견은 구매권이나 무료 재료를 주지 않는다. 발견 이후 골드로 한 번 구매하면 기존 보유 기록과 첫 실제 제조 대기에 합류한다. 재구매·중복 발견과 새 공급원/씨앗 지급은 없다.

일반 보관 대기인 미발견 지역은 기존 비용·시간의 특별 탐색을 진행한다. 이 회차는 일반 재료를 지급하지 않으며 기존 미입고 재료를 삭제하지 않는다. 예비금30과 먼저 필요한 미완료 일반 원정 비용을 보호한다. 특별 탐색은 일반 지역 조사 횟수와32종 해금 조건을 채우지 않는다. 전체 완료 원정 통계에는 포함하고, 발견 뒤 특별 탐색 반복은 멈춘다. 재료가 필요해지면 기존 일반 원정을 재개한다.

기존 첫 제조 우선은 유지한다. 이후 만들 수 있는 희귀 그룹과 일반 그룹을 번갈아 선택하고, 희귀 그룹의4종과 일반 계열은 각자 순환한다. 일반 그룹은 기존 계열 최상위·재료 부족 시 대체와 기본/기존 물약 fallback을 유지한다. 이 교대는 기아 방지용 초기 정책이며 수동 선택이나 병렬 솥을 추가하지 않는다. 배합에 기본 약초가 없는 특별품은 해당 재료가 있으면 약초0개에서도 시작하고, 한 배치의 재료는 정확히 한 번 예약한다.

저장 버전9는 이전1~8을 지원한다. 발견/실패와 별도 `rare_seed`를 저장해 기존 생산·손님·일반 보상 `seed_value`의 호출 순서를 보존한다. 이전 저장의 조사 횟수를 발견/실패로 소급하지 않고, 이미 출발한 회차는 저장된 일반 보상을 그대로 마친다. 새 출발부터 검사한다. 미발견 보유/제조/병과 잘못된 모드·시도·난수·유료 회차를 거부하며, 실패한 불러오기는 대상 상태를 변경하지 않는다.
