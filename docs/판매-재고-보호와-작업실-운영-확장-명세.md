# 판매 재고 보호와 작업실 운영 확장 제작 명세

2026-10-20 · **F20 기획 확정 · 개발 반영 요청 · 구현·검수 전**

판매용 물약을 유지하는 자동 운영을 먼저 만들고, 후반 골드로 작업실을 확장하면 일반 판매와 납품을 동시에 제작한다. 확장 구매에는 납품 전용 보조 조제대의 기본 기능을 포함한다. 확장비만 지출하고 기능을 다시 구매하는 단계는 두지 않는다.

사용자는24시간 플레이 후 기존 구매를 모두 마치고270만 골드가 남았으며, 납품 시작 이후 판매용 물약 재고가 계속0개라고 보고했다. 이는 단일 실제 플레이 피드백이다. 현재 저장을 읽은 측정 결과나 분당 순수입으로 환산하지 않는다. 기존 코드의 납품은 판매 재고를 직접 꺼내지 않고 솥·재료를 공유한다. 고갈 원인은 솥 점유·재료 경쟁·판매 속도를 분리해 검증한다.

## F20-A 판매 재고 자동 보호

### 보호 진입과 해제

판매 가능한 전체 완성 물약 수를 `S`, 실제 보관 한도를 `C`로 정의한다. 납품 중인 병·예약 재료·실패 예정 배치·제작 중인 병은 판매 재고에 포함하지 않는다.

- 보호 진입선 `L = min(C, max(1, min(6, ceil(C × 0.20))))`.
- 보호 해제선 `H = min(C, max(L + 1, min(12, ceil(C × 0.40))))`.
- `S <= L`이면 보호 진입, `S >= H`이면 해제한다. 중간에서는 기존 모드를 유지한다.
- 수치는 개발 검증 초기값이다. 예를 들어 C=12이면 L=3/H=5, C=18이면 L=4/H=8, C=128이면 L=6/H=12다. 큰 창고의40%를 채우기 위해 납품이 지나치게 오래 멈추지 않도록 상한을 둔다.
- 창고 강화 때 기준만 재계산한다. 진행 중 제작·예약·성공 판정은 건드리지 않는다. C=1인 가짜 경계에서는 예외로 L=0/H=1을 사용해 진입과 해제가 겹치지 않게 한다. C<=0은 유효한 보관 한도로 취급하지 않는다.

보호 중에는 새 납품 제작을 시작하지 않고 다음 실제 솥 기회를 일반 판매에 사용한다. 재고가 회복되면 별도 버튼 없이 납품을 재개한다. 이미 시작한 납품은 정상 완료하며 재료 반환·취소·성공 재추첨·타이머 초기화가 없다. 납품 회차·합의·거래 등급·정산은 유지한다.

확장 전에는 건강한 재고일 때 기존 일반4배치:납품1배치 시작 규칙을 유지하되 보호 조건이 우선한다. 납품을 건너뛴 몫을 빚처럼 쌓거나, 회복 후 납품을 연속 몰아 실행하지 않는다. 회복 후에도 다음 일반4배치 규칙으로 돌아간다. 판매 창고가 가득 찼을 때의 기존 납품 활용은 보호 해제 상태에서 가능하다.

### 공유 재료 보호

일반 판매를 위한 다음 제작 후보를 부작용 없이 구하고 해당1배치 재료를 먼저 확보한다. 후보 조회로 RNG·커서·재고를 소비하지 않는다. 메인 솥이 쉬고 있고 만들 수 있는 일반 물약이 있으면 일반 제작 예약이 납품보다 먼저다.

납품의 실제 병수는 기존 일괄 조제 상한·남은 주문량·일반 제작 예비량을 뺀 재료 범위의 최솟값이다. 예비 재료를 실제로 두 번 차감하지 않는다.1병도 만들 수 없으면 `판매 재료 확보 중`으로 대기한다. 예비량은 다음 배치 시작 판단에서 다시 계산하고 별도 재료 창고나 새 소비성 재화로 만들지 않는다. 정상 재고에서도 이1배치 재료 보호를 적용한다.

일반 제작 후보가 없는 경우에는 재료가 있는 것처럼 가상 예약하지 않는다. 판매 재고도 낮으면 보호 상태로 실제 공급을 기다린다. 재고가 충분하고 일반 후보가 없는 경우에는 남은 실제 재료로 납품할 수 있다. 특정 재료 부족 때문에 다른 일반 물약까지 전부 멈추지 않도록 기존 일반 후보/기본 물약 대체 정책을 보존한다.

### 고갈 판정과 한계

잠깐0개였다가 바로 판매되는 현상만으로 실패 판정하지 않는다. 재고0 누적 시간, 손님이 재고를 기다린 시간, 일반 판매 병수/매출, 평균 판매 재고, 일반/납품 재료 대기, 납품 병수/정산을 함께 비교한다.

같은 상태에서 납품을 끈 경우에도 재고를 복구하지 못하면 일반 생산력 자체의 부족이다. 그 경우를 납품 보호 성공으로 보고하지 말고 별도 원인으로 남긴다. 보호 로직만으로 생산 능력이 늘었다고 주장하지 않는다. 보호 때문에 특정 거래처가 영구 제외되는지와, 공급이 충분해진 뒤 실제 납품이 재개되는지도 확인한다.

## F20-B 작업실 운영 확장

### 해금과 최초 구매

아래 조건을 모두 충족하면 `가구·직원`의 후반 투자에 작업실 운영 확장을 표시한다.

1. F19의 기존 성장 완료 조건 충족.
2. 보급 지원3단계와 납품 일괄 조제3단계 보유.
3. 기존 거래처 중 최고 거래4등급 도달.

특별 레시피4종·흥정 훈련3단계 구매는 필수 조건이 아니다. 미래 흥정 기회0인 사용자가 해금에서 막히면 안 된다. 원정 최초 수주 해금은 기존대로 유지한다.

확장을 구매하면 보조 조제대 기본형이 포함되며 바로 자동 운영한다. 보조 설비를 쓰기 위한 재구매·직원 고용·켜기 버튼은 없다. 골드와 직접 투자 실적을 한 번 차감/기록하며, 잔고 부족·조건 부족·중복·오래 열린 버튼은 원자적으로 거부한다.

### 두 생산 설비의 역할

| 상태 | 메인 솥 | 보조 조제대 |
| --- | --- | --- |
| 확장 전 | 일반 판매·건강한 재고에서 기존 납품 배분 | 없음 |
| 확장 후 | 일반 판매만 제작 | 납품만 제작 |
| 판매 재고 보호 중 | 일반 판매 우선 복구 | 진행 중 배치는 완료, 다음 납품 시작 대기 |
| 일반 재료 부족 | 가능한 다른 일반 후보 또는 실제 공급 대기 | 판매 예비량을 뺀 실제 재료와 보호 상태에 따라 대기 |

확장 후에는 납품을 위한 메인 솥의4:1 빈자리를 두지 않는다. 이 부분은 F18/F19의 ‘한 솥4:1’ 규칙을 **확장 구매 후에만** 대체하는 후속 확정이다. 확장 전과 기존 저장은 보호 기능 외의 기존 배분을 유지한다. 물약 종류마다 솥을 늘리는 기능은 아니다.

일반 물약은 기존 배치당1병과 실제 판매 FIFO/선호 판매/병 전달을 유지한다. 납품은 기존 F19 일괄 상한2/3/4병을 그대로 이어받는다. 보조 조제대 기본형이라고1병으로 되돌리거나 F19 강화 효과를 다시 판매하지 않는다.

보조 조제대는 한 번에1개 납품 배치만 만들며 기존3거래처 순환과 부족 계열 선택을 이어받는다. 자동 출고·모든 계열 충족 시 실제 계약 대금 지급·다음 회차 반복도 기존대로다. 보조 제작 병을 일반 진열·손님·일반 판매 수익에 중복 등록하지 않는다.

두 설비는 같은 실제 재료를 쓴다. 다음 메인 솥 배치 우선 예약과 F20-A의 판매 재료 예비량을 적용한다. 입고/완료가 같은 시각이면 기존 일반 영업의 이벤트 순서를 보존하고 추가 납품의 예약은 일반 예약 이후에 처리한다. 두 설비의 같은 재료에 대한 초과 예약·음수·이중 소비를 금지한다.

### 전환과 진행 중 제작

구매 시 메인 솥의 현재 배치를 취소하거나 보조 조제대에 복제하지 않는다. 메인 솥에 기존 납품 배치가 있으면 그 배치를 정상 완료한 다음 보조 조제대로 납품 역할을 넘긴다. 이때까지 새 보조 납품을 시작하지 않는다. 기존 일반 배치이면 그대로 진행하며 별도 보조 납품은 보호·재료 조건을 만족할 때 시작한다.

각 설비는 자체 경과 시간·물약/거래처/회차·실제 수량·소비 재료·예약 시점 제작 시간·성공률·판정을 보유한다. 한 납품 배치에 성공 판정1회라는 F19 규칙을 유지한다. 강화·화면 열기·저장 복구로 진행 중 판정을 다시 추첨하지 않는다.

기존 일반/원정/계약 난수 흐름은 불필요하게 바꾸지 않는다. 보조 제작의 추가 판정은 분리된 저장 가능한 난수 흐름으로 관리한다. 초기 시드는 기존 저장 값으로 결정적으로 파생하고 시계·화면 조회에 의존하지 않는다. 새 시스템을 구매하지 않은 상태는 보호 변경의 의도된 차이 외에 기존 경제/난수 회귀를 검사한다.

## F20-C 비용과 보조 조제대 개선

아래는 **기능 확정·가격/배율은 개발 검증 초기값**이다.270만 G 보유 사용자가 신규 목표를 전부 즉시 구매하지 못하게 하되, 개인 잔고에 따라 가격을 올리는 방식은 쓰지 않는다.

| 구매 | 초기 비용 | 구매 직후 효과 | 누적 신규 비용 |
| --- | ---: | --- | ---: |
| 작업실 운영 확장 | 3,000,000 G | 보조 조제대 기본형 포함. 납품 시간=예약 시점의 기존 물약 제작 시간×2.0 | 3,000,000 G |
| 보조 조제대 개선1 | 1,500,000 G | 다음 납품 배치부터 기존 물약 제작 시간×1.5 | 4,500,000 G |
| 보조 조제대 개선2 | 3,000,000 G | 다음 납품 배치부터 기존 물약 제작 시간×1.0 | 7,500,000 G |

기존 조제 속도/계열 효과와 F19 일괄 상한은 예약 시점에 반영한다. 강화는 다음 배치에만 적용한다. 보급량이나 성공률·물약 단가를 함께 올려 효과 원인을 섞지 않는다. 기존 F19의15만/30만/45만 가격과 이미 구매한 실지출은 소급 변경하지 않는다.

확장 구매는 기존 납품을 별도 제작선으로 옮기고 메인 솥을 일반 영업에 돌려주는 보상이다. 기본형이 느리더라도 기존 전체 영업 순수입이 장기간 악화되거나 마지막 속도 개선이 실제 재료 병목 때문에 무효이면 그대로 완료 처리하지 않는다.

현재270만 G의 합성 복귀 상태에서는 확장까지30만 G이 부족하고, 구매 후 다음 목표가 남는다. 이는 유저 실제 저장을 수정하거나 해당 저축 시간을 측정했다는 뜻이 아니다.

개발 경제 목표는 기존 F19를 늘어뜨리는 대신 후속 구매 목표를 단계적으로 이어 주는 것이다.0골드 자연 성장의 신규3구매 완료를 시작 후36~48시간 범위에서 우선 비교한다. 이는 검증할 목표이며 플레이 시간 보장이 아니다. 특히 현재270만 G 상태에서 첫 구매까지와 그다음 두 구매까지의 실제 저축 간격을 기록한다. 단순 비용÷수입을 완료 시간이나 투자 회수 시간으로 대신하지 않는다.

개발은 실제 생산 경로에서 초반 반복 구매 간격10~30분, 주요 개선30~60분, 큰 기능 해금1~3시간이라는 이전 방향과 이번 큰 후반 비용이 어떻게 양립/충돌하는지도 기록한다. 모든 신규 단계를 반드시 같은 대기 시간에 맞추지는 않는다. 긴 무구매 구간과 효과 부족이 확인되면 새 초기 가격·배율을 비교한 근거를 제시해 기획에서 채택한 뒤 최종 적용한다. 임의로 기존 구매 가격을 일괄 인상하지 않는다.

## 관리 UI와 진행 표시

가구·직원 탭의 기존 후반 투자에 확장·보조 조제대 개선을 둔다. 정식 행에서 개방 조건·비용·현재→다음 효과를 확인하고 실제 구매할 수 있어야 한다. 최신 설정 탭 분리를 유지하며 새 전용 탭은 만들지 않는다.

가게 운영 상단에는 다음 영구 성장 목표1개를 표시한다. `작업실 운영 확장` 또는 `보조 조제대 개선1`과 **현재 골드/필요 골드**의 저축 게이지를 보여 준다. 미달성 해금 조건을 짧게 표시하고 눌러 가구·직원의 해당 행으로 이동한다. 구매 가능해지면 기존 추천과 같은 실제 구매 API로 실행할 수 있다. 돈이 부족한 성장 목표를 살 수 있는 추천인 것처럼 표시하지 않는다.

기존 구매 가능한 추천을 없애거나 중첩 카드·긴 설명을 늘리지 않는다. 상단의 추천/목표 영역은 한 묶음 안에서 구분선과 짧은 두 행으로 구성하고, 비용은 공용 코인과 기존 정렬을 쓴다. 메인 제작과 납품 제작은 가게 운영의 실제 게이지2개로 구분한다. `판매 재고 확보 중`, `판매 재료 확보 중`, `납품 제작 중`처럼 현재 행동을 표시하고 내부 배분식·예비량 계산·RNG는 상세 밖에 노출하지 않는다.

진행 게이지에는 실제 해당 배치의 예약 시간과 수량을 사용한다. 저축 게이지와 제작 게이지는 색/문구로 구분한다. 보조 제작1개를 여러 거래처의 동시 제작처럼 표시하지 않는다. 물약·재료 아이콘은 기존 승인 에셋을 사용한다. 이번 기능 연결에 새 캐릭터/가구 이미지 생성이나 투명 작업실의 소품 재배치를 끼워 넣지 않는다. 작업실의 새 보조 조제대 외형은 별도 디자인 후보로 구분하고 관리 화면 기능을 막지 않는다.

## 저장과 기존 사용자 보존

현재 저장 버전11을 기준으로 다음 저장 버전에 재고 보호 상태·확장 보유·개선 단계·보조 제작 예약/경과/난수를 저장한다. 실제 작업 시 버전이 먼저 올라갔다면 충돌 없는 다음 버전을 사용하고 이관 표를 결과에 남긴다.

기존1~11 저장은 자동 보호를 초기화하고 확장 미구매·개선0·보조 제작 없음으로 복원한다. 보호의 초기 상태는 현재 판매 재고와 L/H로 결정하며 모호한 중간 구간은 보호 해제로 시작한다. 기존 진행 중 일반/납품 제작·재료·성공 판정·원정·계약·과거 훈련·현금·직접 지출·F19 소유와 기간 보급 기준을 보존한다.

잘못된 확장/개선 조합·수량·시간·재료·계약 회차·판정·난수는 부분 적용하지 않고 원자적으로 거부한다. 현재 제작을 저장에 없는 새 배치로 추측하거나 재료를 다시 빼지 않는다. 저장/backup 복구와 구매 rollback에는 두 제작선과 보호 상태가 함께 포함돼야 한다.

## 검증과 개발 인계

### 먼저 완료할 판매 보호 검사

- L/H 경계·중간 구간 유지·창고 확장·재고0·가득 참·작은 용량·장기 부족·재료 회복을 검사한다.
- 보호 진입 중 진행 배치 정상 완료, 미시작 납품의 재료0소모, 회복 후 납품 재개와 거래처 순환을 검사한다.
- 일반 우선 예약·1배치 예비량·납품1~4병 축소·조회 불변·실제 재료 보존을 검사한다.
- 같은 공급/시드에서 납품 없음·기존 납품·보호 적용 납품을 비교해 판매 재고0/손님 대기와 일반 판매·납품 실적의 변화를 기록한다.

### 확장 후 기능 검사

- 실제 두 배치 동시 진행/같은 시각 완료·각 경과 독립·성공/실패·1~4병·재료 경쟁·회차 정산1회·일반 판매 애니메이션 중복 없음.
- 메인 일반/납품 제작 중 구매·보조 제작 중 개선·동일 저장 왕복·이전v11·악성 저장·저장 실패 rollback·중복/오래된 클릭.
- 큰 시간 진행과 분할 진행 일치·화면 조회 불변·배치 시간/판정 동결·기존 원정/보급/일반 판매와 난수 회귀.
- 최신 탭·520px 관리 화면·추천/저축 목표·정식 구매 행·실제2개 게이지를 기존 Control/TextServer 파일 미리보기로 검사한다.

### 경제와 저축 구간

시드73129/19337/9973을 사용한다. 정상 공급·상위 재료 부족 각각에서 보호 미적용/보호 적용/확장 기본/개선1/개선2를 같은 시작 상태로2시간 비교한다. 총30조건이며 개발 필요에 따라 경계 사례를 추가한다. 효과 비교에 쓰는 합성 골드는 구매 자금과 분리해 기록하고 실제 도달 잔고라고 해석하지 않는다.

각 조건에서 실제 현금·미정산·일반 매출/판매 병수·납품 출고/정산·재료비/원정비·순영업수입·재고0 시간·손님 대기·재료 대기·평균 재고·제작선 가동을 기록한다. 납품 수입 증가가 일반 판매 손실을 가리고 있지 않은지 확인한다. 가격만 비싸고 변화 없는 단계는 보완 대상이다.

0골드에서30초/15분 복귀×3시드, 훈련 목표0으로 기존 구매부터 신규3구매까지 실제 진행한6경로를 우선 측정한다. F19 완료 후 확장 해금, 각 신규 구매 시각·직전/직후 잔고·실제 지불·최대 무구매 간격·24/36/48시간 잔고·전체 완료를 기록한다. 보호만 적용한 기존 F19 대조군6경로도 두어 보호와 신규 투자의 영향을 분리한다. 필요하면 훈련3을 추가하되 미측정 정책에 결과를 일반화하지 않는다.

별도 합성 복귀 가게270만 G/기존 구매 완료에서 보호→확장 대기→실제 구매→후속 저축을 관찰한다. 초기 현금만 주입하며 판매/재료/계약 대금을 가짜로 지급하지 않는다. 신규 총750만 G을 한꺼번에 살 수 없음을 확인한다. 실제 사용자의24시간 저장이라고 표시하지 않는다.

코드 소유는 개발, 기획 문서와 최종 기획 검수는 기획 채팅에서 관리한다. 결과는 `판매-재고-보호와-작업실-운영-확장-개발결과.md`에 변경 파일·최종 수치/초기값 차이·소스 해시·검사 명령/로그·원본 경제 데이터·구매 시각·저장 이관·파일 미리보기·남은 문제를 남긴다. A의 결과를 먼저 구분해 기록한 뒤 B/C를 완료한다. 구현·검사·기획 검수 전에는 메인 F20을 완료로 표시하지 않는다.

검증은 작업 공간의 새 `.verification` 폴더·격리 APPDATA/LOCALAPPDATA·가짜 저장·headless·파일 미리보기만 사용한다. **Computer Use·정상 게임/GUI/에디터 실행·실제 AppData/플레이어 저장 접근·실행 중 게임의 종료/재시작/입력/포커스/모드 변경을 금지한다.** 다른 채팅의 과거 재실행 허가를 재사용하지 않는다.
