# 관리 창 복원 보완 · 2026-10-13

상태: 회색 빈 창 회귀 수정 완료. 사용자가 2026-10-13 재시작 후 “이제 관리창 잘 뜨네”라고 실제 표시 정상화를 확인했다. 최소화·앞뒤 순서·포커스의 전체 조합 검증은 별도 사용자 확인 대상.

관리 버튼을 누르면 기존 관리 창을 재사용한다. 최소화 상태는 먼저 숨겨 네이티브 창을 정리하고 일반 창 모드로 바꾼 뒤 다시 표시한다. Godot Window와 자식 UI는 그대로이므로 탭·상세·스크롤을 유지한다. 버튼 입력이 끝난 다음 프레임에 관리 창에 포커스를 요청한다. 최상단 설정은 `ManagementPanel._ready()`에서 창 생성 전에만 적용하며, 표시된 창에 다시 적용하지 않는다.

여러 번 누른 요청은 한 번으로 합친다. 기다리는 동안 닫히거나 트리에서 제거된 창은 다시 표시하지 않는다. 기존 탭·상세 펼침·스크롤과 게임 진행 데이터는 유지한다.

변경: `scripts/shop.gd`의 `open_management()`와 `_raise_management_after_click()`.

첫 수정에서 추가한 런타임 `always_on_top = true` 재설정은 회색 빈 창 회귀를 일으켰다. 사용자 보고 후 실제 게임 PID 52100의 창 정보를 읽었을 때 관리 창은 `IsWindowVisible=False`, `WS_VISIBLE=False`, style `0x860B0000`이고 본창은 두 값 모두 True, style `0x960B0000`이었다. 게임은 응답하고 자동 저장 시각도 갱신돼 전체 루프의 무한 대기와 구분했다. 저장 내용은 읽거나 수정하지 않았다.

Godot 4.6 Windows의 borderless subwindow 스타일 갱신이 표시 플래그를 누락하는 [공식 버그 #91588](https://github.com/godotengine/godot/issues/91588)과 [해당 엔진 소스](https://github.com/godotengine/godot/blob/4.6-stable/platform/windows/display_server_windows.cpp)를 확인했다. 표시된 창의 최상단 플래그 재설정을 제거하고, 같은 스타일 갱신을 거치는 최소화 복원에는 숨김→다시 표시 우회를 적용했다. 앞쪽 이동에는 [`Window.grab_focus()`](https://docs.godotengine.org/en/4.6/classes/class_window.html#class-window-method-grab-focus)를 유지했다. 테마·아이콘·버튼 배치는 이 회귀 수정에서 변경하지 않았다.

Computer Use나 실제 화면 입력은 사용하지 않았다. 사용자 요청으로 게임을 정상 종료·재실행했으며, 보고된 회귀의 진단에서는 실제 프로세스 응답·창 표시 플래그와 저장 파일의 수정 시각만 읽었다. 수정 후 실제 관리 버튼 조작은 사용자 확인 대상으로 남긴다. 최초 코드 구문 검사 로그는 `.verification/management-front-parse-20261013.log` (작업 폴더 기준)다.

격리된 `tools/verify_three_stage_modes.gd` 검사도 통과했다. 본모드·최소모드·정보모드의 실제 관리 버튼 연결을 통해 같은 창·탭·상세 펼침·스크롤 127 유지, 연속 5회 요청 병합과 다음 프레임의 대기 해제, 대기 중 내부 닫기 후 다시 표시하지 않음, 닫기 후 새 요청으로 복원, 로그인 의도·경제·저장 데이터·RNG 보존을 확인했다. 로그: `.verification/management-restore-three-modes-20261013.log` (작업 폴더 기준). headless 검사는 네이티브 Windows 최소화·가림·포커스를 입증하지 않는다.

회색 창 회귀 수정 후에도 같은 검사가 clean PASS했다 (`.verification/management-gray-window-fix-three-modes-20261013.log`). 최종 소스 구문 검사도 통과했다 (`.verification/management-gray-window-fix-parse-20261013.log`). 수정 후 실제 창 표시·입력은 자동 검사 완료로 표시하지 않는다.
