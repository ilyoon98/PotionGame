# 조건 흥정과 자동 납품 개발 결과

2026년 10월 15일 · **F18 코드 연결·격리 검사·경제 비교·파일 미리보기 완료**

별의 정원 최초 개방 이후 거래처와 조건을 합의하고, 한 솥에서 일반 제조와 납품 제조를 배분해 분할 출고·정산·다음 회차를 자동 진행하도록 연결했다. 공유 제작 명세와 메인 F18 상태는 기획 담당이 관리한다. 아래 수치는 개발 검증용 조정값이며 최종 밸런스 승인과 구분한다.

## 적용 결과

- 거래처는 여행자 상단·마법 연구회·숲 조합 3곳이다. 첫 계약과 등급 상승 때만 플레이어가 조건을 선택·수락하며, 일반 손님이나 새 캐릭터를 추가하지 않았다. 최초 수락 전에는 출고하지 않는다. 요구 두 계열 중 구매한 일반 물약이 없는 경우 조건을 보여주고 기회를 소비하지 않는다. 특별 4종은 요구·출고 대상에서 제외했다.
- 일반 **실제 시작 4배치 : 계약 전체 1배치**를 배분한다. 계약·부족 계열은 별도 커서로 순환하며 기존 일반 첫 제조·계열·특별품 교대와 RNG를 보존했다. 재료 부족으로 일반 제조가 대신 시작하면 놓친 계약 몫을 적립하지 않는다. 일반 재고가 가득한 경우에는 가능한 납품을 직접 제조·출고하며 기존 일반 배치의 보관 대기·판매 후 재개는 유지한다.
- 배치 용도·거래처·회차·종류는 시작 때 고정한다. 성공품만 직접 출고하며 선반 입고·일반 판매·일반 첫 판매로 중복 반영하지 않는다. `contract_events`와 계약 대금은 기존 `potion_events`·일반 판매량·매출에서 분리했다. 제조 성공·실패와 재료 예약은 실제 배치를 기준으로 집계한다.
- 각 회차는 당시 보유 일반 품목·종류별 단가·품질·요구량을 고정한다. 실제 출고 종류의 기준액을 더한 뒤 완료 때 배율을 한 번 적용·반올림해 지급한다. 부분 출고에는 대금을 지급하지 않으며, 지급과 다음 고유 회차 생성은 한 처리로 이어진다. 강화·새 구매·저장 복원은 진행 중 회차를 바꾸지 않는다.
- 실적 기준은 **0/60/240/600**, 기본 물량은 등급별 **20/40/60/80병**이다. 대금 중심·관계 중심 모두 요구 물량이 20% 증가해 **24/48/72/96병**이다. 실적은 완료 물량 × 계약 실적 배율로 한 번 반영한다. 관계 중심은 실적 ×2이며 최종 등급에는 제시하지 않는다. 새 합의는 현재 회차 종료 후 적용하고 높은 등급 합의가 우선한다.
- 흥정은 기회당 1회이며 별도 난수·확률·훈련 단계·결과를 저장한다. 1~3등급 성공률은 60%, 수동 훈련 3단계로 70/80/90%이며 비용은 8,000/20,000/50,000이다. 최종 4등급 대금 흥정은 100%다. 기본 수락에는 추첨이 없고 실패 후에도 기본/기존 계약을 유지한다. 오래된 기회·중복 수락·재추첨은 거부한다.

최종 대금 배율은 다음과 같다. 관계 중심은 해당 등급의 기본 배율을 사용한다.

| 거래 등급 | 기본 | 대금 중심 |
| --- | ---: | ---: |
| 1 | 160% | 180% |
| 2 | 170% | 190% |
| 3 | 180% | 200% |
| 4 | 190% | 210% |

생산 연결은 `scripts/shop_contracts.gd`, `shop_state.gd`, `shop.gd`, 표시 연결은 `management_contracts.gd`·`management_status.gd`·`management_panel.gd`에 있다. 새 계약 카탈로그는 독립 모듈 상수로 관리하며 기존 일반 32종·특별 4종 데이터는 변경하지 않았다.

## 저장과 관리 화면

저장 버전은 **10**이며 **1~9를 명시적으로 이전**한다. 구저장은 계약·훈련 미시작, 현재 배치는 일반 용도로 옮기고 기존 재화·제조·원정·재고·통계를 보존한다. 새 계약 데이터는 임시 객체에서 전체 검증 후 적용한다. 허용하지 않은 품목·용도·회차·초과 누계·판정 불일치·미보유 품질을 거부하고 로드 실패는 원래 상태를 바꾸지 않는다. UI 저장 실패도 계약 모듈·골드·직접 투자액만 되돌려 영업 상태와 현재 배치를 보존한다.

기존 6탭과 같은 관리 창 안에 수주 관리·돌아가기를 연결했다. 원래 탭·스크롤을 복원하며 520px 폭, Pretendard 제목 18px·본문/버튼 16px, 먹색·세이지와 기존 아이콘을 유지했다. 현재 회차 고정 단가와 다음 회차의 현재 예상 단가를 구분한다. 통계는 일반 판매·계약 출고·완료·대금을 분리하고 순수입에는 완료 대금을 한 번 더한다. 작업실·축소·정보 화면 크기와 기존 대표 게이지는 늘리지 않았다.

## 경제 비교와 단일 조정

동일한 완성 가게 fixture·시드 **1/73129/4444**를 비교했다. 원본은 진입 30분 36조건, 최종 등급 30분 12조건·1시간 9조건·2시간 9조건의 **66조건**이다. 조정본은 진입 30분 36조건과 최종 등급 2시간 9조건의 **45조건**이다. 진입은 정상/재료 비움/일반 재고 가득 × 계약 없음/기본/대금/관계를 포함한다. 최종 등급 비교는 정상 상황의 계약 없음/기본/대금이다.

원본 기본 115~145%·대금 135~165%는 초기 물량의 기회비용을 충분히 보상하지 못했다. 정상 30분에서 미정산 포함 기본 −5.09%·대금 −1.69%였고, 최종 등급 2시간에서도 기본 −2.60%였다. 계약 때문에 일반 판매·선호 수입이 줄어든 영향이며 원정비·재료비나 일부 비싼 특별품 감소만으로 설명되지 않았다. 따라서 **대금 배율만 전 등급 +45%p** 조정하고 물량·4:1 배분·훈련·실적·제조/재료/난수 정책은 유지했다.

아래는 정상 시나리오 3시드 평균이며 골드 단위로 반올림한 값이다. **미정산 가치**는 아직 완료하지 않은 회차의 `기준액 누계 × 그 회차 배율`을 정확한 실수로 합한 비교 지표로, 보유 골드나 이미 받은 대금이 아니다.

조정 후 진입의 시나리오별 평균 미정산 포함 개선은 +1.84~6.04%다. 다만 일부 30분 현금 순수입은 회차 일괄 정산 시점 때문에 계약 없음보다 낮다. 2시간 최종 등급은 기본·대금 모두 현금 순수입도 높았다. 이를 모든 실제 플레이 구간의 수익 보장으로 일반화하지 않는다.

[통합 경제 분석](../.verification/contracts-f18-20261015/economy-analysis.json)에 현금·미정산·시드별 결과를 분리했다. ## 남은 검증 범위

비교는 일반·특별 레시피/설비/직원이 완성된 합성 상태와 제한된 시드·시간의 개발 실험이다. 훈련 3단계를 사전 보유하며 최종 등급 비교는 유효한 과거 납품 이력을 합성한 뒤 측정한다. 새 등급 조건은 측정기가 정책에 따라 수락했으며 실제 게임에 자동 수락 기능을 추가한 것이 아니다. 실제 초반 성장, 훈련 구매비 회수 시간, 임의 플레이 패턴과 모든 장기 구간을 보장하지 않는다. 앱 종료 중 진행은 추가하지 않았으며 시작 등록·트레이·현재 실행 게임은 변경하지 않았다. 실제 Windows 표시·클릭·드래그·포커스·현재 플레이 저장의 확인은 이번 검증 범위 밖이다.

## 후속 수정 완료 · 2026년 10월 19일

가게 운영의 성장 추천에서 독립 시스템인 흥정 훈련이 누락돼 있던 문제를 수정했다. 별의 정원 해금·다음 단계 비용·최대 단계 조건을 실제 `training_view`로 확인하며, 구매 가능한 단계만 기존 훈련과 같은 우선순위로 추천한다. 8,000/20,000/50,000 비용과 현재→다음 성공률을 기존 추천 버튼·툴팁으로 표시한다.

추천 버튼은 `가구·직원`의 흥정 훈련 버튼과 같은 계약 액션 경로를 사용해 즉시 한 단계 훈련·저장한다. 실패 사유는 가게 운영의 추천 영역에도 표시하며 저장 실패는 기존 계약 액션의 원자적 복원을 따른다. 조건 선택·흥정 판정·계약 수락과 경제 수치는 변경하지 않았다.
