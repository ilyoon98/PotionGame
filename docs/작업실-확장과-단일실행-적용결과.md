# 작업실 확장과 단일 실행 적용 결과

> 후속 UI 변경: 글씨 확대 뒤 하단 지도 삭제와 여백을 적용하여 현재 본540×300·최소256×172·정보320×124다. 아래 수치는 확장 구현 당시 기록이며 공용 미리보기는 최신 파일로 갱신된다. [최신 하단 결과](하단-UI-여백-적용결과.md).

2026년 10월 10일 · **이번 범위 구현 완료 / 격리된 headless·Windows 도우미 검사 완료 / 실제 화면·GPU·입력·로그오프 검사 미실시**

승인된 본 작업실을 **540×288**로 연결했다. 그림은 540×248, 하단은 40px다. 최소 작업실 256×160, 정보 화면 320×112, 전체 실내 440×704와 실내 그림 408×248은 유지한다. Windows에서 같은 사용자 저장 위치의 게임은 한 실행만 운영하며, 중복 실행은 저장·로그인 기록·운영을 시작하기 전에 종료한다. 이번 완료는 작업실 확장과 단일 실행 범위이며 전체 기획 완료를 뜻하지 않는다.

## 단일 실행과 저장 보호

`single_instance.gd`와 동봉된 Windows 도우미가 같은 앱·사용자 저장 위치를 기준으로 OS mutex를 소유한다. 모든 게임 진입은 저장 읽기·로그인 의도·UI·운영 전에 소유권을 얻는다. 다른 실행이 이미 소유하거나 보호를 시작하지 못하면 추가 게임은 종료한다. 창 제목·PID 파일만으로 판단하지 않고 실제 OS 소유권을 사용한다.

도우미는 게임이 끝나거나 비정상 종료되면 소유권을 놓으며, 종료된 실행의 잠금이 영구히 남지 않는다. 첫 동시 실행에서 도우미 실행 파일을 배포하는 과정도 완성된 고유 임시 디렉터리의 원자적 게시로 처리한다. 실행 중 도우미가 사라지면 즉시 소유권을 재확인하고 운영·저장·구매·강화·설정·로그인 종료 표시를 막는다. 관리의 구매/날씨/밝기/집계 초기화와 직접 생산 진행도 변이 전에 소유권을 확인한다. 부팅 끝에도 `start_session`과 PID 의도를 쓰기 전에 재확인한다. 기존에 켜져 있는 게임을 재시작하거나 종료하지 않았다.

일반 `--headless`도 자동으로 검사 모드다. `isolated_preview` 메타가 없어도 실제 플레이어 저장·로그인 설정 읽기/쓰기와 Windows 등록, 단일 실행 도우미 시작을 건너뛴다. 일반 프로젝트 진입과 `--autostart`는 격리된 APPDATA의 정상 경제/로그인 trap 파일을 그대로 두고 기본 상태로 시작했다. 실제 사용자 저장은 어떤 검사에도 사용하지 않았다.
