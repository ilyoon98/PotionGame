# 로그인마다 자동 실행 수정 · 2026-10-15

**코드 수정·현재 PC 적용·실제 예약 작업으로 게임 실행 검증 완료 / 실제 재부팅 검증 대기**

사용자는 자동 실행을 켜 두면 이전에 게임을 직접 종료했어도 PC 로그인마다 자동으로 실행되도록 요청했다. 이전의 ‘켜 둔 게임만 재개’ 정책을 대체한다.

## 수정

- `login_resume.gd.should_resume`와 Windows 로그인 도우미 모두 `enabled`로 실행을 판단한다. `was_running=false`인 기존 설정도 실행한다. 기존 형식·소유자·불리언 검사는 유지하며 설정 파일을 새 형식으로 덮어쓰지 않는다.
- 정상 종료는 실행 상태만 닫힘으로 기록하고 자동 실행 설정과 등록을 유지한다. 진단용 종료 기록 쓰기에 실패해도 등록을 제거하거나 종료 확인창으로 가로막지 않는다.
- 화면 설정은 ‘Windows 로그인마다 게임 자동 실행’으로 표시하고 종료 여부와 무관하게 실행됨을 설명한다.
- Windows 작업 스케줄러에 현재 사용자 SID별 `MoonshadePotionShop-<SID>` 로그인 작업을 등록한다. 로그인 트리거는 해당 사용자, 10초 지연, InteractiveToken, 일반 권한, 암호 없음이다. 배터리 때문에 실행을 생략하지 않는다. 기존 Run 항목은 작업 등록 성공 후 이 게임 값만 제거한다. 설정 해제는 소유한 작업과 기존 이 게임 Run 값만 삭제한다.
- 조회는 실제 작업의 사용자·트리거·권한·실행 명령을 확인한다. Windows가 SID를 사용자 이름으로 반환하는 경우 동일 SID로 정규화한다. 다른 앱 소유의 같은 이름 작업을 덮어쓰거나 삭제하지 않는다.
- 실행기는 게임의 시작 기록을 최대 15초 기다린다. 실제 오류는 JSON 진단과 함께 비정상 종료 코드로 작업 스케줄러에 전달한다. 중복 실행·비활성화에 따른 정상 건너뛰기는 성공으로 반환한다.

게임 운영·수익·세이브 형식·아트에는 변경이 없다. 실제 게임을 켜서 검증하는 동안 정상 운영과 정상 종료에 따른 저장은 수행됐다. 수정 전 진행 저장·설정·설치된 도우미는 프로젝트 `.verification/startup-always-20261015/before/`에 백업했다.

Microsoft의 [로그인 실행 작업 문서](https://learn.microsoft.com/en-us/windows/win32/taskschd/starting-an-executable-when-a-user-logs-on)를 기준으로 사용자의 대화형 로그인에서 게임 창이 열리도록 구성했다.

## 검사 근거

- 작업 공간 루트 `.verification/startup-always-20261015/login-controller.log`: 실제 컨트롤러/관리 UI, 켜짐/꺼짐, 수동 종료 후 허용, 기록 쓰기 실패에도 자동 시작 유지, 저장 실패 취소/확인, 경제·RNG 불변 검사 PASS.
- 작업 공간 루트 `.verification/startup-always-20261015/windows-startup-final.log`: 실행기 30개 dry-run, 전체 PowerShell 파일 전달 5개 probe PASS. 원본과 동봉 실행기 바이트 일치, 한글 경로, 중복·이동 경로·잘못된 상태, 오류 종료 코드, 32,767자 명령 한도와 요청 파일 정리 확인. 현재 설치 명령 17,350자, 이전 방식 재현 53,161자.
- 작업 공간 루트 `.verification/startup-always-20261015/login-diagnostics-final.log`: 호출 시각·JSON 오류·dry-run 읽기 전용·실제 조기 종료 fixture·진단 기록 실패 격리 검사 PASS. 켜짐/닫힘 fixture가 실행을 시도하는 것도 확인.
- 프로젝트 `.verification/startup-always-20261015/live-results.json`: 생산 등록 코드를 실제 Windows PowerShell에서 실행해 설치/조회/해제/재등록 확인. 실제 켜짐/닫힘 상태에서 예약 작업 실행으로 게임 창 생성 → 정상 창 닫기로 저장·종료 → 같은 작업으로 새 게임 창 생성 → 실행 중 재요청은 중복 건너뛰기 확인. 최종 실행기 결과는 `started`, 시작 기록 확인은 true다. 같은 프로젝트 플레이 게임은 1개, 창 핸들과 응답 상태 확인, 작업 종료 결과 0. 최종 게임 PID는 54236이었다.
- 프로젝트 `.verification/startup-always-20261015/installed-task.xml`: 실제 적용된 사용자 로그인 트리거와 실행 명령. 현재 설정은 켜짐이고 게임도 실행 중이다.

## 남은 실제 재부팅 검사

위 검사는 **등록된 작업을 현재 로그인에서 실행한 검사**다. 새 로그인 트리거 발생이나 실제 PC 재부팅을 수행한 것으로 표현하지 않는다. 사용자 작업 저장과 재부팅 승인이 필요한 마지막 단계다.

재부팅 후에는 게임을 수동으로 실행하거나 작업을 수동으로 실행하기 전에 `tools/verify_login_after_reboot.ps1`을 실행한다. 마지막 실측 이후의 새 부팅 시각, 그 이후 작업 실행 시각, 실행기 결과, 실제 게임 프로세스 경로/시작 시각/응답하는 창을 대조한다. 재부팅하지 않았으면 검사를 거부하며 성공 파일을 만들지 않는다. 성공할 때만 `.verification/startup-always-20261015/after-reboot.json`에 실제 재부팅 근거를 저장한다.
