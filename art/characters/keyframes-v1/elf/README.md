# 손님03 · 엘프 키프레임 v1

승인한 v6 엘프의 갈색 옆머리·초록 머리 장식·뾰족한 귀·짧은 초록 의상·짧은 무릎·짙은 부츠를 유지한8포즈 후보다. 기존의 넓게 퍼진 치마를 다시 도입하지 않는다. `review.html`에서 포즈를 선택하고 부위 기준선 및 별도 물약 접점을 확인한다.

순서: 대기, 걷기 접지A, 통과A, 접지B, 통과B, 받기 손 내밀기, 받기 손 모으기, 대기 깜빡임. 현재는 키프레임 검토 단계이며 중간 프레임·호흡·부분 움직임·행동 속도를 합친 완성 애니메이션은 다음 단계다. Godot 런타임 에셋은 교체하지 않았다.

원본32×48 / 최근접 공통3배. 모자 없는 위쪽11행은 투명하다. 머리22×16 기준 영역은11~26행, 실제 머리 폭21~22픽셀·높이16픽셀이다. 몸통27~39행(13행), 다리·부츠40~46행(7행), 발 접지46행,47행은 투명이다. 서 있는 포즈의35행 허리는10픽셀,37~39행 하단은 모든 포즈에서11~12픽셀이다.

5색은 `art/palettes/v1/characters/elf.hex` 그대로다: 테두리·눈·부츠 #241C32, 피부·안쪽 옷 #F6D1AC, 갈색 머리 #916047, 초록 의상·장식 #718C59, 밝은 초록 의상 #B5C77D. 팔레트 밖0색 / 반투명0픽셀 / 외곽선 경계 위반0이다.

두 눈은 기존 엘프처럼 x10/x15,y21~22의1×2픽셀이다. 두 눈 각각 피부 여백1픽셀을 대각선까지 검사한다. 생성된 눈이 축소에서1픽셀로 줄어든 곳은 명시적 재질 마스크로 정리한다. 깜빡임은 같은 대기 그림의 눈4픽셀만 바꿔 만들고 머리·몸·접점을 바꾸지 않는다.

생성은 built-in image_gen으로 승인한 엘프와 부위 가이드를 참고했다. 전체 전신 포즈를 동일 배율로 등록하며 다른 포즈의 몸통·다리를 잘라 붙이지 않는다. 원본과 전체 프롬프트는 `generation.json` 및 `source/generated-v1.png`에 보관했다. 고정 후처리는 배경 정리 → 격자 정리 → 재질 램프 변환 → 검사 순서다. 걷기 접지A의38~39행에서 옷자락 폭을13픽셀로 벌리던 원본 테두리2픽셀은 명시적 배경 마스크로 정리하고 경계를 다시 칠한다.40행부터의 다리는 이 마스크에 포함하지 않는다.

`frames/*.png`는 각32×48 투명 원본, `elf-keyframes-native.png`는128×96 시트, `elf-keyframes-3x.png`는384×288 확대다. `keyframes-review.png`는8포즈 확인표, `anatomy-comparison.png`는 기존 엘프·새 엘프·주인공·여마법사를 같은 배율로 비교하는 그림이다. `validation.json`에 크기·색·머리·옷 폭·눈·외곽선·접지·걷기A/B·깜빡임 검사를 보관한다.

받기 손 앵커는 내밀기[5,31], 모으기[15,32]이고 실제 손 피부 픽셀에 닿는다. 병은 별도 에셋이며 로컬 접점[width/2,6]을 사용한다.36종×2포즈,72조합의 프레임 범위와 눈 여백을 검사했다. 병 색을 캐릭터 팔레트에 추가하지 않는다. 접점 기록은 `hand-anchors.json`이다.

재현: `python tools/build_elf_keyframes_v1.py`. 기존 여행자·여마법사 재질 처리의 동일성은 `regression-validation.json`에서 확인한다. 원본·중간 처리 그림은 검토 결과와 구분한다.
